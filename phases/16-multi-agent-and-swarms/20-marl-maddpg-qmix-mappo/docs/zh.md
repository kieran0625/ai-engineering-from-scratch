# MARL — MADDPG、QMIX、MAPPO

> 多智能体协调的强化学习传承，至今仍在 2026 年的 LLM-agent 系统中发挥指导作用。**MADDPG**（Lowe 等，NeurIPS 2017，arXiv:1706.02275）引入了集中式训练、去中心化执行（CTDE）：在训练期间，每个 critic 都会观察所有智能体的状态和动作；在测试时仅运行本地的 actor。适用于合作、竞争及混合场景。**QMIX**（Rashid 等，ICML 2018，arXiv:1803.11485）采用值分解与单调混合网络；各智能体的 Q 值组合为联合 Q，从而使 `argmax` 能够干净地分配——在星际争霸多智能体挑战（SMAC）中占据主导地位。**MAPPO**（Yu 等，NeurIPS 2022，arXiv:2103.01955）是带有集中式价值函数的 PPO；在 particle-world、SMAC、Google Research Football 和 Hanabi 上“效果出人意料地好”，且只需极少的调参。这些算法构成了必须去中心化行动的智能体团队策略训练的基石。MAPPO 是 **2026 年合作型 MARL 的默认基线**。本课程将基于一个小型网格世界玩具环境逐步构建这三种算法，让你在接触 LLM-agent 训练之前，将这三个核心思想内化为肌肉记忆。

## 问题

LLM-agent 系统越来越多地训练用于智能体间协调的策略：何时移交任务、何时采取行动、调用哪个对等智能体。告诉你如何训练此类策略的文献领域是多智能体强化学习（MARL），它早于 LLM 浪潮，并拥有一组主导算法。

缺乏模式词汇表直接阅读 MARL 论文会非常痛苦。集中式训练结合去中心化执行（CTDE）、值分解以及集中式 critic 并非流行词——它们是针对特定问题的具体解决方案：

- 独立强化学习（每个智能体单独学习）从每个智能体的视角来看是非平稳的。不好。
- 集中式强化学习（一个智能体控制全部）无法扩展，且违反执行约束。
- CTDE 兼顾两者优势：使用全局信息进行训练，使用本地策略进行部署。

## 概念

### 论文使用的三种环境

- **Particle World（多智能体粒子环境）**。具有合作/竞争任务的简单 2D 物理模拟。MADDPG 的原始测试平台。
- **星际争霸多智能体挑战（SMAC）**。合作微操，部分可观测。QMIX 的测试平台。离散动作，连续状态。
- **Google Research Football、Hanabi、MPE**。MAPPO 的基线环境。

不同环境具有不同的动作/观测类型。算法会根据环境特性进行选择。

### MADDPG（2017）—— CTDE 模式

每个智能体 `i` 拥有一个 actor `mu_i(o_i)`，负责将其自身观测映射为动作。每个智能体还配备一个 critic `Q_i(x, a_1, ..., a_n)`，在训练期间可见所有观测和所有动作。actor 根据 critic 的评估通过策略梯度进行更新。

```
actor update:    grad_theta_i J = E[grad_theta mu_i(o_i) * grad_a_i Q_i(x, a_1..n) at a_i=mu_i(o_i)]
critic update:   TD on Q_i(x, a_1..n) given next-state joint estimate
```

为什么采用 CTDE：在训练时，我们知道所有人的动作；利用这一点可以降低每个 critic 的方差。在部署时，每个智能体仅看到 `o_i` 并调用 `mu_i(o_i)`。

失败模式：critic 的规模随智能体数量 N 增长（输入包含所有动作）。若无近似处理，无法扩展到超过约 10 个智能体。

### QMIX（2018）—— 值分解

仅适用于合作场景。全局奖励是各智能体 Q 值的单调函数的总和：

```
Q_tot(tau, a) = f(Q_1(tau_1, a_1), ..., Q_n(tau_n, a_n)),   df/dQ_i >= 0
```

单调性保证了 `argmax_a Q_tot` 可以通过每个智能体独立选择 `argmax_{a_i} Q_i` 来计算。这正是你所需的**去中心化执行属性**。在训练时，混合网络根据各智能体的 Q 值生成 `Q_tot`。

为什么 QMIX 在 SMAC 中胜出：合作型星际争霸微操具有同质化智能体、局部观测、全局奖励的特点——完美契合值分解。

失败模式：单调性约束较为严格；某些任务具有非单调可分解的奖励结构（例如牺牲个体以成全团队）。后续扩展（QTRAN、QPLEX）放宽了这一限制。

### MAPPO（2022）—— 被忽视的默认选项

多智能体 PPO：带有集中式价值函数的 PPO。每个智能体拥有独立的策略；所有智能体共享（或各自拥有）可见完整状态的价值函数。Yu 等人（2022）在五个基准测试中将 MAPPO 与 MADDPG、QMIX 及其扩展进行了对比，发现：

- 在 particle-world、SMAC、Google Research Football、Hanabi、MPE 上，MAPPO 的表现持平或优于离策略 MARL 方法。
- 所需超参数调整极少。
- 训练稳定；跨随机种子可复现。

在该论文发表前，社区低估了在线策略 MARL。到了 2026 年，MAPPO 已成为合作型 MARL 的默认基线；任何新方法都必须超越它。

### 为什么 LLM-agent 工程师应该关注

三个直接应用场景：

1. **路由器训练**。元智能体决定由哪个子智能体处理任务。这是一个包含 N 个去中心化子智能体和 1 个集中式路由器的 MARL 问题。MAPPO 适用。
2. **角色涌现**。在生成式智能体仿真中，训练智能体随时间采用互补角色本质上是一个伪装成其他形式的 MARL 问题。类 QMIX 的值分解通过结构设计强制实现互补性。
3. **多智能体工具使用**。当智能体共享工具并竞争预算时，通过 CTDE 对其进行训练可生成尊重资源约束的可部署本地策略。

实际注意事项：在 2026 年，大多数生产级 LLM-agent 系统是通过提示词来驱动策略，而非直接训练策略。当你具备以下条件时才会引入 MARL：(a) 大量的交互数据，(b) 明确的奖励信号，以及 (c) 愿意投资训练基础设施。

### CTDE 作为超越 RL 的设计模式

即使不进行训练，CTDE 也是一种有用的架构模式：

- 在*设计*阶段，假设具备完整的团队视野。
- 在*运行时*，强制执行去中心化执行：每个智能体仅能看到 `o_i`。

该模式迫使你将每个智能体的状态保持显式，并提前考虑部分可观测性问题。许多生产级多智能体系统会无声地假设处处共享状态——CTDE 规范可防止这种情况发生。

### 非平稳性问题

当多个智能体同时学习时，每个智能体的环境（包含其他智能体的策略）都是非平稳的。经典的单智能体 RL 证明在此失效。本课程中的 MARL 算法均针对此问题提出了方案：

- MADDPG：全局 critic 可见所有动作，因此其价值估计是平稳的。
- QMIX：值分解将学习转移到联合 Q 空间，其中最优性定义明确。
- MAPPO：集中式价值函数缓解了因其他智能体策略变化带来的方差。

在 LLM-agent 系统中，非平稳性表现为“我的智能体上个月运行正常，但现在上游的其他智能体发生了变化，导致我的智能体行为异常。”使用 CTDE 训练 MARL 是原则性的修复方案；提示词层面的修复更快但持久性较差。

### 本课程不涵盖的内容

实际网络的训练属于第 09 阶段的主题。本课程将构建基于脚本策略的版本，在不进行梯度更新的情况下演示 CTDE、值分解和集中式价值模式。目标是在你使用完整的 MARL 库（如 PyMARL、MARLlib、RLlib multi-agent）之前，将这些模式内化于心。

## 动手构建

`code/main.py` 实现了三种模式演示，均在一个极简的 2 智能体合作网格世界中运行：

- 环境：4x4 网格上有 2 个智能体，1 个奖励点。任意智能体到达奖励点即获得奖励 = 1；任务结束。
- `IndependentAgents` —— 每个智能体将其他智能体视为环境。基线方案。
- `MADDPGStyle` —— 集中式 critic 计算联合价值；actor 策略据此更新。脚本化策略改进。
- `QMIXStyle` —— 带有单调混合器的值分解。
- `MAPPOStyle` —— 集中式价值函数；策略针对共享基线进行更新。

这四种方案运行相同的回合，并报告到达目标的平均步数。CTDE 变体收敛到的路径比独立基线更短。

运行：

```
python3 code/main.py
```

预期输出：独立智能体平均需要约 6 步；CTDE 变体收敛至约 3.5 步（4x4 网格的最优步数为 3）。尽管使用的是脚本策略，模式差异依然显现。

`outputs/skill-marl-picker.md` 是一项技能，用于为给定的多智能体任务选择 MARL 算法：合作型还是竞争型、同质化还是异质化、动作空间类型、规模、奖励信号。

## 生产部署

生产环境中使用 MARL 的情况较少。当你确实需要使用它时：

- **从 MAPPO 开始**。2022 年的论文已将其确立为基线；首先复现它可以节省数周追逐更花哨方法的时间。
- **记录每个智能体的观测和动作流**。没有逐智能体追踪日志，调试 MARL 将毫无希望。
- **将训练代码与执行代码分离**。CTDE 是一种规范；让执行路径真正只能看到 `o_i`。
- **奖励塑形警告**。MARL 对奖励设计极其敏感。塑形逻辑中的一个协调缺陷就会导致智能体学会利用它。请运行对抗性测试。
- **对于 LLM 智能体**，优先考虑提示词层面的策略。仅在交互数据、奖励信号和基础设施三者齐备时，才投入 MARL 训练。

## 练习

1. 运行 `code/main.py`。测量独立智能体与 MAPPO 风格智能体之间到达目标的步数差距。在 6x6 网格上，这个差距是扩大还是缩小？
2. 实现竞争变体：两个智能体，一个奖励点，只有第一个到达的获得奖励。哪种模式能干净地处理竞争？历史上是 MADDPG。
3. 阅读 MADDPG（arXiv:1706.02275）第 3 节。用你自己的话，以伪代码形式符号化实现确切的 critic 更新规则。
4. 阅读 MAPPO（arXiv:2103.01955）。作者为何认为集中式价值 + PPO 在其基准测试中胜过离策略 MARL？列出三个最有力的论点。
5. 将 CTDE 作为设计模式应用于一个假设的 LLM-agent 系统（例如：研究智能体 + 摘要智能体 + 编码智能体）。在设计时可用的联合信息有哪些是运行时不可用的？

## 关键术语

| 术语 | 人们常说的说法 | 实际含义 |
|------|----------------|----------|
| MARL | “多智能体强化学习” | 面向多智能体系统的强化学习。 |
| CTDE | “集中式训练，去中心化执行” | 使用全局信息进行训练；使用本地策略进行部署。 |
| MADDPG | “多智能体 DDPG” | 采用 CTDE，每个智能体的 critic 可见所有观测与动作。 |
| QMIX | “值分解” | 对各智能体 Q 值进行单调混合。适用于合作场景。 |
| MAPPO | “多智能体 PPO” | 带有集中式价值函数的 PPO。2026 年默认基线。 |
| 值分解 | “个体 Q 值之和” | 将联合 Q 表示为各智能体 Q 值的单调函数。 |
| 非平稳性 | “移动的目标” | 随着其他智能体学习，每个智能体的环境发生变化。这是 MARL 的核心问题。 |
| 在线策略 / 离策略 | “从当前数据 / 回放缓冲区学习” | PPO 是在线策略（MAPPO）；DDPG 和 Q-learning 是离策略。 |
| SMAC | “星际争霸多智能体挑战” | 合作微操基准测试；QMIX 的主场。 |
