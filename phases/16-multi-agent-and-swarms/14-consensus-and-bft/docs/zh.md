# 面向智能体的共识与拜占庭容错

> 经典分布式系统的拜占庭容错（BFT）与随机性大语言模型相遇。在 2025-2026 年间涌现出三个研究方向：**CP-WBFT**（arXiv:2511.10400）通过置信度探针为每张选票加权；**DecentLLMs**（arXiv:2507.14928）采用无领导者架构，由工作节点并行提出提案并进行几何中位数聚合；**WBFT**（arXiv:2505.05103）将加权投票与层次结构聚类相结合，以划分核心节点（Core）和边缘节点（Edge）。来自《Can AI Agents Agree?》（arXiv:2603.01213）的实际实验结果表明，即便是在标量数值的一致性上，当前的共识依然脆弱——单个具有欺骗性的智能体就足以破坏智能体混合模型（Mixture-of-Agents）。BFT 是必要条件但非充分条件。本课将构建一个最小化的 BFT 协议，注入三种针对智能体的特定攻击（拜占庭谎言、阿谀附和、同质化相关错误），并测量每种共识变体如何应对这些攻击。

**类型：** 学习 + 构建
**语言：** Python（标准库）
**前置知识：** 第 16 阶段 · 07（心智社会与辩论），第 16 阶段 · 13（共享内存）
**耗时：** 约 75 分钟

## 问题

你有 N 个 LLM 智能体各自生成一个答案。它们产生了分歧。多数投票选出了错误的答案，因为其中两个智能体存在相关性（使用相同的基座模型、相同的训练数据、相同故障模式）。第三个智能体恰好以新颖的方式出错——因此多数派成了虚假多数。

现在加入一个欺骗性智能体：它故意撒谎。或者一个阿谀附和型智能体：它同意最后发言的人。在经典 BFT 中，假设拜占庭节点占比为 `f < n/3` 且行为任意。2026 年的现实情况是，即使诚实的 LLM 节点也具有随机性，跨模型存在相关性，且会受彼此输出的影响。你不能将它们视为独立的伯努利投票者。

经典 BFT（PBFT，1999）并没有错——它是不完整的。它能处理任意的比特翻转，但无法处理“三个诚实智能体因共享训练数据而共享幻觉”的情况。本课将从 PBFT 的基础出发，叠加三种 2025-2026 年的适应性改进。

## 概念

### 经典 BFT 提供什么

实用拜占庭容错（Castro & Liskov，OSDI 1999）可容忍 `f < n/3` 个拜占庭节点。该协议包含三个阶段（预准备、准备、提交）和两个原语（签名消息、法定人数证书）。在 `n >= 3f + 1` 个诚实或恶意节点中就单一值达成一致。

其保证非常强，但基于以下假设：

1. **故障独立。** 拜占庭节点之间不协调。
2. **诚实节点确实诚实。** 诚实输出的正确性不是问题；协议仅用于对齐分歧。
3. **问题存在事实真相。** 对错误事实达成共识仍然是共识。

LLM 智能体违反了所有这三条。运行相同基座模型的两个智能体会共享故障。“诚实”的 LLM 仍会产生幻觉。而在模糊问题上，“真相”取决于智能体的决定——不存在外部真理源。

### 三种 LLM 特有攻击

**拜占庭谎言。** 一个智能体输出故意错误的答案。若 `f < n/3`，经典 BFT 可处理此情况。

**阿谀附和（趋同）。** 一个智能体在投票前阅读其他智能体的答案，并与最后发言者保持一致。并非恶意，但与最响亮的声音产生关联。经典 BFT 无法阻止此行为，因为该智能体通过了所有签名验证。

**同质化相关错误（单一种植）。** 三个智能体共享一个基座模型。它们产生了相同的错误幻觉。多数派是错误的。经典 BFT 对此无能为力，因为三者都“诚实”地达成一致。

### 2025-2026 年的应对方案

**CP-WBFT**（arXiv:2511.10400）—— 置信度探针加权 BFT。每个投票者在其答案上附加一个置信度探针（自我报告的概率，或独立校准模型的预测）。投票权重随置信度缩放。在完全图上报告了 +85.71% 的 BFT 性能提升。缓解对象：阿谀附和（附和型智能体通常对其自愿提出的立场置信度较低）。

**DecentLLMs**（arXiv:2507.14928）—— 无领导者架构。工作智能体并行提出提案，评估智能体对提案打分，最终答案为得分位置的几何中位数。当 `f < n/2` 时表现稳健。缓解对象：拜占庭谎言和相关错误（几何中位数对异常值稳健，会将结果拉向密集簇，而非偏向模型的均值）。

**WBFT**（arXiv:2505.05103）—— 带层次结构聚类的加权 BFT。投票权重根据响应质量加上从历史中学习到的信任分数分配。将智能体聚类为核心（Core）和边缘（Edge）；核心智能体必须先达成一致，边缘智能体随后跟进。缓解对象：可扩展性（核心共识规模小且快速）及部分缓解单一种植（核心节点可选择多样化组合）。

### 实证研究：《Can AI Agents Agree?》（arXiv:2603.01213）

该论文跨多个前沿模型测量了标量一致性（LLM 智能体对单一数值达成一致）。发现令人不安：

- 即使没有对抗者，在许多基准测试中，LLM 智能体在标量问题上的分歧率也超过 30%。
- 单个采用欺骗人设的智能体就能使智能体混合模型的共识偏离诚实基线 40 个百分点以上。
- 分歧率与模型多样性相关——异构集成的分歧多于同质集成（好：错误不相关），但漂移也更慢（坏：达成一致所需时间更长）。

核心结论：BFT 提供了对齐输出的机制，但它无法告诉你对齐后的输出是否正确。需结合验证（第 16 阶段 · 08 角色专业化）、多样性（第 16 阶段 · 15 辩论变体）和评估智能体（第 16 阶段 · 24 基准测试）。

### 核心协议（精简版）

面向 LLM 智能体的最小化 BFT 轮次：

```
1. task arrives; each agent i produces answer a_i
2. each agent attaches confidence probe c_i in [0, 1]
3. aggregator collects (a_i, c_i) from all n agents
4. aggregator groups by semantic cluster (equivalent answers)
5. aggregator computes weight for each cluster C:
     w(C) = sum_{i in C} c_i
6. winner = cluster with max weight, if max > threshold * sum(c_i)
   else: retry or escalate
7. minority clusters logged with provenance for post-hoc audit
```

语义聚类步骤是 LLM 特有的关键设计。两条答案“研究报告显示为 4.2%”和“提升了 4.2%”属于同一聚类。朴素字符串相等检查会遗漏这一点。在生产环境中，请使用轻量级嵌入模型或显式规范化。

### 阈值调优

`threshold` 参数决定何时接受结果以及何时重试。过低：你会接受微弱的多数派。过高：你永远无法接受任何结果。经验范围：对于 `n=5-7` 个智能体为 0.5-0.67，对于更小的 `n` 则更高。低于阈值时，升级为人工介入或切换至不同的智能体集成。

### 共识无效的场景

- **模糊问题。** 如果问题没有事实真相，共识只是一种观点。请明确称之为观点。
- **复合问题。** “编写代码并解释它”——涉及两个答案。分别独立投票。
- **对抗性多轮交互。** 如果智能体可以观察先前轮次并模仿（Du 2023 辩论），它们会开始相互一致，无论真相如何。限制轮次（通常为 2-3 轮）。

## 构建实现

`code/main.py` 实现了：

- `AgentVoter` —— 带有（答案，置信度）的脚本策略。
- `MajorityVote` —— 经典相对多数票。
- `CPWBFT` —— 结合语义聚类的置信度加权投票。
- `DecentLLMs` —— 对打分提案进行几何中位数聚合。
- `Scenario` —— 在三种攻击模式下运行每种聚合器。

已实现的攻击模式：

1. `byzantine`：一个智能体以高置信度撒谎。
2. `sycophancy`：一个智能体复制它看到的第一个答案，并匹配相应置信度。
3. `monoculture`：三个智能体共享一个错误答案（相关错误），置信度中等。

运行：

```
python3 code/main.py
```

预期输出：一个 `(attack, aggregator) -> final answer` 表格，正确答案会被高亮显示。相对多数票会在单一种植案例中失败。CPWBFT 的置信度加权可缓解阿谀附和。当单一种植比例小于人口半数时，DecentLLMs 的几何中位数会将结果拉向诚实簇。

## 交付规范

在交付任何共识机制之前：

- **至少使用上述三种模式进行攻击测试。** 你的协议应能可预测地失败，而不是静默崩溃。
- **记录每个少数派集群及其来源。** 少数派集群是你检测相关错误的预警系统。
- **强制执行轮次上限。** 不要“持续辩论直到达成一致”——那会奖励阿谀附和。
- **将一致性与正确性分离。** 共识输出交由验证器处理；验证器必须独立于智能体集成。
- **监控一致率。** 急剧上升意味着从众偏差；急剧下降意味着模型漂移。

## 练习

1. 运行 `code/main.py`。确认相对多数票在单一种植攻击下失效，但当单一种植置信度低于 0.7 时，CPWBFT 能部分缓解该问题。
2. 添加第四种攻击模式：**沉默弃权**——一个智能体拒绝回答（“我不知道”）。每种聚合器应如何处理弃权？实现你的选择。
3. 将语义聚类从字符串规范化替换为嵌入相似度（使用任意开源嵌入模型）。这对阿谀附和攻击有何影响？
4. 阅读 CP-WBFT（arXiv:2511.10400）。实现置信度探针校准步骤（独立的校准模型检查每个智能体的自我报告置信度）。测量在单一种植场景下的准确率提升。
5. 阅读《Can AI Agents Agree?》（arXiv:2603.01213）。复现简化的标量一致性实验：三个智能体、一个标量问题、欺骗人设提示词。CPWBFT 或 DecentLLMs 能检测到吗？

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|------|------------|----------|
| BFT | “拜占庭容错” | Castro-Liskov 1999 协议，用于在 `f < n/3` 个任意故障节点下达成共识。 |
| Byzantine | “任何不良行为” | 能够撒谎、丢弃消息、静默失败的节点——除了安全崩溃外的一切行为。 |
| Confidence probe | “你有多确定？” | 附加在选票上的自我报告或校准器预测的概率。 |
| Semantic clustering | “答案相同，措辞不同” | 在计票前将等价答案分组。 |
| Geometric median | “稳健中心点” | 使到样本点距离之和最小的点。对异常值稳健，不同于均值。 |
| Monoculture | “同模型，同故障” | 智能体共享训练数据或基座模型时产生的相关错误。 |
| Sycophantic conformity | “附和响亮声音” | 智能体的投票偏向最先/最大声发言者。 |
| Core/Edge | “分层 BFT” | WBFT 划分：先达成小规模核心共识，边缘节点随后跟进。限制延迟。 |
