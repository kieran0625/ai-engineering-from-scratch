# 谈判与议价

> 智能体就资源、价格、任务分配和条款进行谈判。2026 年的基准测试目标很明确：NegotiationArena（arXiv:2402.05863）显示，LLM 可通过“人设操纵”（如扮演“急于出售”的角色）将收益提升约 20%；《Measuring Bargaining Abilities》（arXiv:2402.15813）表明买方比卖方更难应对，且单纯增加规模无济于事——其 **OG-Narrator**（确定性报价生成器 + LLM 叙述者）将成交率从 26.67% 提升至 88.88%；大规模自主谈判竞赛（arXiv:2503.06416）运行了约 18 万次谈判，发现**隐藏思维链**的智能体通过向对手隐瞒推理过程而获胜；Bhattacharya 等人 2025 年基于哈佛谈判项目指标的研究将 Llama-3 评为最有效，Claude-3 最具攻击性，GPT-4 最公平。本课实现合同网协议（FIPA 的前身，见第 02 课），接入类 LLM 的买方/卖方，运行 OG-Narrator 风格的分解，并测量每种结构选择如何改变成交率。

**类型：** 学习 + 构建
**语言：** Python (stdlib)
**前置要求：** 第 16 阶段 · 02（FIPA-ACL 传承）、第 16 阶段 · 09（并行蜂群网络）
**耗时：** 约 75 分钟

## 问题

两个智能体需要就价格达成一致。如果仅依靠纯语言提示，2024-2026 年的 LLM 在紧密参数化的议价场景（arXiv:2402.15813）中成交率出奇地低（约 27%）。规模无法解决此问题：GPT-4 在议价的结构能力上并不优于 GPT-3.5；它只是更擅长议价的*语言*表达。

根本原因在于 LLM 混淆了两项工作——决定报价和叙述报价。OG-Narrator 将二者分离：确定性报价生成器计算数值变动；LLM 仅负责叙述。成交率跃升至约 89%。

这与经典的多智能体发现一致：将机制与通信层解耦即可取胜。合同网协议（FIPA, 1996; Smith, 1980）是参考性的任务市场机制。将 LLM 插入叙述槽位，即可得到现代 LLM 驱动的任务市场。

## 概念

### 合同网，一段话概括

Smith 1980 年的合同网协议（Contract Net Protocol）：**管理者**广播**提案征集 (cfp)**；**竞标者**回复包含其报价的**提议 (propose)** 消息；管理者挑选胜出者，并向胜出者发送**接受提案 (accept-proposal)**，向失败者发送**拒绝提案 (reject-proposal)**。胜出者执行任务。可选消息：**拒绝 (refuse)**（竞标者声明不参与投标）。FIPA 将其标准化为 `fipa-contract-net` 交互协议。

### 为什么 OG-Narrator 能赢

《Measuring Bargaining Abilities of Language Models》（arXiv:2402.15813）观察到：

- LLM 经常违反议价规则（在非逻辑价格上报价，忽略对方的 ZOPA）。
- 锚定效应差（接受糟糕的首次报价；以象征性而非战略性金额进行反报价）。
- 单纯增加规模无法修复这些问题。更大的模型能生成更合理的语言，但战略错误率相似。

OG-Narrator 的分解方式：

```
           ┌──────────────────┐        ┌──────────────────┐
  state  → │ offer generator  │ price → │  LLM narrator    │ → message
           │  (deterministic) │        │  (writes the     │
           │                  │        │   human-style    │
           └──────────────────┘        │   accompaniment) │
                                       └──────────────────┘
```

报价生成器采用经典议价策略：鲁宾斯坦讨价还价模型、泽滕策略，或基于价格的简单以牙还牙策略。LLM 负责叙述。消息包含确定性价格和自然语言包装。

成交率跃升的原因在于：
- 价格始终保持在议价区间内。
- 锚点是战略性的，而非情绪化的。
- LLM 只做它擅长的事：写作。

### NegotiationArena 的发现

arXiv:2402.05863 提供了标准基准。核心发现：

- LLM 可通过采用特定人设（“我周五前必须卖掉这个”）将收益提升约 20%——人设操纵是一种真实有效的战术。
- 公平/合作型智能体会被对抗型智能体剥削；防御需要显式的反向姿态调整。
- 对称配对在约 40% 的基准场景中会收敛至不公平的结果。

这并非“LLM 是不好的谈判者”。而是“LLM 的谈判方式过于像人类，包括那些容易被利用的部分”。

### 思维链隐藏

大规模自主谈判竞赛（arXiv:2503.06416）跨多种 LLM 策略运行了约 18 万次谈判。获胜者向对手隐藏了其推理过程：

- 如果智能体将“我只接受 $75；我的保留价格是 $70”打印到公开可见的草稿区，对手就能读取到。
- 获胜者在私有环境中计算策略；输出通道仅包含报价和最低限度的必要叙述。

这是 2026 年对经典博弈论（Aumann 1976 关于理性与信息的研究）的回响：暴露你的私有估值会损失收益。LLM 缺乏这种直觉，会毫不犹豫地在其推理轨迹中输入保留价格，而这些轨迹往往会被对手看到。

工程启示：将私有草稿上下文与公共消息上下文分离。这不是可选项，是必选项。

### Bhattacharya 等人 2025 — 模型排名

基于哈佛谈判项目指标（原则性谈判、BATNA 尊重、利益互惠）：

- **Llama-3** 在达成交易方面最有效（成交率 + 收益最高）。
- **Claude-3** 是最具攻击性的谈判者（高锚点，后期才让步）。
- **GPT-4** 最公平（跨配对方案的收益方差最小）。

这是 2025 年的快照。重点不在于哪个模型在 2026 年 4 月胜出——而在于不同的基础模型具有持久的谈判风格。异构集成（第 15 课）将此作为多样性来源之一。

### 通过合同网 + LLM 进行任务分配

合同网在现代 LLM 多智能体中的复用方式：

1. 管理智能体将任务分解为单元。
2. 向工作智能体广播 `cfp`，附带任务描述。
3. 每个工作智能体返回报价：`(price, eta, confidence)`，其中价格可以是 token 数、计算单元或美元。
4. 管理者挑选胜出者（单个或多个，取决于任务）并进行分配。
5. 被拒绝的工作智能体可自由竞标其他任务。

由于协调方式是广播与响应，而非同步聊天，该模式在超过 100 个工作节点时扩展性极佳。已用于生产环境：Microsoft Agent Framework 的编排模式、部分 LangGraph 实现。

### LLM-利益相关者交互式谈判

NeurIPS 2024（https://proceedings.neurips.cc/paper_files/paper/2024/file/984dd3db213db2d1454a163b65b84d08-Paper-Datasets_and_Benchmarks_Track.pdf）引入了带有**秘密评分**和**最低接受阈值**的多方计分游戏。每个利益相关者拥有私有效用值；LLM 必须从消息中推断它们。这是将两方议价推广至 N 方联盟形成的通用形式。适用于具有异构工作能力的生产级任务市场。

### 叙述 vs 机制原则

纵观所有 2024-2026 年的谈判基准，一致的工程原则是：

> 让 LLM 负责叙述。不要让 LLM 计算报价。

如果报价需要是一个数字（价格、预计到达时间、数量），请根据谈判状态确定性生成它，并由 LLM 生成包装文本。如果报价需要是一个提案结构（任务分解、角色分配），可以让 LLM 起草，但在发送前必须对照 Schema 进行验证和约束检查。

## 构建实现

`code/main.py` 实现了：

- `ContractNetManager`, `ContractNetTask`, `Bid` —— 管理者 + 竞标者，广播 cfp，收集提案，分配任务。
- `og_narrator_bargain(state, rng)` —— OG-Narrator 买方：确定性地向中点做出泽滕式让步。
- `seller_response(state, rng)` —— 确定性卖方反报价策略（两种风格的结构性事实基准）。
- `naive_llm_bargain(state, rng)` —— 模拟全 LLM 议价者：以高方差选择价格，常超出 ZOPA 范围。
- 测量：在 1000 次试验中统计成交率，每次试验重新采样保留价格。

运行：

```
python3 code/main.py
```

预期输出：朴素 LLM 成交率约 65-75%；OG-Narrator 成交率约 85-95%；15-25 个百分点的差距体现了将报价生成与叙述解耦的结构优势。此外还包括一个包含三个竞标者和一个任务的合同网任务市场分配示例。

## 生产部署清单

生产级议价检查清单：

- **分离草稿区。** 私有状态绝不能进入对手的上下文。这是不可妥协的底线。
- **确定性报价生成。** 价格、数量、ETA：直接计算，不要依赖提示词。
- **验证所有传入报价。** 对照 Schema 进行校验。在协议边界处直接拒绝超出 ZOPA 的报价。
- **限制轮次。** 最多 3-5 轮；陷入僵局时升级至调解员。
- **持续测量成交率和收益方差。** 成交率下降是一个症状——通常是提示词漂移或对手侧的攻击所致。
- **记录所有被拒绝的提案及其确定性理由。** 对于合同网管理者，落标的竞标者需要知道原因。

## 练习

1. 运行 `code/main.py`。确认 OG-Narrator 在成交率上优于朴素 LLM。具体高出多少？
2. 实现**基于人设的收益提升**（arXiv:2402.05863）——买方仅在叙述中采用“本周急需购买”的人设，报价生成器保持不变。成交率或收益会发生变化吗？
3. 实现思维链**隐藏**：维护一个不传递给对手的私有草稿字符串。如果你意外泄露了它（通过交换通道来模拟），会发生什么？
4. 将合同网扩展为带保留价格的 N 竞标者拍卖。当所有出价均超过保留价格时，管理者如何在最低价格和最高质量之间做决定？你会选择哪种分配规则，为什么？
5. 阅读 Bhattacharya 等人 2025 年关于哈佛谈判项目指标的研究。实现两种不同风格（激进 vs 公平）的议价者。在对称和非对称配对下测量收益方差。

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|------|----------------|------------------------|
| Contract Net | “任务市场” | Smith 1980, FIPA 1996。cfp + propose + accept/reject。经典的任务市场机制。 |
| ZOPA | “可能达成协议的区域” | 买方最高价与卖方最低价的重叠区。超出此区的报价无法成交。 |
| BATNA | “谈判协议的最佳替代方案” | 若本交易失败时的备选方案。决定了你的保留价格。 |
| OG-Narrator | “报价生成器 + 叙述者” | 解耦架构：确定性报价，LLM 叙述。 |
| Zeuthen strategy | “风险最小化让步” | 基于风险限制的古典报价生成策略。 |
| Rubinstein bargaining | “交替报价均衡” | 考虑贴现因子的无限期博弈议价模型。 |
| CoT concealment | “隐藏推理过程” | arXiv:2503.06416 中的获胜者保持私有草稿；公共通道仅显示报价。 |
| Persona manipulation | “情绪姿态调整” | arXiv:2402.05863：通过“急售/急购”人设可获得约 20% 的收益增益。 |
