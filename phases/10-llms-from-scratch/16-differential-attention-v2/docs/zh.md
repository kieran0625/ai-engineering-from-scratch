# 差分注意力（V2）

> Softmax 注意力会将少量概率分散到每个不匹配的 token 上。在 10 万个 token 的情况下，这种噪声会累积并淹没信号。Differential Transformer（Ye 等人，ICLR 2025）通过计算两个 softmax 的差值来求解注意力，从而减去共享的噪声基底。DIFF V2（Microsoft，2026年1月）是面向生产环境的重写版本：解码延迟与基线 Transformer 匹配，无需自定义算子，兼容 FlashAttention。本课程涵盖从 V1 到 V2 的完整流程，并提供一个可在标准库 Python 中运行的差分运算玩具实现。

**类型：** 构建
**语言：** Python（标准库）
**前置知识：** Phase 7 · 02（自注意力）、Phase 7 · 15（注意力变体）、Phase 10 · 14（架构导览）
**耗时：** 约 60 分钟

## 学习目标

- 精确阐述为什么 softmax 注意力存在噪声基底，以及它为何随上下文长度增长。
- 推导差分注意力公式，并解释减法如何抵消共享噪声分量同时保留信号。
- 梳理 V1 到 V2 的差异：哪些部分变快了、哪些变简单了、哪些更稳定了，以及每项改动对生产级预训练的必要性。
- 使用纯 Python 从零实现差分注意力，并在合成信号加噪声查询上经验性验证其噪声抵消特性。

## 问题所在

标准 softmax 注意力具有一个数学特性，在大规模应用时会变成运维难题。对于查询 `q`，注意力权重为 `softmax(qK^T / sqrt(d))`。Softmax 永远无法产生精确的零值——每个不匹配的 token 都会获得一定的正质量。这部分残余质量就是噪声，且会随上下文长度缩放。在 128k token 的情况下，即使每个不匹配的 token 仅获得 0.001% 的概率，127,999 个 token 合计也会贡献约 12% 的总量。模型必须学会绕过这个随上下文增长的噪声基底。

经验上，这表现为注意力头之间的干扰：长上下文 RAG 中的幻觉引用、10 万 token 检索任务中的“迷失中间”失败，以及在 32k 以上的 needle-in-haystack 基准测试中细微的准确率下降。Differential Transformer 论文（arXiv:2410.05258，ICLR 2025）测量了这一差距：DIFF Transformer 相比同规模基线模型达到了更低的困惑度、更高的长上下文准确率和更少的幻觉。

DIFF V1 存在三个问题，使其无法进入前沿预训练流水线。它的值缓存（value cache）在每个解码步骤需要加载两次，它需要破坏 FlashAttention 兼容性的自定义 CUDA 算子，并且其每头 RMSNorm 在 70B 以上规模的长期训练中会导致不稳定。DIFF V2（Microsoft unilm 博客，2026年1月20日）修复了所有这三个问题。本课程将讲解这两个版本，构建差分算子，并在玩具查询上基准测试噪声抵消效果。

## 核心概念

### Softmax 的噪声基底

对于查询 `q` 和键 `K = [k_1, ..., k_N]`，注意力权重为：

```
w_i = exp(q . k_i / sqrt(d)) / sum_j exp(q . k_j / sqrt(d))
```

没有任何 `w_i` 会是零。如果 `k_i` 与 `q` 完全无关，得分 `q . k_i` 并非 0——它会围绕零波动，方差为 `||q||^2 / d`。经过 softmax 归一化后，每个不相关的 token 仍然会对加权和贡献 `O(1/N)`。不相关 token 的总贡献量为 `O((N-1)/N) = O(1)`——这并不是一个小量。

模型真正想要的是类似硬 top-k 的效果：对匹配的 token 赋予高权重，在其他位置赋予接近零的权重。Softmax 过于平滑，无法直接做到这一点。

### 差分思想

将每个头的 Q 和 K 投影拆分为两部分：Q = (Q_1, Q_2) 和 K = (K_1, K_2)。计算两个注意力图：

```
A_1 = softmax(Q_1 K_1^T / sqrt(d))
A_2 = softmax(Q_2 K_2^T / sqrt(d))
```

输出：

```
DiffAttn = (A_1 - lambda * A_2) V
```

减法会抵消两个图共享的任何噪声分布。如果两个图在 12.7 万个不相关 token 上都大致具有均匀权重（随机初始化时确实如此），它们就会相互抵消。信号——即集中在少数真正相关 token 上的峰值权重——只有当它以相同幅度出现在两个图中时才会被抵消，而模型训练后这种情况不会发生。

`lambda` 是每个头可学习的标量，参数化为 `lambda = exp(lambda_q1 dot lambda_k1) - exp(lambda_q2 dot lambda_k2) + lambda_init`。它可以为负数。`lambda_init` 默认设置为 0.8 这样的小正数。

### 为何这与头部噪声抵消机制契合

想象两个有噪麦克风录制同一个人的声音。两者都会拾取说话人声音以及相关的背景噪声。将其中一个减去另一个，共享的噪声就会消除。声音得以保留，是因为两个信号在相位或幅度上存在足够差异以防止完全抵消。每个头的 `lambda` 正是学习这种平衡。

### V1 与 V2 的差异

V1 保持了与基线 Transformer 相同的参数量。为了在每个头中获得两个查询，它将头维度减半。这牺牲了头的表达能力，而且更麻烦的是，每个头的值缓存也减半了。解码时必须每一步加载两次值缓存（每个 softmax 分支一次）。结果：尽管参数量匹配，但解码速度仍慢于基线。

V2 将查询头的数量翻倍，并保持 KV 头数量不变（从 up-projection 借用参数）。头维度保持与基线一致。减法之后，额外的维度会被投影回降维，以匹配基线 Transformer 的 O_W 投影。以下三件事同时发生：

1. 解码速度与基线匹配（KV 缓存只需加载一次）。
2. FlashAttention 无需修改即可运行（无需自定义算子）。
3. 解码时的算术强度提升（从 HBM 加载每字节数据对应的计算量增加）。

V2 还移除了 V1 用于稳定减法的每头 RMSNorm。在 70B 级别的预训练规模下，该 RMSNorm 会导致训练后期不稳定。V2 用一种更简单的初始化方案替代了它，在不增加额外模块的情况下保持训练稳定。

### 适用场景

| 工作负载 | 收益 |
|----------|------|
| 长上下文 RAG（64k+） | 注意力图更清晰，幻觉引用更少 |
| needle-in-haystack 基准测试 | 超过 32k 时准确率显著提升 |
| 多文档问答 | 减少跨文档干扰 |
| 8k 代码补全 | 收益微乎其微，不值得架构改动 |
| 短对话（< 4k） | 与基线基本无异 |

收益随上下文长度增长。在 4k token 时，噪声基底足够小，标准注意力完全够用。到了 128k，它就会拖累性能。

## 动手实现

`code/main.py` 使用纯 Python 实现了差分注意力。带有已知信号加噪声结构的玩具查询让你可以直接测量噪声抵消比率。

### 步骤 1：标准 softmax 注意力

标准库矩阵运算：列表的列表、手动矩阵乘法、带数值稳定性（减去最大值）的 softmax。

```python
def softmax(row):
    m = max(row)
    exps = [math.exp(x - m) for x in row]
    s = sum(exps)
    return [e / s for e in exps]
```

### 步骤 2：将 Q、K 拆分为两半

V1 风格：将头维度减半。V2 风格：保持头维度并将头数量翻倍。玩具实现采用 V1 风格以保证教学清晰度——数学原理完全相同，仅维度管理不同。

### 步骤 3：两个 softmax 分支 + 减法

```python
A1 = [softmax([dot(q1, k) / scale for k in K1]) for q1 in Q1]
A2 = [softmax([dot(q2, k) / scale for k in K2]) for q2 in Q2]
diff_weights = [[a1 - lam * a2 for a1, a2 in zip(r1, r2)] for r1, r2 in zip(A1, A2)]
out = [[sum(w * v[j] for w, v in zip(row, V)) for j in range(d_v)] for row in diff_weights]
```

注意：输出权重可以为负。这没问题——值缓存仍能处理带符号的贡献。后续的 V 投影会吸收该符号。

### 步骤 4：噪声抵消测量

构建长度为 1024 的合成序列。将信号 token 放在已知位置，其余填充噪声。计算 (a) 信号位置的标准 softmax 注意力权重和 (b) 差分注意力权重。分别测量两者的信噪比。DIFF 注意力能可靠地产生高出 3 到 10 倍的信噪比，具体倍数取决于两个分支的训练差异程度。

### 步骤 5：V1 与 V2 参数量核算

给定配置（hidden=4096, heads=32, d_head=128），打印：

- 基线 Transformer：Q、K、V 各大小为 `hidden * hidden`，MLP 为 4 * hidden。
- DIFF V1：Q、K 各大小为 `hidden * hidden`，V 大小为 `hidden * hidden`（不变），内部头维度减半。增加每头 `lambda` 参数（O(heads * d_head)）。
- DIFF V2：Q 大小为 `2 * hidden * hidden`，K 大小为 `hidden * hidden`，V 大小为 `hidden * hidden`。额外维度在 O_W 之前投影回降维。增加相同的 `lambda` 参数。

玩具实现会测量 V2 的额外参数成本（每个注意力块大约多出 `hidden * hidden`）并将其打印出来。

## 实际应用

DIFF V2 截至 2026 年 4 月尚未在所有生产推理服务器中发布，但 vLLM 和 SGLang 正在集成中。与此同时，该模式已出现在：

- Microsoft 内部的长上下文生产模型中。
- 多个瞄准 256k+ 上下文的开源模型训练实验的研究复现中。
- 交替层结合 DIFF 注意力与滑动窗口注意力的混合架构中。

在 2026 年何时考虑使用它：

- 从头训练新模型，目标有效上下文为 64k+。从一开始就加入差分注意力；后期重新训练成本高昂。
- 微调长上下文模型，且评估中“迷失中间”失败占主导。对 Q 投影应用 LoRA 可近似 DIFF 结构。

何时不应使用：

- 你正在部署具有稳定长上下文性能的预训练稠密模型。重新训练的成本通常无法从现有权重中收回。
- 你的上下文始终低于 16k。噪声基底可忽略不计。

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|----------|----------|
| 差分注意力 | “两个 softmax 相减” | 将 Q、K 拆分为两半，计算两个 softmax 图，从第一个中减去第二个（经 lambda 缩放），然后乘以 V |
| 噪声基底 | “softmax 的非零尾部” | softmax 分配给每个不相关 token 的 O(1/N) 权重，在长上下文中累加至 O(1) |
| lambda | “减法缩放因子” | 每头可学习标量，参数化为 `exp(lq1.lk1) - exp(lq2.lk2) + lambda_init`；可为负数 |
| DIFF V1 | “ICLR 2025 版本” | 原始差分 Transformer；为保持参数量而将头维度减半，需要自定义算子，解码较慢 |
| DIFF V2 | “2026年1月修复版” | 保持 KV 头数量不变并将 Q 头翻倍；解码速度与基线匹配，兼容 FlashAttention |
| 每头 RMSNorm | “V1 稳定器” | V1 在差分后应用的额外归一化；V2 将其移除以防止训练后期不稳定 |
| 信噪比 | “注意力浪费了多少” | 真实信号位置权重与不相关位置平均权重的比值 |
| 迷失中间 | “长上下文失效模式” | 检索准确性在长上下文中间文档处下降的经验现象——DIFF 注意力可减少此问题 |
| 算术强度 | “每加载字节的浮点运算次数” | V2 通过将每次 KV 加载的查询翻倍来提升解码时的该比率；对内存受限的解码至关重要 |
