# 推测解码与 EAGLE-3

## 学习目标

- 用一句话阐述 Leviathan 定理，并证明推测循环产生的样本与直接采样自验证器的样本具有完全相同的分布。
- 梳理从 vanilla spec-decoding（Leviathan 2023）到 EAGLE、EAGLE-2 和 EAGLE-3 的两年演进历程，并指出每一步具体消除了哪些限制。
- 根据接受率 `α` 和草稿到验证器的成本比 `c` 计算预期加速比，并为不同场景选择最优的草稿长度 `N`。
- 从零实现完整的推测循环：生成草稿、验证、从残差分布中采样拒绝项、在拒绝时回滚 KV 缓存、在全接受时输出奖励 token。

## 问题背景

在 H100 上对 70B 模型进行自回归解码的速度可能仅为每秒 35 个 token。GPU 远未达到饱和。内存带宽是瓶颈：每个 token 都需要从 HBM 加载 70B 权重，执行一步算术运算，并输出一个浮点数。计算单元大部分时间处于空闲状态。

推测解码将其转化为一个你实际上可以解决的吞吐量问题。廉价的草稿模型通过 `N` 次小型前向传播提出 `N` 个 token。验证器在上下文前缀加上全部 `N` 个草稿 token 上运行一次。如果验证器在位置 `i` 的分布与草稿一致（我们将在后文给出精确的统计定义），则接受；否则拒绝，并从残差分布中采样修正 token。单次大模型前向传播可产生多达 `N+1` 个被接受的 token，而非仅仅一个。

最重要的定理来自 Leviathan、Kalman 和 Matias（ICML 2023）：输出分布与直接从验证器采样的分布完全相同。不是近似相同，而是完全相同。这正是推测解码在生产环境中被广泛接受的根本原因——它是一种纯粹的延迟优化，且不牺牲任何质量。

第 7 阶段 · 第 16 课为你提供了数学基础。而本课提供的是训练栈。一个好的草稿模型带来的加速效果是廉价草稿的两倍。EAGLE、EAGLE-2 和 EAGLE-3（Li 等，2024–2025）将“草稿 = 同一模型的缩小版”转变为一门精确的工程学科。2026 年的生产推理服务器默认采用 EAGLE-3。

## 核心概念

### 不变量：Leviathan 拒绝采样

设 `p(t)` 为给定某前缀时草稿模型对下一个 token 的分布，`q(t)` 为验证器的分布。采样一个草稿 token `d ~ p`。以概率 `min(1, q(d) / p(d))` 接受它。若拒绝，则从残差分布 `(q - p)_+ / ||(q - p)_+||_1` 中采样。最终得到的样本服从 `q` 分布。无论 `p` 有多糟糕，这一结论都成立——它越差，拒绝发生的频率越高，但输出始终保持精确。

使用一次验证器前向传播处理 `prefix + d_1 + ... + d_N`，将 `N` 次调用依次堆叠。验证器同时返回 `q_1, q_2, ..., q_{N+1}`。从左向右遍历。在位置 `j` 首次遇到拒绝时，从 `residual(q_j, p_j)` 中采样并停止。若全部接受，则从 `q_{N+1}` 中采样一个奖励 token。

### 决定加速比的因素

设 `α` 为每个草稿 token 的预期接受率。设 `c = cost(draft) / cost(verifier)` 为成本比。每次验证器前向传播的预期接受 token 数为：

```
E[accepted] = (1 - α^(N+1)) / (1 - α)
```

每个被接受 token 的预期总墙钟时间为 `(N * c + 1) / E[accepted]`。对其关于 `N` 求最小值即可找到最佳平衡点。对于 `α = 0.8, c = 0.05`：最优 `N` 约为 5–7，加速比为 3.2×。对于 `α = 0.95, c = 0.02`：最优 `N` 约为 8–10，加速比可达 5×。

最大的杠杆在于 `α`。在固定 `N = 5` 的情况下，从 `α = 0.6`（原始草稿）升级到 `α = 0.9`（EAGLE-3），可将每次验证器前向传播的预期接受 token 数从 2.2 提升至 4.1。仅凭同一个验证器，吞吐量几乎翻倍。

### 两年演进历程

**原始推测解码（Leviathan，2023）**。草稿模型是与主模型同家族但独立训练的较小规模 LLM。易于接入，但 `α ≈ 0.6`，加速比最高仅约 2×。

**EAGLE-1（Li 等，2024）**。草稿模型是一个极小的 Transformer（通常仅一两层），它以验证器最后一层的隐藏状态作为输入，直接预测下一个 token。由于草稿模型能够观察到验证器的特征表示，其分布与验证器更为接近。`α` 攀升至 0.7–0.8。

**EAGLE-2（Li 等，2024）**：引入动态草稿树：不再提议单一序列的 `N` 个 token，而是提议一棵候选小树，在一次前向传播中利用验证器对所有候选进行打分（树注意力机制），并沿概率最高的路径前进。草稿长度变为每步自适应。`α` 随被接受路径的 token 数攀升至 0.85 以上。

**EAGLE-3（Li 等，2025，NeurIPS）**：新增两项改进。首先，彻底放弃特征预测损失——EAGLE-1/2 训练草稿模型去匹配验证器的隐藏状态，这限制了数据带来的收益上限。EAGLE-3 直接在 token 预测上进行训练。其次，训练时测试（TTT）：在草稿训练期间，将草稿模型自身之前的预测结果在多步中反馈作为输入，与其在推理时的运作方式保持一致。这对齐了训练与测试分布，并阻止了误差累积。实测加速比：聊天场景下高达 6.5×，在 H100 上使用 SGLang 且 batch size 为 64 时吞吐量提升 38%。

### KV 缓存回滚

验证过程在一次传递中将验证器的 KV 缓存扩展 `N` 个条目。如果在位置 `j` 发生拒绝，那么位置 `j-1` 之后的缓存内容现已失效。两种常见实现方式：写入临时缓冲区并在接受时提交（vLLM、TensorRT-LLM），或维护物理 KV 缓存加逻辑长度并在拒绝时截断。无论如何，回滚成本仅为每层每头的几个字节，与前向传播成本相比可忽略不计。

对于 EAGLE-2 的树搜索，验证器会使用尊重树拓扑结构的非因果掩码运行注意力机制。工程实现较为繁琐，但计算本质上是带有自定义掩码的标准 flash-attention 调用。

### 2026 年的草稿架构

| 策略 | 草稿类型 | `α` | 加速比 | 训练成本 |
|----------|-----------|-----|---------|---------------|
| 原始推测 | 独立的小型 LLM | 0.55-0.70 | 1.8-2.3× | 无（复用现有小模型） |
| Medusa | 验证器附加额外 LM head | 0.65-0.75 | 2-3× | 约 1B SFT token |
| EAGLE-1 | 作用于隐藏状态的 1 层 Transformer | 0.70-0.80 | 2.5-3× | 约 60B token |
| EAGLE-2 | EAGLE-1 + 动态草稿树 | 0.80-0.88 | 3-4× | 约 60B token |
| EAGLE-3 | 多层特征融合 + TTT | 0.88-0.92 | 3.5-6.5× | 约 60-200B token |
| Lookahead | 无草稿（雅可比迭代） | 不适用 | 1.3-1.6× | 无 |

2026 年生产环境：vLLM 和 SGLang 在可用时默认采用 EAGLE-3，否则降级为 EAGLE-2。TensorRT-LLM 针对 Meta 和 NVIDIA 公开模型提供了最快的 Medusa 路径。llama.cpp 为 CPU 部署提供原始草稿方案。

## 动手实现

参见 `code/main.py`。这是包含所有组件的完整 Leviathan 推测循环：N 次草稿生成、验证器并行传递、逐位置拒绝、残差采样、奖励 token、KV 缓存回滚，以及经验证输出分布与直接从 `q` 采样的分布一致的实证检验。

### 步骤 1：拒绝规则

```python
def accept(q_prob, p_prob, u):
    if p_prob <= 0:
        return True
    return u < min(1.0, q_prob / p_prob)
```

### 步骤 2：残差分布

```python
def residual(q, p):
    raw = [max(0.0, qi - pi) for qi, pi in zip(q, p)]
    s = sum(raw)
    if s == 0:
        return list(q)
    return [r / s for r in raw]
```

### 步骤 3：完整的推测步骤

``spec_step`` 函数从 `p` 生成 `N` 个草稿 token，随后在一次并行的 `q` 评估中验证它们。针对每个草稿 token 应用拒绝规则，并在首次拒绝时从残差分布中采样修正值。若全部接受，则从 `q_{N+1}` 输出一个奖励 token。

### 步骤 4：KV 缓存回滚记账

模拟器为每个工作进程跟踪一个逻辑 `kv_length`。在接受 `k` 个草稿时，`kv_length += k`。若在位置 `j` 发生拒绝，缓存已写入至 `j` 之后，但逻辑长度被设置为 `prefix_length + j + 1`——即修正 token 之后一位。后续读取将按逻辑长度进行截断。

### 步骤 5：Leviathan 校验

运行 50,000 次推测步骤。统计被接受 token 的经验分布。将其与从 `q` 直接采样的 50,000 个样本进行比较。卡方统计量应远低于临界值。该定理在实践中得到验证。

### 步骤 6：加速比与 α 的关系

通过在不同幅度下扰动 `p` 使其偏离 `q` 来扫描草稿质量。测量 `α`，然后绘制每次验证器调用的预期 token 数随 `α` 和 `N` 变化的曲线。代码将打印一张表格，展示 EAGLE-3 级别的草稿质量（`α ≈ 0.9`）如何使每次验证器调用解锁 4–5 个 token。

## 生产应用

生产级 `vllm serve`（配合 EAGLE-3）：

```bash
vllm serve meta-llama/Llama-3.3-70B-Instruct \
  --speculative-config '{
    "model": "yuhuili/EAGLE3-LLaMA3.3-Instruct-70B",
    "num_speculative_tokens": 5,
    "method": "eagle3"
  }'
```

在 H100 上使用 SGLang 配合 EAGLE-3（batch size 为 64）：根据 EAGLE-3 论文，吞吐量比 batch size 为 64 的原始推测解码高出约 1.38 倍。

何时使用推测解码：

- 任何交互型聊天工作负载，其中 p50 延迟比峰值吞吐量更重要。
- 代码生成和结构化输出（JSON、SQL）。`α` 高于 0.9，因为目标分布高度可预测。
- 长文本生成（数千个 token）。摊销后的加速比持续带来收益。

何时避免使用：

- 极小模型（< 3B）。草稿模型并不比验证器便宜多少。
- 极小规模 batch-1 CPU 部署。草稿模型的内存开销可能得不偿失。
- 极高温度下的创造性采样，此时 `α` 会急剧下降。

## 关键术语

| 术语 | 人们常说的说法 | 实际含义 |
|------|----------------|------------------------|
| Leviathan 规则 | “min(1, q/p)” | 以概率 `min(1, q(d)/p(d))` 进行伯努利接受/拒绝；在拒绝时从残差分布采样，可精确保留验证器分布 |
| 残差分布 | “(q - p) 取正后归一化” | 将 `(q - p)_+` 截断为零并重新归一化——拒绝时应从中采样的正确分布 |
| 接受率 α | “草稿猜对的频率” | 拒绝规则下每个 token 的伯努利成功期望概率；支配所有加速比计算 |
| EAGLE-1 | “隐藏状态草稿” | 以验证器最后一层隐藏状态为条件的极小 Transformer 草稿模型（Li 等，2024） |
| EAGLE-2 | “动态草稿树” | EAGLE-1 加上候选续写树，在一次验证器传递中利用树注意力进行打分 |
| EAGLE-3 | “训练时测试” | 放弃特征预测损失，直接在 token 预测上训练，训练期间将草稿模型自身的输出反馈给它 |
| 训练时测试（TTT） | “修复暴露偏差” | 在训练期间让草稿模型自回归运行，使训练与测试输入分布一致——即计划采样的直接类比 |
| KV 缓存回滚 | “撤销被拒绝的草稿” | 拒绝发生后，将验证器的 KV 缓存重置为已接受前缀长度的记账操作 |
| 奖励 token | “免费的那个” | 当全部 `N` 个草稿被接受时，无需额外验证器成本即可从 `q_{N+1}` 多采样一个 |
| 树注意力 | “一次性验证多个候选” | 使用尊重草稿树拓扑结构的非因果掩码的注意力机制；在一次前向传播中计算树中每个节点的 `q_i` |
