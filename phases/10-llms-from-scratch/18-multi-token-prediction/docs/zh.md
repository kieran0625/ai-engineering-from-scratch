# 多词元预测 (MTP)

> 从 GPT-2 到 Llama 3，每个自回归 LLM 的训练目标都是每个位置一个损失：预测下一个词元。DeepSeek-V3 为每个位置增加了第二个损失：预测该词元之后的词元。额外的 14B 参数（在 671B 的模型上）通过梯度流蒸馏回主模型，训练好的 MTP 头在推理时被重新用作推测解码的草稿生成器，接受率超过 80%。生成吞吐量提升了 1.8 倍，且几乎零成本。本课程将基于 DeepSeek 技术报告从零构建顺序 MTP 模块，计算损失与共享头的参数布局，并解释为什么 MTP 保留了因果链，而 Gloeckle 等人最初的并行 MTP 却破坏了它。

**类型：** 构建
**语言：** Python (stdlib)
**前置知识：** 第 10 阶段 · 04（预训练迷你 GPT）、第 10 阶段 · 15（推测解码）
**时间：** 约 60 分钟

## 学习目标

- 阐述 MTP 的训练目标，并推导跨预测深度的联合损失。
- 解释 Gloeckle 等人的并行 MTP 头（2024）与 DeepSeek-V3 的顺序 MTP 模块之间的区别，以及为什么顺序设计能保留因果链。
- 计算在预训练中增加 MTP 模块所带来的参数和显存开销。
- 从零实现一个 MTP 模块：共享嵌入、每深度 Transformer 块、投影层和共享输出头。

## 问题背景

下一个词元预测是标准的 LLM 训练目标。每个隐藏状态都被监督去预测恰好一件事：紧随其后的那个词元。这是一个相当微弱的信号。序列中的大部分信息都超出了单个词元的范围——结构、连贯性、事实准确性、算术逻辑流。模型必须通过在数万亿个词元上积累大量的单词元信号来学习这些特性。

MTP 提出一个问题：如果每个隐藏状态都被监督去同时预测多个未来词元会怎样？Gloeckle 等人（Meta，2024）证明了这确实有帮助。他们的实现在骨干网络上放置了几个独立的输出头，每个头预测不同的偏移量。这种方法并行且简单，但各个头看到的是同一个隐藏状态，缺乏层次化的细化——并且预测结果之间没有形成因果链，因此无法用于推测解码。

DeepSeek-V3（2024年12月）将 MTP 重新设计为顺序模块，在每个预测深度保留因果链。模型从 `h_i^(0)` 预测 `t+1`，然后从一个结合了 `h_i^(0)` 与 `E(t+1)` 嵌入的新隐藏状态 `h_i^(1)` 中预测 `t+2`，依此类推。每个深度都是一个独立的小型 Transformer 块。共享嵌入和共享输出头将参数开销控制在合理范围内。在 DeepSeek-V3 的规模下，主模型 671B 权重之上，MTP 模块仅增加了 14B 额外参数。这 2% 的开销既带来了更密集的训练信号，又在推理时提供了现成的推测解码草稿。

本课程将从零构建单个 MTP 模块及 D 层深度的损失。数学推导清晰整洁，实现代码仅需 150 行。

## 核心概念

### 顺序 MTP 设计

DeepSeek-V3 在主模型之上添加了 `D` 个 MTP 模块。每个模块 `k`（对应 `k = 1..D`）负责预测深度 `k` 处的词元——即给定通过位置 `i` 的前缀，预测 `t_{i+k}`。

模块 `k` 包含：

- 一个带有独立注意力机制和 MLP 的 Transformer 块 `T_k`。
- 一个投影矩阵 `M_k`，用于结合上一深度的隐藏状态与下一深度真实词元的嵌入。
- 共享嵌入 `E`（与主模型相同）。
- 共享输出头 `Out`（与主模型相同）。

在训练时，对于通过位置 `i` 的前缀，各深度的隐藏状态为：

```
h_i^(0) = main model backbone at position i
h_i^(k) = T_k( M_k * concat(RMSNorm(h_i^(k-1)), RMSNorm(E(t_{i+k}))) )   for k >= 1
```

各深度的预测结果为：

```
logits_{i+k} = Out(h_i^(k-1))   for k = 1..D
```

各深度的损失是对真实标签 `t_{i+k}` 的交叉熵：

```
L_k = CE(logits_{i+k}, t_{i+k})
```

跨深度的联合损失为：

```
L_MTP = (lambda / D) * sum_{k=1..D} L_k
```

`lambda` 是一个较小的加权因子——DeepSeek-V3 在训练的前 10% 阶段使用 0.3，之后使用 0.1。总训练损失为 `L_main + L_MTP`。

### 为什么是顺序而非并行

Gloeckle 原始的并行 MTP 拥有 D 个输出头，每个头直接作用于 `h_i^(0)`。每个头都从相同的骨干隐藏状态预测 `t_{i+k}`。这种设计可以正常训练，但预测结果之间互不依赖。你无法利用 `head_1` 的输出辅助 `head_2`——因为各个头是并行触发的。

DeepSeek-V3 的顺序设计通过将 `h_i^(k-1)` 与实际的下个词元嵌入 `E(t_{i+k})` 结合来构建 `h_i^(k)`。这保留了因果链：为了预测 `t_{i+k+1}`，深度 `k+1` 处的模块会看到 `t_{i+k}` 的内容。这在结构上与自回归解码器消费自身输出的方式完全一致——使得 MTP 模块可直接用作推测解码的草稿生成器。

在推理时：将 `h_i^(k-1)` 和已生成的草稿 `t_{i+k}` 输入模块 `k+1`，得到对 `t_{i+k+1}` 的预测。重复此过程。这正是 EAGLE 风格的草稿生成流程，利用训练好的 MTP 模块作为草稿网络。DeepSeek-V3 报告首个 MTP 模块的接受率超过 80%，速度提升约 1.8 倍。

### 参数核算

对于一个隐藏维度为 `h`、词表大小为 `V` 的模型：

- 主模型：数十亿参数，外加一个大小为 `V * h` 的输出头。
- 共享输出头：复用主模型的输出头。无额外参数。
- 共享嵌入：复用主模型的嵌入表。无额外参数。
- 每个 MTP 模块：
  - 投影层 `M_k`：参数量 `(2h) * h = 2h^2`。
  - Transformer 块 `T_k`：注意力部分（MHA 为 `4h^2`）加上 MLP（通常 SwiGLU 比例为 8/3，参数量为 `8h^2`）。每个块约 `12h^2`。

每个模块的额外总参数量：`~14h^2`。对于 DeepSeek-V3 的 `h = 7168`，D = 1 个模块：理论参数量 `~14 * 7168^2 = ~720M`。DeepSeek-V3 实际报告为 14B——差异主要在于 MTP 模块中的专家层同样采用了 MoE 架构。

### 推测解码的收益

在预训练期间，MTP 模块会使训练速度降低约 10%（前向计算量增加，额外损失计算）。但其收益是双重的：

1. 更密集的训练信号。每个隐藏状态面对 D+1 个监督目标。在 MMLU、GSM8K、MATH、HumanEval 上的实测效果显示：DeepSeek-V3 的消融实验均带来稳定的几个百分点的性能提升。

2. 推理时免费获得推测解码草稿。MTP 模块已经过训练以预测接下来的几个词元。将其重新用作草稿网络时，可实现 80% 以上的接受率。在此水平下，N=3 或 N=5 的推测解码可带来 1.8 倍的吞吐量提升。这 10% 的训练时间成本在首次运行推理时即可收回。

### 与 EAGLE 的关系

EAGLE 在预训练完成后单独训练一个小型草稿模型。MTP 则将草稿生成能力直接融入预训练过程中。这两种方法最终收敛于相似的接受率，但流水线不同：

| 维度 | EAGLE-3 | MTP (DeepSeek-V3) |
|-----------|---------|------------------|
| 训练时机 | 预训练之后 | 预训练期间 |
| 是否兼容现有权重 | 是 | 否（需重新训练） |
| 草稿参数量 | 1-2 个 Transformer 层 | 1 个 Transformer 块 + 投影层 |
| 接受率 | 0.88-0.92 | 深度 1 处 > 0.80 |
| 除加速外的收益 | 仅限推测解码 | 更密集的训练信号 + 加速 |

## 动手实现

`code/main.py` 从头到尾构建单个 MTP 模块：共享嵌入、投影层、Transformer 块、共享输出头。随后它在一段简短的合成序列上计算各深度的交叉熵损失，并按组件打印参数量。使用 32 个词元的小词表可使数值更易读。

### 步骤 1：共享嵌入表

单一的 `vocab_size x hidden` 表由主模型 AND 所有深度下的每个 MTP 模块共同使用。不是第二份副本——字面意义上是同一个张量。

### 步骤 2：逐深度组合

```python
def combine(prev_hidden, next_token_embed, M_k):
    # concat along feature dim, then project down to hidden
    concat = rms_norm(prev_hidden) + rms_norm(next_token_embed)  # vector addition stand-in
    projected = matvec(M_k, concat)
    return projected
```

真实的 DeepSeek-V3 将两个经过 RMSNorm 的向量拼接为 `[2h]`，并使用 `h x 2h` 矩阵进行投影。本示例为了标准库实现的简洁性，采用向量加法。

### 步骤 3：深度 k 的 Transformer 块

自注意力机制加上 MLP。在本示例中，单层线性注意力块与 SwiGLU MLP 在不依赖 numpy 的情况下保持了结构清晰可见。

### 步骤 4：共享输出头

复用主模型的输出投影层。输出词表维度的 logits。

### 步骤 5：逐深度损失

对 softmax(logits) 与偏移量为 `k` 的真实词元计算交叉熵。使用 `lambda / D` 缩放因子在各深度间进行聚合。

### 步骤 6：参数核算

打印总参数量、共享部分（嵌入、输出头）参数量以及每个模块的额外参数量。展示 MTP 额外参数量占主模型规模的比率。

## 应用场景

MTP 已集成至 DeepSeek-V3（2024年12月）及 DeepSeek-R1 系列。在推理时：

- DeepSeek 自身的推理服务栈开箱即用地将 MTP 模块作为推测解码器调用。
- 截至 2026 年 4 月，vLLM 和 SGLang 均已提供 DeepSeek-V3 MTP 的集成路径。
- AMD 的 ROCm SGLang 教程展示了特定的 MTP 推测解码配置，在 V3 检查点上实测速度提升 1.8 倍。

在新预训练任务中使用 MTP 的适用场景：

- 你掌控完整的预训练流水线，并希望获取更密集的训练信号。
- 你明确知道将在大规模场景下部署该模型，并希望免费获得推测解码能力。
- 你的隐藏层维度至少为 4096。在 1B 规模下，开销带来的负面影响可能大于收益。

不适用场景：

- 微调现有的预训练稠密模型。MTP 模块未经过训练。
- 需要干净基线进行对比的研究模型。MTP 会改变模型架构。

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|----------------|------------------------|
| MTP 模块 | “额外损失块” | 一个小尺寸 Transformer 块加投影层，用于预测主模型前方 `k` 个位置的词元 |
| 预测深度 | “哪个偏移量” | 整数 `k`，表示模块 `k` 从通过位置 `i` 的前缀中预测 `t_{i+k}` |
| 并行 MTP | “Gloeckle 风格” | 在相同骨干隐藏状态上设置 D 个独立头，无条件依赖链 |
| 顺序 MTP | “DeepSeek-V3 风格” | 每个模块依赖前一深度的隐藏状态加上下个词元的嵌入；保留因果链 |
| 共享输出头 | “复用主输出头” | MTP 模块直接调用主模型的 LM 头，而非独立的输出投影 |
| 共享嵌入 | “复用主词表” | 全局使用同一词表嵌入表；无重复参数 |
| 投影矩阵 M_k | “融合隐藏状态+下个词元” | 一个 `h x 2h` 线性层，将前一隐藏状态与目标词元嵌入折叠为下一深度的输入 |
| 联合损失 L_MTP | “平均额外损失” | 各深度交叉熵损失的算术平均值，经 `lambda` 缩放 |
| 深度 1 接受率 | “MTP 草稿猜对的比例” | D=1 MTP 模块的 top-1 预测与主模型 top-1 预测一致的比率；DeepSeek-V3 上 > 80% |
| Lambda 加权 | “额外损失的重要性” | 逐深度缩放因子；DeepSeek-V3 训练初期为 0.3，后期为 0.1 |
