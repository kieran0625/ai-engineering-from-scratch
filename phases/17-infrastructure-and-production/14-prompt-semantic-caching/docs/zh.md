# 提示词缓存与语义缓存经济学

> **价格快照截至 2026 年 4 月。** 下文中的数值基于本课程发布时捕获的厂商价目表；在下游引用前，请务必对照相关文档进行核实。

> 缓存分为两个层级。L2（提供商级）提示词/前缀缓存通过复用注意力机制的 KV 来应对重复的前缀——Anthropic 的提示词缓存文档宣称，对于长提示词可实现高达 90% 的成本降低和 85% 的延迟降低；针对 Claude 3.5 Sonnet，缓存读取价格为 $0.30/M，而全新请求为 $3.00/M，TTL 为 5 分钟，若选择 1 小时 TTL 选项则写入价格翻倍（docs.anthropic.com，2026-04）。OpenAI 提示词缓存对 ≥1024 token 的提示词自动生效，缓存输入的价格约为全新输入的 10%（platform.openai.com，2026-04）；具体的每模型缓存费率取决于实时价目表。L1（应用级）语义缓存在嵌入相似度命中时直接跳过 LLM。厂商宣称的“95% 准确率”指的是匹配的正确性，而非命中率——实际生产环境的命中率范围从开放式对话的 10% 到结构化 FAQ 的 70% 不等；两家厂商均未公布官方基线，因此请将这些数据视为社区观测值而非保证。生产环境中的陷阱：并行化会破坏缓存（在首次缓存写入完成前发出的 N 个并行请求可能会使支出膨胀数倍），且前缀内的动态内容会导致完全无法命中缓存。ProjectDiscovery 通过将动态文本移出可缓存前缀，将命中率从 7% 提升至 74%（2025-11）。

## 学习目标

- 区分 L2 提示词/前缀缓存（提供商级的 KV 复用）与 L1 语义缓存（相似提示词直接绕过 LLM）。
- 解释 Anthropic 的 `cache_control` 显式标记机制，以及两种 TTL 选项（5 分钟 vs 1 小时）及其价格乘数。
- 根据命中率、提示词/响应比例及 token 价格计算预期月度节省金额。
- 指出会使账单膨胀 5-10 倍的并行化反模式，以及会导致命中率归零的动态内容反模式。

## 问题背景

你将提示词缓存引入 RAG 服务后，账单却纹丝不动。你测量了命中率，仅为 7%。你的提示词看起来是静态的，但并非如此——系统提示词包含了精确到分钟的当前日期、请求 ID，以及为了多样性而随机重排的例子。每个请求都会写入新的缓存条目，读取量为零。

另一方面，你的智能体针对每个用户问题运行十个并行工具调用。这十个请求都在首次缓存写入完成前到达提供商。十次写入，零次读取。你的账单是“开启缓存后”预期成本的 5-10 倍。

缓存是一种协议，而不是一个开关。两层架构，两种不同的故障模式。

## 核心概念

### L2 — 提供商提示词/前缀缓存

提供商为可缓存的前缀存储注意力 KV，并在下一个匹配该前缀的请求中复用它们。你只需支付一次写入成本，读取几乎免费。

**Anthropic（Claude 3.5 / 3.7 / 4 系列）**：请求中需包含显式的 `cache_control` 标记。你需指定哪些块是可缓存的。TTL：5 分钟（写入成本为基础价格的 1.25 倍）或 1 小时（写入成本为基础价格的 2 倍）。缓存读取：Claude 3.5 Sonnet 为 $0.30/M，而全新请求为 $3.00/M——便宜 10 倍（docs.anthropic.com，截至 2026-04）。各模型费率不同（Opus/Haiku 单独公布）；务必交叉核对实时定价页面。

**OpenAI**：对 ≥1024 token 的提示词自动启用缓存（platform.openai.com，2026-04）。无需显式标记。在当前 gpt-4o/gpt-5 价目表下，缓存输入的价格约为全新输入的 10%。无论是文档还是发布说明均未公布官方的命中率基线；社区报告表明，经过精心设计的提示词命中率集中在 30%–60%。请监控 `usage.cached_tokens` 以测量你自己的数据。

**Google（Gemini）**：通过显式 API 提供上下文缓存；1M token 的上下文意味着缓存的收益更高。

**自托管（vLLM, SGLang）**：Phase 17 · 06 涵盖了 RadixAttention——在你自己的算力上采用相同模式。

### L1 — 应用级语义缓存

在调用 LLM 之前，先对提示词进行哈希和嵌入，并查找相似的已缓存请求（余弦相似度高于阈值，通常为 0.95+）。命中时返回缓存的响应；未命中时调用 LLM 并缓存结果。

开源方案：Redis Vector Similarity、GPTCache、Qdrant。商业方案：Portkey Cache、Helicone Cache。

厂商的准确率声明指的是返回的缓存响应在语义上合适的频率——而非命中率。实际生产环境的命中率：

- 开放式对话：10-15%。
- 结构化 FAQ / 客服支持：40-70%。
- 代码类问题：20-30%（细微变体会导致命中率下降）。
- 语音智能体重复提示词：50-80%（语音标准化固定集）。

### 并行化反模式

你的智能体并行发起 10 个工具调用。所有 10 个都带有相同的 4K token 系统提示词。Anthropic 的缓存写入是按请求计算的；首个缓存写入在提供商看到提示词后约 300 ms 完成。请求 2-10 在同一毫秒窗口内到达，且每次都会缓存未命中。你支付了 10 次写入溢价，却享受不到 0 次读取折扣。

修复方法：采用顺序优先的批处理——先单独发出请求 1，待其缓存填充后再并发触发请求 2-10。这会使首个工具调用增加 300 ms，但能节省 5-10 倍的账单。

### 动态内容反模式

你的系统提示词如下所示：

```
You are a helpful assistant. The current time is 14:32:17.
User ID: abc123. Today is Tuesday...
```

每个请求都是唯一的。每个请求都会写入。命中率为零。

修复方法：将所有真正静态的内容移至可缓存前缀；将动态内容追加到缓存边界之后：

```
[cacheable]
You are a helpful assistant. [rules, examples, instructions]
[/cacheable]
[dynamic, not cached]
Current time: 14:32:17. User: abc123.
```

ProjectDiscovery 正是通过这种方式将缓存命中率从 7% 提升至 74%，并公开了其结构分析。

### 批处理与缓存叠加用于夜间工作负载

批处理 API（Phase 17 · 15）在 24 小时周转期内提供 50% 折扣。在此基础上叠加缓存输入，可获得额外的约 10 倍优惠。通过叠加使用，夜间分类、标注和报告生成工作负载的成本可降至同步非缓存成本的约 10%。

### 关键数据速记

定价数据截取自 2026 年 4 月的链接厂商文档，且每隔几个月就会变动——依赖这些数据前请重新核对。

- Anthropic 缓存读取：Claude 3.5 Sonnet 为 $0.30/M，比全新输入便宜约 10 倍（docs.anthropic.com）。
- Anthropic 缓存写入溢价：1.25 倍（5 分钟 TTL）或 2 倍（1 小时 TTL）。

## 核心术语

| 术语 | 常见说法 | 实际含义 |
|------|------------------------|------------------------|
| L2 提示词缓存 | “前缀缓存” | 提供商为重复前缀存储 KV |
| `cache_control` | “Anthropic 缓存标记” | 显式属性标记可缓存块 |
| 缓存写入溢价 | “写入税” | 首次未命中至缓存的额外成本（1.25 倍或 2 倍） |
| L1 语义缓存 | “嵌入缓存” | 调用 LLM 前的应用级哈希与嵌入 |
| GPTCache | “LLM 缓存库” | 流行的开源 L1 缓存库 |
| 缓存命中率 | “命中数 / 总数” | 从缓存服务的请求比例 |
| 并行化反模式 | “N 次写入陷阱” | N 个并行请求导致缓存未命中 N 次 |
| 动态内容陷阱 | “提示词时间陷阱” | 前缀中的动态字节会导致命中率归零 |
| RadixAttention | “副本内缓存” | SGLang 的前缀缓存实现 |
