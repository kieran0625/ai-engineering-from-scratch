# InternVL3：原生多模态预训练

> InternVL3 之前的所有开源视觉语言模型（VLM）都遵循相同的三步配方：使用在数万亿文本 token 上训练的文本大语言模型，外挂一个视觉编码器，随后微调两者之间的接口。这种方法可行，但会产生对齐债务——文本 LLM 已将其全部预训练预算用于纯文本，并不原生理解视觉 token。当你事后添加视觉能力时，LLM 必须重新学习如何将视觉输入与其文本推理关联起来，同时不能遗忘已有的文本知识。InternVL3（Zhu 等，2025年4月）摒弃了事后添加的方案：仅进行一次预训练运行，从第一步开始就将文本与多模态数据交错混合。其结果在 78B 参数规模下于 MMMU-Pro 基准上达到了与 Gemini 2.5 Pro 相当的水平。本课将阐述采用原生预训练的理由，以及实现这一方案所带来的变化。

**类型：** 学习
**语言：** Python（标准库、训练语料混合器）
**前置要求：** Phase 12 · 05, Phase 12 · 07 (recipes)
**时间：** 约 120 分钟

## 学习目标

- 解释为何事后 VLM 训练会积累对齐债务，并引用三个可衡量的症状（灾难性遗忘、答案漂移、图文不一致）。
- 描述 InternVL3 的原生预训练语料混合比例，以及文本 : 交错混合 : 图像说明的比例为何关键。
- 比较 V2PE（可变视觉位置编码）与 Qwen2-VL 的 M-RoPE。
- 说出视觉分辨率路由器（ViR）和解耦视觉-语言（DvD）部署优化。

## 问题所在

事后 VLM 训练是默认做法。LLaVA、BLIP-2、Qwen-VL、Idefics 等均采用已预训练好的 LLM（如 Llama、Vicuna、Qwen、Mistral），并在此基础上添加视觉能力。其典型训练阶段如下：

1. 冻结 LLM + 冻结视觉编码器 + 可训练投影层，在图像-说明对上训练以对齐嵌入表示。
2. 解冻 LLM，在指令数据（LLaVA-Instruct、ShareGPT4V）上进行训练。
3. 可选的任务特定微调。

对齐债务会引发三种典型症状：

- 灾难性遗忘（Catastrophic forgetting）。事后构建的 VLM 会遗忘纯文本技能。GSM8K 分数下降 5-10 分，Hellaswag 分数下降，纯文本智能体性能倒退。
- 答案漂移（Answer drift）。同一视觉问题的微小措辞变化会导致不同的答案。视觉编码器与 LLM 的连接绑定强度弱于 LLM 自身 token 的绑定强度。
- 图文不一致（Visual-text inconsistency）。VLM 能正确描述一张图片，却给出与自身描述相矛盾的答案。视觉 token 无法像文本 token 那样有效参与 LLM 的内部一致性校验。

这些症状已有充分记录。MM1.5 第 4 节对其进行了量化。LLaVA-OneVision 的消融实验也暗示了它们的存在。原生预训练是解决方案。

## 核心概念

### 原生多模态预训练

InternVL3 从零开始在一个从第一步起就是原生多模态的语料库上进行训练。其混合比例为：

- 40% 纯文本数据（FineWeb、Proof-Pile-2 等）
- 35% 交错式图文数据（OBELICS、MMC4 风格）
- 20% 配对图像-说明数据
- 5% 视频-文本数据

视觉 token、文本 token 以及跨模态交互从第一个梯度步起就共同参与同一个损失函数。无需对齐预训练阶段，无需冻结投影层，也无需处理灾难性遗忘的恢复问题。

基础模型的训练为单阶段。指令微调紧随其后，但基础模型已将视觉 token 视为一等公民。

### V2PE（可变视觉位置编码）

Qwen2-VL 使用固定轴分配的 M-RoPE。InternVL3 引入了 V2PE：位置编码随模态类型（文本、图像、视频）变化，并配备可学习的缩放系数。具体而言：

- 文本 token 获得 1D 位置（文本索引）。
- 图像 patch 获得 2D 位置（行、列）。
- 视频帧获得 3D 位置（时间、行、列）。

三者共享相同的 RoPE 频率基底，但每个频带的隐藏维度分配是可学习参数，而非固定划分。这为预训练期间在时间频率与空间频率分辨率之间进行权衡提供了自由度。

V2PE 的消融实验声称：在相同算力下，其在视频基准上的表现比 M-RoPE 高出 1-2 分。虽非革命性突破，但设计更简洁。

### 视觉分辨率路由器（ViR）

部署优化手段。并非所有图像都需要全分辨率编码。一张低细节的单物体照片若以 1280px 原生分辨率编码，会浪费大量 token。ViR 是一个轻量级分类器，可在编码前预测回答当前问题所需的最低分辨率。

路由分为三个层级：低分辨率（256 token）、中分辨率（576）、高分辨率（2048+）。在实际生产流量中，60% 的查询只需低或中分辨率即可满足。净效果：在同等质量下吞吐量提升 2-3 倍。

### 解耦视觉-语言部署（DvD）

在服务大型 VLM 时，视觉编码器对每张图像仅运行一次，而 LLM 则对每个输出 token 自回归运行。两者的瓶颈不同（视觉端受限于卷积+注意力的 GPU 显存带宽；LLM 端受限于 KV Cache）。DvD 将两者拆分至独立 GPU，并通过流式传输进行通信。

对于 8B LLM + 400M 编码器架构，DvD 相比同机部署可将单节点吞吐量大致翻倍。

### 单阶段 vs 多阶段质量

InternVL3 的核心基准主张：在 78B 参数下，匹配 Gemini 2.5 Pro 的 MMMU-Pro 成绩；在 38B 参数下，匹配 GPT-4o；在 8B 参数下，领跑开源 8B 榜单。全部基于单阶段预训练 + 指令微调的流程。

对齐债务假说是可量化的：InternVL3-8B 每获得一单位视觉基准提升所损失的文本基准分数（MMLU、GSM8K），少于 Qwen2.5-VL-7B。由于训练过程是一体化而非割裂的两段，该模型更接近通用型模型。

### InternVL3.5 与 InternVL-U

InternVL3.5（2025年8月）扩展了这一配方。沿用原生预训练思路，增加数据量与参数量。MMMU 的提升属于渐进式改进。

InternVL-U（2026年）增加了统一生成能力——通过在同一骨干网络上叠加 MMDiT 头实现图像输出。“U”代表“理解（Understanding）+ 生成（generation）”，旨在追赶 Transfusion 风格的统一模型（课程 12.13）。同一原生预训练骨干网络可同时支持理解与生成头。

### 原生预训练的权衡

原生预训练并非没有代价：

- 算力。从零训练新 VLM 的成本与训练文本 LLM 相同——需数百万 GPU 小时。事后适配可复用现有 LLM 权重，节省大部分成本。
- 数据。大规模交错式图文语料库极为稀缺。OBELICS 仅含 1.41 亿文档，MMC4 为 5.71 亿。纯文本数据可达 15T token。多模态预训练数据的稀缺性是硬性约束。
- 基础 LLM 复用。原生预训练放弃了后续直接替换新 LLM 的选项。事后方法允许你仅重训适配器即可将 Llama-3.1 替换为 Llama-4。

InternVL3 的赌注是：对齐债务的负面影响大于复用损失。基准测试支持了这一主张。高昂的生产成本将阻止未来实验室廉价复制该方案。事后 VLM 仍将持续存在，因为它们对大多数项目而言依然更便宜。

## 使用它

`code/main.py` 是一个训练语料混合器与 ViR 路由器模拟器。它能：

- 接收目标语料混合比例（%text, %interleaved, %caption, %video）并计算各模态的预期步数。
- 在查询批次上模拟 ViR 路由（分布：50% 低细节、30% 中细节、20% 高细节）并报告平均 token 消耗。
- 根据编码器与 LLM 的 FLOPs 估算 DvD 吞吐量。
- 打印事后方法与原生预训练在参数量、算力、数据和预期对齐债务症状方面的对比表。

## 练习

1. 估算 InternVL3-8B（原生预训练）与 LLaVA-OneVision-7B（事后构建）之间的算力差异。GPU 小时的比率大约是多少？造成差距的原因是什么？
2. InternVL3 报告的比例为 40% 文本 / 35% 交错混合 / 20% 说明 / 5% 视频。如果你的目标任务是视频密集型，请提出新的比例，并论证为何基础模型仍需大量的文本和说明数据。
3. 阅读 MM1.5 第 4 节关于遗忘的内容。指出事后训练表现出最大性能倒退的具体基准。该倒退造成了多少分数损失？
4. ViR 将 60% 的流量路由至低分辨率编码。哪些类型的查询会被错误路由（本应高分辨率却被路由至低分辨率）？提出三种路由器失效模式。
5. DvD 将视觉模块与 LLM 拆分至独立 GPU。在何种流量模式下，DvD 反而会降低吞吐量而非提升？

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|----------|----------|
| 原生多模态预训练 | “从零开始一起训练” | 文本、图像和视频 token 从第一步起就参与损失计算，而非后期外挂 |
| 对齐债务 | “事后惩罚” | 因将视觉模块外挂至冻结 LLM 而导致的文本技能退化与答案一致性下降，且可量化 |
| V2PE | “可变视觉位置编码” | 按模态划分的可学习位置编码分配；InternVL3 对 M-RoPE 的改进版 |
| ViR | “分辨率路由器” | 轻量级分类器，在编码前为每个查询选择所需最低分辨率，从而节省推理 token |
| DvD | “解耦部署” | 视觉编码器与 LLM 分别部署在不同 GPU 上，通过流式传输交接；可使大型 VLM 吞吐量翻倍 |
| InternVL-U | “统一理解与生成” | 2026 年后续版本，在原生的原生预训练骨干网络上增加图像生成头 |
| 交错式语料库 | “OBELICS / MMC4” | 文本与图像按自然阅读顺序排列的文档；原生预训练的基础原料 |
