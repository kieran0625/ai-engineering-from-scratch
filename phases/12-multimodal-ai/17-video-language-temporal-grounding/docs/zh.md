# 视频语言模型：时间令牌与时序定位

> 视频不是照片的堆叠。一个 5 秒的视频片段具有因果顺序、动作动词和事件时序，这是图像模型无法表达的。Video-LLaMA（Zhang 等人，2023 年 6 月）推出了首个具备视听定位能力的开源视频大语言模型。VideoChat 和 Video-LLaVA 进一步扩展了这一模式。到 2025 年，Qwen2.5-VL 的 TMRoPE 缩小了与顶尖闭源模型的差距。每个系统对时间令牌的处理方式各不相同——Video-LLaMA 按片段使用 Q-former，Video-LLaVA 按帧拼接池化，Qwen2.5-VL 按令牌使用 TMRoPE。本课将解析这些模式，构建均匀采样与动态采样的帧采样器，并在时序定位任务上进行评估。

**类型：** 构建
**语言：** Python（标准库，帧采样器 + 时序定位评估器）
**前置知识：** 第 12 阶段 · 08（LLaVA-OneVision）
**预计耗时：** 约 180 分钟

## 学习目标

- 解释为何时序位置编码会独立于视觉编码器影响视频 VLM 的性能。
- 对比均匀采样、动态 FPS 和事件驱动帧采样在“每秒令牌数”与“定位准确率”上的表现。
- 描述 Q-former 按片段（Video-LLaMA）、池化按帧（Video-LLaVA）与 M-RoPE 按令牌（Qwen2.5-VL）的设计差异。
- 列举四个视频基准测试：VideoMME、TempCompass、EgoSchema、Video-MMMU。

## 问题所在

一段 30 FPS 的 1 分钟视频包含 1800 帧。若每帧产生 196 个视觉令牌（ViT-B 在 224x224 分辨率下），总计将达到 35.2 万个令牌——这超过了任何 2024 年代 LLM 的上下文窗口限制。

存在三种降维策略：

1. 对帧进行重采样（根据内容调整为 1-8 FPS）。
2. 激进地对每帧的 patch 令牌进行池化（使用 3x3 或 4x4 双线性池化）。
3. 通过 Q-former 进行压缩，输入 16 帧片段并输出 64 个令牌。

每种方案各有取舍。重采样会损失时间细节。池化会损失空间细节。Q-former 两者都会损失一点，但能大幅节省令牌数量。

时序位置编码是另一个维度：模型如何知道第 5 帧早于第 6 帧？可选方案包括简单的 1D 时序 RoPE（Video-LLaMA）、可学习的时序嵌入（Video-LLaVA）以及 TMRoPE（Qwen2.5-VL，完整的 3D 版本）。

## 核心概念

### Video-LLaMA：按片段使用 Q-former + 音频分支

Video-LLaMA（2023）是首个开源视频大语言模型。其架构如下：

- 以 2 FPS 处理 16 帧片段（即 8 秒时长）。
- 逐帧 ViT 特征 -> 跨所有 16 帧进行交叉注意力的视频 Q-former -> 32 个可学习查询向量 -> LLM。
- 并行音频分支：波形 -> ImageBind 音频编码器 -> 音频 Q-former -> 32 个查询向量 -> LLM。

优势：支持视听联合推理。劣势：固定片段长度，无法支持任意时间点定位。

### VideoChat 与 Video-LLaVA

VideoChat 保留了 Video-LLaMA 的思路，但去除了音频模块并进行了简化。Video-LLaVA（Lin 等人，2023）在图像和视频帧上训练单一视觉编码器（“投影前对齐”），从而获得统一的表征。两者均采用冻结的 CLIP 编码器 + MLP + LLM 结构。

两者均无法处理长视频。它们都是基于 8-16 帧的系统。

### Qwen2.5-VL 与 TMRoPE

Qwen2.5-VL 引入了 TMRoPE（Temporal-Modality Rotary Position Embedding，时序-模态旋转位置编码）。每个 patch 令牌都携带一个 `(t, h, w)` 位置信息，其中 `t` 为实际时间戳（而非帧索引）。

与简单时序嵌入的关键区别在于：

- 绝对时间而非索引。模型看到的是“在第 4.2 秒”，而不是“在第 15 帧”。
- 按令牌旋转而非按片段。每个视觉令牌根据其时间戳独立进行旋转。
- 兼容动态 FPS。如果此处采样率为 2 FPS，彼处为 4 FPS，TMRoPE 能够原生处理这种不均匀的时间间隔。

TMRoPE 使得“猫在第几秒跳起？”这类查询成为可能。模型可以输出“在第 4.2 秒”。而 Video-LLaMA 只能回答“片段早期”。

### 帧采样策略

均匀采样：在时间段内均匀抽取 N 帧。实现简单，但会丢失运动峰值。

动态 FPS：根据运动强度自适应采样。光流法或帧差法可识别高运动片段并进行密集采样。Qwen2.5-VL 即采用此策略进行训练。

事件驱动：运行轻量级检测器，在动作发生处增加采样密度。VideoAgent 使用了该方法。

关键帧+上下文：在镜头切换边界及相邻帧处采样。常用于电影类内容。

### 逐帧池化

若以 1 FPS 采样且每帧 576 个令牌，一个 5 分钟的片段将产生 172,800 个令牌。虽然 Qwen2.5-VL-72B 的 128k 上下文窗口勉强能容纳，但计算成本高昂。

使用 3x3 双线性池化可将每帧降至 64 个令牌 -> 5 分钟仅需 19,200 个令牌。这是大多数任务的最佳平衡点。

对于空间细节要求不高的智能体工作流，可采用更激进的池化策略（6x6 -> 每帧 16 个令牌）。

### 四大视频基准测试

- VideoMME：综合视频理解，涵盖短、中、长视频。
- TempCompass：细粒度时序推理，侧重“之前/之后”类问题。
- EgoSchema：长周期第一人称视角视频。
- Video-MMMU：多模态多学科视频问答。

完整评估视频 VLM 需覆盖全部四项基准。它们侧重的维度不同——TempCompass 专注排序能力，EgoSchema 考验 3 分钟以上的长程推理，VideoMME 则横跨多种时长。

### 定位输出格式

时序定位的输出格式包括：

- 自由文本：“猫在第 4 秒左右跳起。”易于解析但不够精确。
- 结构化 JSON：`{"event": "jump", "start": 4.1, "end": 4.3}`。Qwen2.5-VL 针对此格式进行了训练。
- 基于令牌：在答案中穿插特殊的 `<time>4.1</time>` 令牌。这是 Qwen2.5-VL 的内部格式。

基于令牌的方式对下游应用最为准确。Qwen2.5-VL 的 JSON 输出格式可直接解析。

### 2026 最佳实践

面向 2026 年的视频 VLM 最佳实践：

- 编码器：配合 M-RoPE 或 TMRoPE 的 SigLIP 2（如 Qwen2.5-VL）。
- 帧采样：动态 FPS（根据运动情况在 1-4 之间调整），并设置最大帧数上限。
- 逐帧池化：3x3 双线性池化。
- 输出：包含时间与事件字段的结构化 JSON。
- 基准测试：通用场景使用 VideoMME + TempCompass；长周期场景使用 EgoSchema。

## 核心术语

| 术语 | 常见说法 | 实际含义 |
|------|----------|----------|
| Temporal grounding（时序定位） | “时间局部化答案” | VLM 输出事件发生的具体时间戳范围 |
| TMRoPE | “Time-Multimodal RoPE” | 带有绝对时间戳的 3D 旋转位置编码，由 Qwen2.5-VL 使用 |
| Dynamic FPS | “Motion-aware sampling” | 在高运动片段中采样更多帧，在静态片段中减少采样 |
| Frame pooling | “Spatial compress per frame” | 在送入 LLM 前，使用双线性插值减少每帧的 patch 数量 |
| Video Q-former | “Clip compressor” | 交叉注意力瓶颈层，将 N 帧映射为 K 个可学习查询向量 |
| VideoMME | “Video bench” | 涵盖短/中/长视频的综合性基准测试，包含 2500+ 样本 |
