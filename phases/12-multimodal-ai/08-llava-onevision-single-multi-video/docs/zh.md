# LLaVA-OneVision：单图、多图与视频的统一模型

> 在 LLaVA-OneVision（Li 等人，2024年8月）出现之前，开源 VLM 领域存在不同的技术脉络：LLaVA-1.5 专注于单图，Mantis 和 VILA 等多图模型，以及 Video-LLaVA 和 Video-LLaMA 等视频模型。它们在各自的基准测试中胜出，却在其他任务上表现不佳。LLaVA-OneVision 提出，通过单一的课程训练即可让一个模型在所有三种场景中占据主导，并且涌现的任务迁移效应（将单图技能迁移至视频，将多图推理能力迁移至单图）优于各专精模型的简单叠加。其配方看似简单：跨场景保持恒定的视觉 Token 预算，加上从单图到 OneVision（多图）再到视频的显式课程安排。本课将深入解析该预算分配、课程设计及涌现行为。

**类型：** Build
**语言：** Python（标准库，Token 预算求解器 + 课程规划器）
**前置条件：** Phase 12 · 05 (LLaVA), Phase 12 · 06 (any-resolution)
**预计时间：** ~180 分钟

## 学习目标

- 设计一个在单图、多图和视频输入下保持恒定的视觉 Token 预算。
- 安排训练课程顺序，使技能从单图向视频迁移，同时避免灾难性遗忘。
- 解释为何在正确安排课程的情况下，统一模型在相同参数量下能击败专精模型。
- 列举 LLaVA-OneVision 报告的三项涌现能力：多摄像头推理、Set-of-Mark 提示、iPhone 截图智能体。

## 问题所在

图像、多图和视频对模型的压力各不相同。

单图需要高分辨率 Token（AnyRes，约 2880 个视觉 Token）以捕捉 OCR 和细微细节。每个样本的预算：1 张图，2880 个 Token。

多图需要中等分辨率的多张图片（每张约 576 个 Token），以便在上下文窗口内完成跨图推理。每个样本的预算：4-8 张图，每张 576 个 Token，总计 2300-4600 个 Token。

视频需要低分辨率的大量帧（池化后每帧约 196 个 Token）以捕捉时序动态。每个样本的预算：8-32 帧，每帧 196 个 Token，总计 1600-6200 个 Token。

如果分别训练模型，你只能选择一种预算。如果训练统一模型，你需要预算在不同场景间合理缩放，且不超出上下文限制。

在 OneVision 出现之前，默认方案是“只训练一个场景，忽略其他”。Video-LLaVA 通过额外训练阶段将视频适配到图像模型上。LLaVA-NeXT 通过分块添加了多图支持。它们都未能干净利落地同时处理这三种场景。

## 核心概念

### OneVision Token 预算

LLaVA-OneVision 选定统一的视觉 Token 预算约为每样本 3000-4000 个 Token，并按场景差异化分配：

- 单图：AnyRes-9（3x3 分块 + 缩略图），每个分块分辨率为 384，含 729 个 patch，采用激进的 2x2 双线性池化 → 每个分块 182 个 Token。总计：9 * 182 + 182 = 1820 个 Token。或 AnyRes-4 按每分块 729 计算 = 2916 + 729。
- 多图：每张图使用中等分辨率（384，不分块），729 个 Token 且无池化。预算 6 张图 → 4374 个 Token。
- 视频：32 帧分辨率为 384，采用激进的 3x3 双线性池化 → 每帧 81 个 Token。总计：32 * 81 = 2592 个 Token。

该分配方式保持了总 Token 数的大致恒定。LLM 永远不会遇到超出上下文限制的批次。编码器为不同场景生成不同的几何结构，但 LLM 消费的预算保持一致。

### 三阶段课程训练

LLaVA-OneVision 分三个阶段训练：

1. 单图 SFT（阶段 SI）。所有数据均为单图加文本。在高分辨率 AnyRes 输入上进行训练。这教授感知、OCR 和细粒度理解。使用 LLaVA-NeXT 数据加上 OneVision 特定的单图数据。
2. OneVision SFT（阶段 OV）。混合单图 + 多图 + 视频（均匀采样帧）。在统一的 Token 预算下进行训练。这教会模型处理异构的批次形状。不重置权重——从阶段 SI 继续。
3. 任务迁移（阶段 TT）。继续使用目标任务混合比例进行训练，通常根据产品需求加重多图或视频的比例。可选微调用于部署。

关键：课程顺序至关重要。即使使用相同的数据，先训练视频或多图会导致比先训练单图更差的图像性能。论文对此进行了明确的消融实验。

### 为什么课程训练有效

单图训练构建感知基础。Patch Token 携带细粒度视觉特征；LLM 学习将其与文本整合。多图和视频引入结构性挑战（哪张图是哪张、谁先发生），这些在没有强大感知基础的情况下很难学习。

如果从零开始一起训练所有场景，模型会在感知上欠拟合（批次中单图数据有限），而在结构上过拟合（大量多图/视频数据）。结果是一个遵循跨图推理模式但视觉表征浅薄的模型。

课程顺序让你获得阶段 SI 的感知强度，然后获得阶段 OV 的组合/时序推理能力，且不会丢失任何一方。

### 跨场景涌现技能

LLaVA-OneVision 论文报告了三项涌现能力：

1. 多摄像头推理。分别在多图和视频上训练；在推理时，要求其对多摄像头驾驶场景进行推理。尽管训练中从未见过该确切格式，模型仍能正确整合各个视角。
2. Set-of-Mark 提示。用户在图像上用编号标记标注物体；模型推理“标记 3 相对于标记 7 正在做什么”。既未训练过标记也未训练过标注；从空间定位 + 多图参考的组合中学习得到。
3. iPhone 截图智能体。用户提供 iPhone 屏幕截图并要求规划下一次点击。在 UI 截图、用户工作流视频和多图前后对比对上训练。泛化到智能体用例。

这些并非直接训练的任务；它们源于课程的结构化组合。

### 视觉 Token 池化

Token 预算需要池化。OneVision 在 2D Patch 网格上使用双线性插值：24x24 = 576 个 patches 变为 12x12 = 144（2倍因子）或 8x8 = 64（3倍因子）。池化在 Patch 网格空间而非 Token 空间中进行，以保留局部性。

每个场景的池化因子选择本身就是一个超参数。较少池化 = 更多 Token = 更丰富的表征。较多池化 = 更少 Token = 可容纳更多帧/图片。

### LLaVA-OneVision-1.5

2025 年的后续版本（LLaVA-OneVision-1.5，arXiv:2509.23661）在训练数据、模型权重和代码方面“完全开源”。在某些基准上与专有模型持平，并普及了该训练配方。相同的课程，更多的数据，更好的基础 LLM。架构无变化。

### 与 Qwen2.5-VL 的对比

Qwen2.5-VL（第 12.09 课）做出了不同的选择。它使用 M-RoPE 和动态 FPS，而非固定池化。其预算随输入缩放——1 分钟视频使用的 Token 多于 5 秒视频。LLaVA-OneVision 固定预算并缩放池化。两者均可行；它们用可配置性换取了可预测性。

## 使用方法

`code/main.py` 是一个用于 OneVision 风格 VLM 的课程与预算规划器。给定每个样本的 Token 预算和目标场景混合比例（例如 40% 单图、30% 多图、30% 视频），它会：

- 为每个场景分配分辨率、池化因子和帧数。
- 检查每个场景是否都在共享预算范围内。
- 报告预期的 Token 数量、LLM FLOPs，以及哪些场景 Token 不足。
- 打印分阶段的训练计划表。

可用于规划 OneVision 微调，或对 VLM 部署的单次请求成本进行合理性检查。

## 交付物

本课将产出 `outputs/skill-onevision-budget-planner.md`。给定目标任务分布和每个样本的预算，它将输出 AnyRes 因子、逐帧池化参数、视频帧数和课程阶段权重。每当训练或微调统一场景 VLM 时，均可使用此工具。

## 练习

1. 你的产品支持 80% 单图、10% 多图（2-4 张）、10% 视频（8-16 帧）。请设计 Token 预算。你会将从减少重度多图使用中节省下来的额外预算分配到何处？
2. 阅读 LLaVA-OneVision 第 4.3 节（涌现能力）。提出一项本课程训练可能解锁但论文未报告的第四项涌现技能。
3. 交换课程顺序——先训练多图，再训练单图，最后训练视频。预测哪些基准测试会下降，并说明原因。
4. 论文报告视频基准测试仅使用每样本 8 帧进行训练。这能否泛化到推理时的 30 秒视频？最先崩溃的是什么——Token 预算还是时序推理？
5. 将 24x24 的 patches 通过双线性池化降至 12x12 是每个维度 4 倍的缩减。请使用 Python 标准库实现该池化操作，并验证每个 2x2 区块的平均值是否与双线性输出匹配。

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|----------|----------|
| OneVision scenario | "Single-image, multi-image, or video" | 统一 VLM 处理的三种输入形状之一；预算在此之间保持恒定 |
| Token budget | "How many tokens per sample" | LLM 在每个训练/推理样本中看到的视觉 Token 总数，通常为 3000-4000 |
| Curriculum | "Training order" | 阶段排序（单图 → 多图 → 视频），旨在实现涌现迁移 |
| Bilinear pooling | "Token shrink" | 对 Patch 网格（2D）应用双线性插值以减少 Token 数量，同时保留局部性 |
| Emergent skill | "Not trained, still works" | 推理时出现但未在训练数据中明确匹配的能力，源于课程的结构化组合 |
| AnyRes-k | "k-tile setup" | k 个固定分辨率的子分块加一个缩略图，典型 k ∈ {4, 9} |
| Task transfer | "Cross-scenario generalization" | 在单图上学习到的技能通过共享骨干网络应用于视频（反之亦然） |
