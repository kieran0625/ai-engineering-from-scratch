# MIO 与任意到任意流式多模态模型

> GPT-4o 发布了一个大多数开源模型无法复制的产品：一个能实时听语音、看视频并回应的智能体。截至 2024 年底，开放生态的应对方案是 MIO（Wang 等人，2024 年 9 月）。MIO 对文本、图像、语音和音乐进行分词，在交错序列上训练一个因果 Transformer，并实现任意模态到任意模态的生成。AnyGPT（Zhan 等人，2024 年 2 月）是概念验证；MIO 是规模扩展版；Unified-IO 2（Allen AI，2023 年 12 月）则是带有视觉+动作 grounding 的“表亲”。本课将解析任意到任意模式——四个分词器、一个 Transformer、支持流式解码。

**类型：** 学习
**语言：** Python（标准库、四模态分词分配器 + 流式解码循环）
**前置要求：** 第 12 阶段 · 11（Chameleon），第 6 阶段（语音与音频）
**时间：** 约 120 分钟

## 学习目标

- 设计一个共享词表，容纳文本、图像、语音和音乐 token 且无冲突。
- 对比 SEED-Tokenizer（图像）和 SpeechTokenizer 残差 VQ（语音）在压缩率与重建质量之间的权衡。
- 解释构建任意到任意生成的四阶段课程计划。
- 列举三种开放的任意到任意方案及其主要权衡：MIO、AnyGPT、Unified-IO 2。

## 问题所在

统一的多模态模型宣称起来容易，但大规模构建却很难。直到 2024 年，大多数“任意到任意”系统都是流水线式的：视觉模型 → 文本表示 → 语音模型 → 音频。每一步都会丢失信息、增加延迟并使训练复杂化。GPT-4o 的演示视频展示了一种单模型的替代方案，响应时间在亚秒级；而开源系统落后了数月。

工程挑战包括：

- 每种模态都必须有对应的分词器，压缩程度需足以支持重建，且产生 token 的速率必须匹配 Transformer 的消费能力。
- 单个词表必须为文本（32k+）、图像（16k+）、语音（4k+）、音乐（8k+）分配空间。至少需要四万多个条目。
- 训练数据必须覆盖所有输入-输出组合（文本→图像、图像→语音、语音→图像等），否则模型必须具备组合能力。
- 推理必须足够快地流式输出 token，以满足对话延迟要求（首个音频字节到达时间 <500ms）。

## 核心概念

### 四种模态对应四个分词器

MIO 的分词器栈：

- 文本：标准 BPE，词表大小约 32000。
- 图像：SEED-Tokenizer（2023）——带离散码本的量化 VAE，4096 个条目，每张图像生成 32x32 个 token。
- 语音：SpeechTokenizer 残差 VQ（2023）——将 16kHz 波形编码为 8 个分层码本；第一层为粗略内容，后续层添加韵律和说话人身份特征。
- 音乐：类似的残差 VQ（Meta 的 MusicGen / Encodec 系列），4-8 个码本。

每种模态都生成整数 token。这些 token 在共享词表中被分配到不相交的 ID 范围：

```
text:   0..31999
image:  32000..36095  (4096 image tokens)
speech: 36096..40191  (4096 speech base tokens, plus residual layers)
music:  40192..48383  (8192 music tokens)
sep:    48384..48390  (<image>, <speech>, <music>, </...>, etc.)
```

总计：约 48k 词表。输入嵌入和输出投影均覆盖整个词表。

### 流式解码

语音生成使用残差 VQ。Transformer 预测基础层（第 0 层）的语音 token；并行解码的残差量化器预测后续层。每个第 0 层 token 大约对应 16kHz 采样率下 50ms 的音频。

流式处理流程如下：

1. 用户对着麦克风说话；实时音频分词器每 50ms 输出一次语音 token。
2. MIO 随 token 到达而消费它们（提示预填充 + 增量前向传播）。
3. 输出 token 随生成流式输出；并行语音解码器将其转换为音频样本，延迟约 50-150ms。
4. 首个音频字节到达时间：MIO 论文中约为 300-500ms，接近 GPT-4o 的约 250ms。

Mini-Omni（arXiv:2408.16725）、GLM-4-Voice（arXiv:2412.02612）和 Moshi（arXiv:2410.00037）是互补的流式语音 LLM 设计。其中 Moshi 在单卡 GPU 上实现了 160ms 的往返延迟。

### 四阶段课程计划

MIO 的训练课程计划：

1. 阶段 1 —— 对齐。大规模模态对语料库：文本-图像、文本-语音、文本-音乐。每对模态使用其专属的词表分段。用于训练共享词表。
2. 阶段 2 —— 交错。多模态交错文档（含图片+视频的博文、带转录稿的播客等）。用于训练跨模态上下文。
3. 阶段 3 —— 语音增强。引入额外音频数据以提升语音质量，同时不损失文本能力。
4. 阶段 4 —— SFT。跨模态指令微调：视觉问答、图像描述、旁白、语音到语音对话。

跳过任一阶段都会削弱特定能力：跳过阶段 2 会导致模型丧失跨模态上下文理解；跳过阶段 3 则语音质量较差。

### 视觉思维链

MIO 引入了视觉思维链（chain-of-visual-thought）：模型将中间图像 token 作为推理步骤输出。针对“猫是否在爬树？”这个问题，模型会：

1. 输出一组 `<image>` token 来渲染场景（基于输入图像或草图）。
2. 输出分析该草图的文本。
3. 输出最终答案。

渲染出的中间图像充当草稿纸。基准测试显示其在空间推理任务上表现更好。这一理念与文本推理中的思维链（chain-of-thought）如出一辙。

### 任意到任意领域的竞争者

- AnyGPT（arXiv:2402.12226）：4 种模态（文本、图像、语音、音乐），设计类似。
- Unified-IO 2（arXiv:2312.17172）：增加了视觉动作输出、深度图、法线向量。任务更多样，但规模较小。
- NExT-GPT（arXiv:2309.05519）：LLM + 模态专用扩散解码器。非单模型架构。
- CoDi（arXiv:2305.11846）：可组合扩散；通过共享潜在空间实现任意到任意。

MIO 最接近纯 token 化的任意到任意方案。AnyGPT 是其概念上的先驱。

### 延迟预算

对于对话类产品，每个组件的延迟都至关重要：

- 麦克风到音频 token：约 50ms。
- 预填充（音频 token + 历史上下文）：8B 模型上约 100ms。
- 首个输出 token：约 50ms。
- 并行残差 VQ + 语音解码器：约 100-150ms。

首个音频字节到达总时间：最低约 300ms。GPT-4o 声称约 250ms。Moshi 声称 160ms。根据公开基准测试，MIO/AnyGPT 处于 400-600ms 区间。

### 为何任意到任意依然困难

即使在 2026 年，开源的任意到任意模型在两个维度上仍落后于闭源模型：

- 语音质量。残差 VQ 分词器是有损的；与 ElevenLabs 级别的语音相比，对话语音听起来较为机械。
- 跨模态推理。询问模型“唱出你看到的内容”时，失败率仍高于纯视觉任务。

这些都是未解决的研究课题。Qwen3-Omni（第 12.20 课）是 2025 年最先进的开源尝试。

## 实践应用

`code/main.py`：

- 定义四模态词表分配并打印。
- 将多模态输入列表（文本、图像、音频片段、音乐）路由至分词器路由器。
- 模拟文本转语音响应的流式解码，并统计延迟。
- 根据编码器、预填充和解码器的延迟计算预期的首个音频字节到达时间。

## 练习

1. 你的产品接受语音输入并返回语音输出。端到端延迟预算目标是多少？列出耗时组件。

2. SpeechTokenizer 残差 VQ 使用了 8 个码本。请说明为什么需要对残差层级进行并行解码（而非顺序解码），以及它能带来多少延迟节省。

3. 你的词表包含 32k 文本 + 4k 图像 + 4k 语音。再添加 8k 音乐和约 10 个分隔符。在隐藏层维度为 4096 的情况下，嵌入矩阵的参数成本是多少？

4. 视觉思维链会输出中间图像。哪些问题能从中受益？哪些问题的回答会被额外的 token 拖累？

5. 阅读 Moshi（arXiv:2410.00037）。描述其“内心独白”技术，并与 MIO 的视觉思维链进行比较。

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|-----------------|------------------------|
| 任意到任意 | “多模态输入/输出” | 单一模型，能以任意方向接收并生成文本、图像、语音和音乐 |
| 残差 VQ | “语音分词器栈” | 多码本分词，每层添加新信息；基础层为内容，后续层为韵律 |
| SEED-Tokenizer | “图像编码” | MIO 使用的离散图像分词器，拥有 4096 个条目的码本 |
| 视觉思维链 | “视觉草稿纸” | 模型在给出最终答案前，先生成一张中间图像作为推理步骤 |
| 首个音频字节到达时间 | “TTFAB” | 从用户发声到首次输出音频的延迟；<500ms 以保证对话感 |
| 四阶段课程计划 | “训练配方” | 按顺序执行：对齐 -> 交错 -> 语音增强 -> SFT |
