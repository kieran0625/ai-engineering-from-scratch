# Show-o 与离散扩散统一模型

> Transfusion 混合了连续和离散表示。Show-o（Xie 等人，2024年8月）则反其道而行之：文本 token 使用因果下一个 token 预测，图像 token 采用受 MaskGIT 启发的掩码离散扩散。两者位于同一个 transformer 中，配合混合注意力掩码。其结果在一个骨干网络、每种模态一个 tokenizer、一种损失公式（将下一个 token 预测扩展为掩码预测）上统一了 VQA、文生图、图像修复和跨模态生成。本课程将深入讲解 Show-o 的设计——为什么掩码离散扩散是一种并行、少步数的图像生成器——并与 Transfusion 和 Emu3 进行对比。

**类型：** 学习
**语言：** Python（标准库、掩码离散扩散采样器）
**前置知识：** 第 12 阶段 · 第 13 阶段（Transfusion）
**预计时间：** 约 120 分钟

## 学习目标

- 解释掩码离散扩散：一种均匀掩码 token 然后要求 transformer 恢复它们的调度策略。
- 从速度和质量角度对比并行图像解码（Show-o、MaskGIT）与自回归图像解码（Chameleon、Emu3）。
- 列举 Show-o 在单个检查点中处理的三项任务：文生图（T2I）、视觉问答（VQA）、图像修复。
- 选择一种掩码调度策略（余弦、线性、截断），并推理其对样本质量的影响。

## 问题背景

Transfusion 的双损失训练虽然有效，但动态平衡更为复杂——连续扩散损失与离散 NTP（下一个 token 预测）损失处于不同的数值尺度上。平衡损失权重需要进行超参数搜索。该架构有效但较为复杂。

Show-o 的应对方案：保持两种模态均为离散形式（类似 Chameleon），但通过掩码离散扩散并行生成图像，而非顺序生成。训练目标变为单一的掩码 token 预测，自然地泛化了下一个 token 预测。

## 核心概念

### 掩码离散扩散（MaskGIT）

Chang 等人（2022）提出的原始 MaskGIT 技巧非常优雅。从一个完全掩码的图像开始（每个 token 都是特殊占位符 `<MASK>` ID）。在每一步中，并行预测所有掩码 token，然后保留置信度最高的 Top-K 预测结果，并将剩余的重新掩码。经过约 8-16 次迭代后，所有 token 都会被填充完毕。每步解掩码多少 token 的调度策略经过调优——余弦调度效果很好。

训练过程很简单：从 [0, 1] 中均匀采样一个掩码比例，将其应用于图像的 VQ token，然后训练 transformer 恢复被掩码的部分。这与 BERT 处理文本的方式完全一致，只是扩展到了图像生成领域。

### Show-o：单一 transformer 与混合掩码

Show-o 将 MaskGIT 嵌入到因果语言模型 transformer 中。其注意力掩码配置如下：

- 文本 token：因果掩码（标准 LLM 模式）。
- 图像 token：在图像块内完全双向（以便在预测时，掩码 token 能看到其他所有图像 token）。
- 文生图：文本关注之前的图像，图像关注之前的文本。

训练在以下任务间交替进行：
1. 文本序列的标准 NTP。
2. T2I 样本：文本 → 图像（图像 token 被掩码），采用掩码 token 预测损失。
3. VQA 样本：图像 → 文本（文本 token 被掩码，本质上仍是 NTP）。

统一的损失函数是对 `<MASK>` token 计算的交叉熵，它同时涵盖了文本 NTP（仅最后一个 token 被“掩码”）和图像掩码扩散（随机子集被掩码）。

### 并行采样

Show-o 仅需约 16 步即可生成一张图像，而非自回归方式的约 1000 步（每个 token 一步）或扩散模型的约 20 步。在每一步中，并行预测所有掩码 token；提交置信度最高的 Top-K 结果；然后重复此过程。

对比如下：
- Chameleon / Emu3（基于 token 的自回归）：需要 $N_{\text{tokens}}$ 次前向传播，每张图像通常需要 1024-4096 次。
- Transfusion（连续扩散）：约 20 步，每步均为完整的 transformer 前向传播。
- Show-o（掩码离散扩散）：约 16 步，每步均为完整的 transformer 前向传播。

在同等规模模型下，Show-o 比 Chameleon 更快；其步数大致与 Transfusion 相当，但单步成本更低（离散词表 logits 对比连续 MSE 损失）。

### 单检查点支持的任务

Show-o 在推理时支持四种任务，通过提示词格式进行选择：

- 文本生成：标准自回归文本输出。
- VQA：输入图像，输出文本。
- T2I：输入文本，通过掩码离散扩散输出图像。
- 图像修复：部分 token 被掩码的图像，进行补全。

图像修复能力是掩码预测训练的自然副产品。只需对 VQ token 网格的某个区域进行掩码，输入其余部分及文本提示词，即可预测被掩码的 token。

### 掩码调度策略

每步解掩码多少 token 的调度策略直接影响生成质量。Show-o 推荐使用余弦调度：

```
mask_ratio(t) = cos(pi * t / (2 * T))   # t = 0..T
```

在第 0 步，所有 token 均被掩码（比例为 1.0）。在第 T 步，无 token 被掩码。余弦调度将概率质量集中在中间范围的比例上，此时预测最具信息量。线性调度同样有效，但更容易提前达到平台期。

### Show-o2

Show-o2（2025 年后续工作，arXiv 2506.15564）对 Show-o 进行了扩展：采用更大的 LLM 基座、更优的 tokenizer 以及改进的掩码调度策略。整体架构模式保持一致。

### Show-o 的定位

在 2026 年的技术分类中：

- 离散 token + NTP：Chameleon、Emu3。结构简单但推理较慢。
- 离散 token + 掩码扩散：Show-o、MaskGIT、LlamaGen、Muse。支持并行采样，但仍受限于 tokenizer 的有损压缩。
- 连续表示 + 扩散：Transfusion、MMDiT、DiT。质量最高，但训练更复杂。
- 连续表示 + VLM 中的流匹配：JanusFlow、InternVL-U。最新方案。

按任务选择：若希望在一个开源模型中同时实现 T2I、图像修复和 VQA，且对速度有一定要求，选 Show-o；若质量至上且能接受双损失架构的复杂性，选 Transfusion。

## 练习

1. 掩码离散扩散通常在约 16 步内完成采样。为什么不设为 1 步？如果在第 0 步就解掩码所有内容会发生什么？

2. 掩码扩散天然附带图像修复能力。请提出一个产品用例（真实或假设场景），说明在此场景下 Show-o 的图像修复能力优于专用模型。

3. 余弦调度与线性调度对比：追踪 T=8 时每步解掩码的 token 数量。哪种调度更均衡？

4. 一张 512x512 的 Show-o 图像对应 1024 个 token。当词表大小 K=16384 时，模型输出 1024 * log2(16384) = 14,336 bits（约 1.75 KiB）的数据。Stable Diffusion 输出 512*512*24 bits = 6,291,456 bits（约 768 KiB）的原始像素数据。压缩比是多少？这种压缩换来了怎样的质量？

5. 阅读 LlamaGen（arXiv:2406.06525）。LlamaGen 的类别条件自回归图像模型与 Show-o 的掩码方法有何不同？

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|----------|----------|
| 掩码离散扩散 | “MaskGIT 风格” | 训练时预测被掩码的 token；推理时迭代性地解掩码置信度最高的预测结果 |
| 余弦调度 | “解掩码调度” | 推理过程中掩码比例的衰减曲线；将置信度增长集中在中间比例区间 |
| 并行解码 | “一次性所有 token” | 每一步在一次前向传播中预测完整的掩码 token 序列，随后提交 Top-K 结果 |
| 混合注意力 | “因果 + 双向” | 对文本 token 采用因果掩码，在图像块内部采用双向掩码 |
| 图像修复 | “补全生成” | 以部分 token 被掩码的图像为条件，预测缺失部分；由训练目标自然衍生 |
| 提交率 | “每步 Top-K” | 每次迭代中声明为“已完成”的 token 数量；控制推理速度与质量的权衡 |
