# 文档与图表理解

> 文档不是照片。PDF、科学论文、发票或手写表单具有版式、表格、图表、脚注、页眉以及纯图像理解无法捕捉的语义结构。在视觉语言模型（VLM）之前的技术栈是一个流水线：Tesseract OCR + LayoutLMv3 + 表格提取启发式规则。VLM 浪潮用无 OCR 模型取代了它——Donut（2022）、Nougat（2023）、DocLLM（2023）——它们直接输出结构化标记。到 2026 年，前沿方案仅仅是“以 2576px 原生分辨率将页面图像输入给 Claude Opus 4.7”，而结构化标记输出是免费附赠的。本课程梳理文档 AI 的三个时代演进。

**类型：** 构建
**语言：** Python（标准库、布局感知文档解析器骨架）
**前置要求：** 第 12 阶段 · 05（LLaVA），第 5 阶段（NLP）
**耗时：** 约 180 分钟

## 学习目标

- 阐述文档 AI 的三个时代：OCR 流水线、无 OCR、VLM 原生。
- 描述 LayoutLMv3 的三大输入流：文本、布局（边界框 bbox）、图像块，以及统一的掩码机制。
- 对比 Donut（无 OCR，图像 → 标记）、Nougat（科学论文 → LaTeX）、DocLLM（布局感知生成式）、PaliGemma 2（VLM 原生）。
- 为新任务（发票、科学论文、手写表单、中文收据）选择合适的文档模型。

## 问题所在

“理解这份 PDF”看似简单实则困难重重。信息分布在以下方面：

- 文本内容（占 90% 的信号）。
- 版式（页眉、脚注、侧边栏、双栏排版）。
- 表格（行、列、合并单元格）。
- 插图与图表。
- 手写批注。
- 字体与排版（标题与正文的区别）。

原始 OCR 仅转储文本并丢失其余信息。一个关注发票的系统需要知道“总计：$1,245”来自右下角，而不是脚注。

## 核心概念

### 时代一 —— OCR 流水线（2021 年前）

经典技术栈：

1. PDF → 逐页转为图像。
2. Tesseract（或商业 OCR）提取带词级边界框的文本。
3. 布局分析器识别区块（页眉、表格、段落）。
4. 表格结构识别器解析表格。
5. 领域规则 + 正则表达式提取字段。

适用于清晰的印刷文本。遇到手写体、倾斜扫描、复杂表格或非英文字符时就会失效。每种失败模式都需要定制化的异常处理路径。

### TrOCR（2021）

TrOCR（Li 等，arXiv:2109.10282）用基于合成+真实文本图像训练的 Transformer 编码器-解码器，取代了 Tesseract 经典的 CNN-CTC。在手写体和多语文本上取得了压倒性优势。它仍然是流水线架构（检测器 → TrOCR → 布局分析），但 OCR 步骤的性能大幅提升。

### 时代二 —— 无 OCR（2022-2023）

首批无 OCR 模型的理念是：完全跳过检测步骤，直接将图像像素映射为结构化输出。

Donut（Kim 等，arXiv:2111.15664）：
- 编码器-解码器 Transformer，编码器采用 Swin-B。
- 输出格式根据任务而定：表单理解输出 JSON，摘要输出 Markdown，或其他特定任务的 Schema。
- 无需 OCR、无需布局分析、无需目标检测。

Nougat（Blecher 等，arXiv:2308.13418）：
- 专门针对科学论文进行训练。
- 输出为 LaTeX / Markdown。
- 能够处理公式、多栏排版和插图。
- 它是所有 arXiv 解析器都会调用的模型。

它们是专家型模型，而非通用型模型。Donut 处理科学论文会失败；Nougat 处理发票也会失败。

### LayoutLMv3（2022）

另一条技术路线。LayoutLMv3（Huang 等，arXiv:2204.08387）保留了 OCR，但增加了布局理解能力：

- 三大输入流：OCR 文本 Token、每个 Token 的 2D 边界框、图像块。
- 跨三大模态的掩码训练目标（掩码文本、掩码图像块、掩码布局）。
- 下游任务：分类、实体抽取、表格问答。

LayoutLMv3 是基于 OCR 的文档理解的巅峰之作。在表单和发票上表现强劲。依赖上游 OCR。在标准化文档基准测试中拥有 VLM 出现前的最佳准确率。

### DocLLM（2023）

DocLLM（Wang 等，arXiv:2401.00908）是 LayoutLM 的生成式兄弟模型。基于布局 Token 条件生成自由形式的答案。更适合文档问答；但仍依赖 OCR 输入。

### 时代三 —— VLM 原生（2024 年起）

2024 年的 VLM 已经足够强大，可以完全替代传统流水线。将高分辨率的完整页面图像输入 VLM，提出问题，即可得到答案。

- LLaVA-NeXT 336-tile AnyRes 适用于小型文档。
- Qwen2.5-VL 动态分辨率原生支持 2048+ 像素。
- Claude Opus 4.7 支持 2576px 文档。
- PaliGemma 2（2025 年 4 月）专门针对文档+手写体进行训练。

VLM 原生与传统 OCR 流水线的差距迅速缩小。到 2026 年，VLM 原生方案在以下场景胜出：

- 场景文本（手写+印刷，混合字符集）。
- 包含合并单元格的复杂表格。
- 嵌入文本中的数学公式。
- 带有文字标注的插图。

OCR 流水线仍在以下场景保持优势：

- 大规模纯扫描工作负载，且对单页延迟敏感的场景。
- 流水线可靠性（确定性失败 vs VLM 幻觉）。
- 需要可审计 OCR 输出的受监管环境。

### Claude 4.7 / GPT-5 的前沿水平

在 2576 像素原生输入下，前沿 VLM 能够实现接近人类水平的文档理解准确率。2026 年初的基准测试数据如下：

- DocVQA：Claude 4.7 ~95.1，PaliGemma 2 ~88.4，Nougat ~77.3，流水线版 LayoutLMv3 ~83。
- ChartQA：Claude 4.7 ~92.2，GPT-4V ~78。
- VisualMRC：Claude 4.7 ~94。

闭源模型的差距主要在于分辨率和基础 LLM 规模。7B 参数的开源模型落后几个百分点，但正在快速追赶。

### 数学公式与 LaTeX 输出

科学论文需要对公式进行精确的 LaTeX 输出。Nougat 正是为此训练而成。使用 LaTeX 目标训练的 VLM（如 Qwen2.5-VL-Math、Nougat 衍生模型）能生成可用的 LaTeX。如果没有显式的 LaTeX 训练，VLM 生成的转录文本可读但不够精确。

2026 年的科学论文处理流水线建议：先用 Nougat 处理整个 PDF，再用 VLM 处理疑难页面。

### 手写体识别

这仍然是最困难的子任务。混合印刷+手写体（医生笔记、填写的表单）场景中，OCR 流水线在成本上仍优于 VLM。纯手写体 VLM 正在不断进步（如 Claude 4.7、PaliGemma 2）。

### 2026 年实践指南

针对新的文档 AI 项目：

- 大规模纯印刷发票：LayoutLMv3 + 规则引擎，成本效益高。
- 混合文档（科学论文+手写体+表单）：VLM 原生方案（PaliGemma 2 或 Qwen2.5-VL）。
- 完整 arXiv 数据摄入：Nougat 处理数学公式，VLM 处理插图。
- 合规场景：OCR 流水线为主 + VLM 校验器进行交叉验证。

## 练习

1. 你的项目每天处理 1000 万张发票。哪种技术栈能在不损失准确率的前提下最小化单页成本？

2. 为什么 LayoutLMv3 在表单问答上优于纯 CLIP-VLM，但在场景文本上表现不佳？bbox 流让渡了什么？

3. Nougat 生成 LaTeX。请提出一个测试用例，说明 VLM 原生输出在 LaTeX 保真度上胜过 Nougat 的情况，以及 Nougat 胜出的情况。

4. 阅读 PaliGemma 2 论文（Google，2024）。相比 PaliGemma 1，哪项关键训练数据的加入提升了文档准确率？

5. 设计一个符合合规要求的混合架构：以 OCR 流水线为主，VLM 为辅进行交叉验证。如何解决两者的分歧？

## 核心术语

| 术语 | 常见说法 | 实际含义 |
|------|-----------------|------------------------|
| OCR pipeline | "Tesseract 风格" | 分阶段技术栈：检测 → OCR → 布局 → 规则；确定性强，但脆弱 |
| OCR-free | "Donut 风格" | 跳过显式 OCR 的图像到输出 Transformer；单一模型 |
| Layout-aware | "LayoutLM 风格" | 输入包含每个 Token 的 bbox 坐标；跨模态统一掩码 |
| VLM-native | "前沿 VLM" | 将页面图像直接以高分辨率输入 Claude/GPT/Qwen VLM；无需流水线 |
| DocVQA | "文档基准" | 文档视觉问答标准；引用率最高的评分指标 |
| Markup output | "LaTeX / MD" | 结构化输出格式而非自由文本；支持下游自动化 |
