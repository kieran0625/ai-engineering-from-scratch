# 多模态智能体与计算机使用（综合项目）

> 2026 年的前沿产品是一个多模态智能体，能够读取截图、点击按钮、导航网页 UI、填写表单并端到端完成工作流。SeeClick 和 CogAgent（2024）证明了 GUI 定位这一基础原语的有效性。Ferret-UI 将其扩展至移动端。ChartAgent 引入了用于图表分析的视觉工具调用。VisualWebArena 和 AgentVista（2026）是前沿模型追逐的基准测试——甚至 Gemini 3 Pro 和 Claude Opus 4.7 在 AgentVista 的高难度任务上也仅得分约 30%。本综合项目将第 12 阶段的所有线索整合在一起：感知（高分辨率 VLM）、推理（带工具调用的 LLM）、定位（坐标输出）、长程记忆以及评估。

**类型：** 综合项目 (Capstone)
**语言：** Python（标准库、动作模式 + 智能体循环骨架）
**前置要求：** 第 12 阶段 · 05 (LLaVA)，第 12 阶段 · 09 (Qwen-VL JSON)，第 14 阶段 (智能体工程)
**耗时：** 约 240 分钟

## 学习目标

- 设计多模态智能体循环：感知 → 推理 → 执行 → 观察 → 重复。
- 构建 GUI 定位输出模式（点击坐标、输入文本、滚动、拖拽），使 VLM 能以 JSON 格式输出。
- 比较纯截图智能体、无障碍树（accessibility-tree）智能体与混合智能体。
- 在小型 VisualWebArena 切片上搭建多模态智能体基准评估环境。

## 问题描述

一个订票网站工作流：“帮我找一张 4 月 15 日飞往东京的机票，靠过道座位，价格低于 800 美元，并完成预订。”

多模态智能体需要：

1. 截取浏览器屏幕画面。
2. 将截图、URL 和目标指令解析为计划。
3. 输出结构化动作：点击（在 x,y 处）、输入“Tokyo”（在元素 E 处）、向下滚动、选择（单选按钮）。
4. 将动作应用到浏览器中。
5. 观察新状态（下一张截图）。
6. 重复直到任务完成。

每一步都是一次多模态 VLM 调用。VLM 的输出必须是可解析的 JSON。错误会在步骤间累积，因此恢复机制至关重要。

## 核心概念

### GUI 定位 —— 基础原语

GUI 定位是指：给定一张截图和一条自然语言指令，输出需要点击的 (x, y) 坐标（或其他动作）。

SeeClick (arXiv:2401.10935) 是首个大规模开源成果：在合成数据与真实 GUI 数据上微调 VLM，以纯文本 token 形式输出坐标。效果显著。

CogAgent (arXiv:2312.08914) 增加了 1120x1120 的高分辨率编码以应对密集 UI。得分：网页导航任务约 84%。

Ferret-UI (arXiv:2404.05719) 专注于移动端 UI，并与 iOS 无障碍数据集成。

输出格式通常为 JSON：

```json
{"action": "click", "x": 384, "y": 220, "element_desc": "Search button"}
```

`element_desc` 有助于错误恢复：如果截图之间的坐标发生漂移，语义提示能让系统重新进行定位。

### 动作模式 (Action Schemas)

典型的动作模式包含 6-10 种动作类型：

- `click`: (x, y)
- `type`: (text, x?, y?)
- `scroll`: (direction, amount)
- `drag`: (x0, y0, x1, y1)
- `select`: (option_index)
- `hover`: (x, y)
- `navigate`: (url)
- `wait`: (ms)
- `done`: (success, explanation)

智能体每步只输出一个动作。浏览器包装器执行该动作并返回新状态。

### 纯截图 vs 无障碍树

两种输入模式：

- 纯截图：完整图像，无结构信息。通用性最强；适用于任何应用。
- 无障碍树：结构化的 DOM / iOS 无障碍信息。定位更可靠；仅在可用树结构时生效。
- 混合模式：两者结合，以树作为原子动作的可靠定位器，以截图提供语义上下文。

生产环境的智能体在条件允许时会采用混合模式。浏览器自动化（Selenium + 无障碍接口）始终拥有树结构；桌面应用则视情况而定。

### 长程记忆 (Long-horizon Memory)

一个 20 步的工作流会生成 20 张截图。VLM 的上下文很快就会被填满。三种压缩策略：

- 摘要链（Summary-chain）：每 5 步后总结已发生的情况，丢弃旧截图。
- 跳帧（Skip-frame）：保留第一张、最后一张以及每隔 3 张的截图。
- 工具记录日志（Tool-recorded log）：执行动作，保留已完成操作的文本日志；不再回顾旧截图。

Claude 的 computer-use API 采用日志模式。更简单、更可靠。

### 视觉工具调用 (Visual Tool Use)

ChartAgent (arXiv:2510.04514) 引入了用于图表理解的视觉工具调用：裁剪、缩放、OCR、调用外部检测工具。智能体可以输出“裁剪到区域 (100, 200, 300, 400) 然后调用 OCR”作为工具调用。工具返回文本后，VLM 继续推理。

该模式具有普适性：标记集提示（set-of-mark prompting）、区域标注和外部检测工具都符合相同的“输出工具调用，接收结构化响应”模式。

### 2026 年基准测试

- ScreenSpot-Pro。针对约 1k 网页截图的 GUI 定位。开源 SOTA Qwen2.5-VL-72B 约 85%。前沿模型约 90%。
- VisualWebArena。端到端网页任务（购物、论坛、分类广告）。开源 SOTA 约 20%。Gemini 3 Pro 约 27%。
- AgentVista (arXiv:2602.23166)。2026 年最难的基准测试。涵盖 12 个领域的真实工作流。前沿模型得分 27-40%；开源模型 10-20%。
- WebArena / WebShop。较旧的基准测试；已被前沿模型饱和。

### 为什么仍然困难

智能体性能瓶颈：

1. 细粒度视觉定位。“点击那个小 X”在移动端分辨率下经常失败。
2. 长程规划。经过 10 个动作后，智能体会偏离目标。
3. 错误恢复。当点击失败（点错按钮）时，检测并恢复通常缺乏训练数据。
4. 跨页面上下文。在标签页之间跳转或处理长表单会导致状态丢失。

研究方向：记忆架构、显式重规划、多模态验证（通过截图匹配来确认动作是否成功）。

### 综合项目构建指南

综合项目任务：构建一个计算机使用智能体，要求：

1. 读取订票网站模拟页面的 HTML 和截图。
2. 规划多步序列：搜索 → 选择 → 填写表单 → 提交。
3. 输出符合动作模式的 JSON 动作。
4. 在固定的 10 任务切片上进行评估。

课程提供的脚手架代码易于扩展至真实浏览器环境。

## 使用方式

`code/main.py` 是综合项目的脚手架：

- 动作模式 JSON 定义（10 种动作）。
- 作为字典的模拟浏览器状态。
- 智能体循环骨架：接收状态、输出动作、应用动作、循环。
- 10 任务迷你基准测试（合成页面）用于测量端到端成功率。
- 动作失败时的错误恢复钩子（hook）。

## 练习

1. 使用 `screenshot_region` 工具（裁剪 + 缩放）扩展动作模式。哪些任务会从中受益？

2. 阅读 AgentVista (arXiv:2602.23166)。描述最难的任务类别，并说明为何前沿模型仍然会失败。

3. 长程记忆压缩：设计一个摘要链，要求实时保留 ≤4 张截图，其余全部记录到日志中。

4. 构建错误恢复钩子：当动作失败（未找到按钮）时，智能体的下一步操作是什么？

5. 对比纯截图的 Claude 4.7 与混合截图+无障碍树的 Qwen2.5-VL 在 10 个网页任务上的表现。各自在哪些任务上胜出？

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|------------------------|--------------------------|
| GUI grounding | “点击坐标” | 模型针对截图中的指令输出目标 (x,y) 坐标 |
| Action schema | “工具定义” | 有效动作（点击、输入、滚动、拖拽）的 JSON 描述 |
| Accessibility tree | “结构化 DOM” | 来自浏览器/iOS API 的可机器读取的 UI 层级结构 |
| Hybrid agent | “截图 + 树” | 同时使用图像和结构化信息；比单一模式更可靠 |
| Visual tool use | “缩放/裁剪/检测” | 智能体在规划中途调用外部视觉工具（OCR、检测等） |
| Summary-chain | “记忆压缩” | 定期文本摘要替代冗长的截图历史 |
| VisualWebArena | “E2E 网页基准” | 面向端到端网页任务的 2024 年基准测试 |
| AgentVista | “2026 高难基准” | 12 个领域的真实工作流；即使 Gemini 3 Pro 得分也仅约 30% |
