# Qwen-VL 家族与动态帧率视频

> Qwen-VL 家族（Qwen-VL、Qwen2-VL、Qwen2.5-VL、Qwen3-VL）是 2026 年最具影响力的开源视觉-语言模型谱系。每一代都押注了一个决定性的架构特性，并在十二个月内被整个开源生态跟进：通过 M-RoPE 实现原生动态分辨率、带绝对时间对齐的动态帧率采样、ViT 中的窗口注意力机制，以及结构化的智能体输出格式。到 Qwen3-VL 时，技术路线已趋于稳定：采用支持原生宽高比的 2D-RoPE-ViT 编码器、将特征投影到大规模 Qwen3 语言基座的 MLP 投影层，以及在训练阶段将 OCR、空间定位（grounding）和智能体行为作为首要目标进行优化。本课程按时间顺序梳理该家族的发展脉络，帮助你理解每一项配置项为何如此设定。

**类型：** 学习
**语言：** Python（标准库、M-RoPE 编码器 + 动态帧率采样器）
**前置要求：** 第 12 阶段 · 06（patch-n'-pack）
**耗时：** 约 120 分钟

## 学习目标

- 计算 M-RoPE 的三个轴旋转（时间、高度、宽度），并解释为何三者缺一不可。
- 为视频选择动态帧率采样策略，并权衡每秒 token 数与事件检测准确率之间的关系。
- 按顺序列出 Qwen-VL 的四代升级及其各自带来的能力突破。
- 实现类 Qwen2.5-VL 的 JSON 智能体输出格式，并从 VLM 响应中解析结构化工具调用指令。

## 问题背景

Qwen-VL 于 2023 年 8 月发布，直接回应了 LLaVA-1.5 和 BLIP-2。Qwen 团队瞄准的差距主要体现在三个方面：分辨率、视频处理和结构化输出。

分辨率：LLaVA-1.5 运行在 336x336 分辨率下。处理普通照片尚可，但面对中文发票或密集的表格截图则毫无用处。Qwen-VL 的首个创新点在于支持 448x448 分辨率及带空间定位（grounding）的边界框输出，使模型能够“指认”具体位置。

视频：Video-LLaMA 堆叠逐帧编码器并将其输入 LLM。该方法适用于短视频片段，但在多分钟级视频中效果不佳，因为时间轴才是关键信号。Qwen 团队希望拥有一个能理解时间维度的单一编码器。

结构化输出：LLaVA 生成自由文本。而智能体需要 JSON。Qwen-VL 针对明确的 JSON 输出格式进行训练，包括将边界框坐标作为文本输出。

Qwen-VL 的每一代都在这三个维度之一上进行了扩展。

## 核心概念

### Qwen-VL（2023 年 8 月）

第一代：使用 OpenCLIP ViT-bigG/14 作为编码器（25 亿参数），兼容 LLaMA 的 Q-Former（单步 256 个查询），基座为 Qwen-7B。核心贡献：

- 448x448 分辨率（当时开源 VLM 的 SOTA）。
- 空间定位（Grounding）：在带有显式坐标 token 输出的图文对上进行训练。例如：“猫位于 <box>(112, 204), (280, 344)</box>”。
- 从一开始就支持中英双语多语言训练。

当时的基准测试表现：英文能力与 GPT-4V 相当，中文领域占据主导。真正的亮点在于其定位监督学习。

### Qwen2-VL（2024 年 9 月）—— M-RoPE 与原生分辨率

Qwen2-VL 用原生动态分辨率 ViT 编码器取代了固定分辨率 + Q-Former 的堆叠架构。关键变更：

- 原生动态分辨率。ViT 接受任意能被 28 整除的 HxW 尺寸（14x14 patch 配合 2x 空间合并）。一张 1120x672 的图片（40x24 合并后的 patch）会生成 960 个视觉 token。无需缩放、分块或缩略图。
- M-RoPE（多模态 RoPE）。每个 token 携带三维位置 (t, h, w) 而非一维。图像中 t=0，视频中 t = 帧索引。RoPE 按轴频率旋转 query/key 向量。无需位置嵌入表。
- MLP 投影层。弃用 Q-Former；直接在合并后的 patch token 上使用两层 MLP。
- 支持动态帧率的视频。默认以 1-2 FPS 采样，但模型可接受任意帧数。

结果：Qwen2-VL-7B 在多项多模态基准上与 GPT-4o 持平，并在 DocVQA 上超越它（94.5 vs 88.4）。架构变革是决定性的一步。

### Qwen2.5-VL（2025 年 2 月）—— 动态帧率 + 绝对时间

Qwen2.5-VL 的重大转变在于视频处理。动态帧率并非简单的“按需增加采样帧数”。论文将其形式化如下：

- 绝对时间 token。不再使用位置索引（第 0、1、2 帧...），而是使用实际时间戳。“在 0:04 时，猫跳了起来。”模型会看到 `<time>0.04</time>` token 与帧 token 交错排列。
- 动态 FPS。慢速画面采样 1 FPS，动作场景采样 4+ FPS。由用户或训练者决定；M-RoPE 会自动适配。
- ViT 中的窗口注意力。为提升吞吐量，空间注意力采用窗口机制（块内局部）；每隔几层使用全局注意力。
- 显式 JSON 输出格式。基于工具调用数据进行训练：`{"tool": "click", "coords": [380, 220]}`。开箱即用的智能体就绪模式。
- MRoPE-v2 缩放机制。位置编码随最大输入尺寸缩放，确保 10 分钟长的视频不会超出频率范围。

基准测试：Qwen2.5-VL-72B 在大多数视频基准上击败 GPT-4o，在文档任务上与 Gemini 2.0 持平，并创下 GUI 定位的开源模型 SOTA（ScreenSpot：准确率达 84%，而 GPT-4o 仅为 38%）。

### Qwen3-VL（2025 年 11 月）

Qwen3-VL 是一次巩固型增量升级，而非推倒重来：更大的 LLM 骨干网络（Qwen3-72B）、扩充的训练数据、优化的 OCR 能力，以及通过 Qwen3 “思考模式”增强的推理能力。ViT 和 M-RoPE 保持不变。论文重点在于数据和训练方法的改进，而非架构革新。

发展脉络总结：到 2025 年，Qwen-VL 的架构已趋于稳定。后续世代主要扩展算力和数据规模，而非基础组件。

### M-RoPE 数学原理

经典 RoPE 使用配对坐标，对维度为 `d` 的查询 `q` 在位置 `m` 处进行旋转：

```
q_rot[2i]   = q[2i]   * cos(m * theta_i) - q[2i+1] * sin(m * theta_i)
q_rot[2i+1] = q[2i]   * sin(m * theta_i) + q[2i+1] * cos(m * theta_i)
theta_i     = 10000^(-2i/d)
```

M-RoPE 将隐藏层维度划分为三个频带。假设总维度为 `d = 96`。分配 32 维给时间轴，32 维给高度轴，32 维给宽度轴。每个频带按其自身的轴位置进行旋转。位于 (t=5, h=10, w=20) 的 patch 会在其三个频带上分别应用旋转 `R_t(5)`、`R_h(10)`、`R_w(20)`。

文本 token 使用 `t = text_index, h = 0, w = 0`（或归一化选项）以保持兼容性。视频帧使用 `t = frame_time, h = row, w = col`。单张图像使用 `t = 0`。

优势：单一的位置编码即可同时处理文本、图像和视频，无需分支代码或维护不同的位置表。

### 动态帧率采样逻辑

给定一段时长为 `T` 秒的视频，以及目标 token 预算 `B`：

1. 计算你能承受的最大 FPS：`fps_max = B / (T * tokens_per_frame)`。
2. 从 `{1, 2, 4, 8}` 中选择一个满足 `fps <= fps_max` 的目标 FPS。
3. 若运动剧烈（基于光流启发式判断或用户明确要求），选择较高 FPS；若运动平缓，选择较低 FPS。
4. 按选定 FPS 均匀采样；在帧之间插入 `<time>t</time>` token。

Qwen2.5-VL 隐式训练了这一逻辑；在推理阶段，用户可通过 `fps` 参数进行控制。一段 60 秒的动作序列以 4 FPS 采样，每帧 81 个 token，总计 19440 个 token，可在 32k 上下文窗口内容纳。

### 结构化智能体输出

Qwen2.5-VL 的智能体训练明确针对结构化工具调用：

```
{
  "tool": "mouse_click",
  "coords": [1024, 512],
  "button": "left",
  "modifier": null
}
```

解析过程是确定性的：直接对模型输出执行 `JSON.parse`。相比之下，自由文本格式的“点击 (1024, 512)”需要依赖正则表达式和歧义处理。正是这一转变使得 Qwen2.5-VL 的 ScreenSpot 得分从 Qwen2-VL 的 55% 跃升至 84%。

## 动手实践

`code/main.py` 实现了以下功能：

- 混合文本、图像 patch 和视频帧的打包序列的 M-RoPE 位置计算。
- 动态帧率采样器：给定（时长、预算、运动强度），选择 FPS 并输出帧时间戳。
- 一个玩具级的 Qwen2.5-VL JSON 输出解析器，用于处理包含坐标字段的工具调用响应。

运行该代码，然后在 5 分钟长的视频上将固定帧率切换为动态帧率，亲身体验其中的差异。

## 核心术语

| 术语 | 常见说法 | 实际含义 |
|------|----------|----------|
| M-RoPE | “多模态 RoPE” | 隐藏层维度中包含时间、高度和宽度频带的三维旋转位置编码 |
| Dynamic FPS | “智能采样” | 根据运动强度、视频时长和 token 预算为每个视频选择的帧采样率 |
| Absolute time token | “时间戳 token” | `<time>t</time>` 交错插入序列中，使模型感知实际秒数而非帧索引 |
| Window attention | “局部注意力” | 为提升速度将空间自注意力限制在小窗口内；周期性添加全局注意力 |
| Structured agent output | “JSON 模式” | 通过训练数据监督，教导 VLM 输出包含坐标和工具名称的可解析 JSON |
| min_pixels / max_pixels | “分辨率边界” | 每次请求的 Qwen2.5-VL 配置，用于控制总像素数量上限，从而限制 token 数量 |
| Grounding | “指认定位” | 将边界框坐标作为文本 token 输出；自 Qwen-VL v1 起沿用 |
