# 从 CLIP 到 BLIP-2 —— Q-Former 作为模态桥梁

> CLIP 能够对齐图像和文本，但无法生成描述、回答问题或进行对话。BLIP-2（Salesforce，2023）通过一个小型可训练的桥梁解决了这一问题：32 个可学习的查询向量（query vectors）通过交叉注意力机制关注冻结的 ViT 特征，随后直接嵌入到冻结的 LLM 输入流中。该桥梁仅含 1.88 亿参数，便将一个 110 亿参数的 LLM 与 ViT-g/14 连接起来。截至 2026 年，所有基于 Adapter 的 VLM——MiniGPT-4、InstructBLIP 以及 LLaVA 的衍生模型——皆是其后裔。本课将解析 Q-Former 的架构，阐述其两阶段训练过程，并构建一个玩具版本，用于将视觉 token 输入到冻结的文本解码器中。

**类型：** Build
**语言：** Python（标准库，交叉注意力 + 可学习查询演示）
**前置要求：** Phase 12 · 02 (CLIP), Phase 7 (Transformers)
**耗时：** ~180 分钟

## 学习目标

- 解释为何在冻结的视觉编码器与冻结的 LLM 之间使用可训练的瓶颈结构，在成本和稳定性上优于端到端微调。
- 实现一个交叉注意力模块，其中一组固定的可学习查询向量关注外部图像特征。
- 梳理 BLIP-2 的两阶段预训练流程：表示学习（ITC + ITM + ITG）随后是生成式学习（使用冻结解码器的 LM loss）。
- 对比 Q-Former 与 LLaVA 中使用的更简单的 MLP 投影器，并论证各自适用的优势场景。

## 问题背景

你有一个冻结的 ViT，每张图像输出 256 个 patch token，维度为 1408。你还有一个冻结的 7B LLM，它期望接收维度为 4096 的 token embedding。最直接的桥梁——一个从 1408 到 4096 的线性层——确实可行，但将所有 256 个 patch token 输入 LLM 的上下文窗口，意味着每张图像会额外消耗 256 个 token。在一个包含 32 张图像的 batch 中，仅视觉模态就会消耗 8192 个 token。

BLIP-2 的核心疑问是：能否将 256 个 token 的图像表示压缩为数量少得多的 token（例如 32 个），同时保留足够的信息供 LLM 进行图像描述、问答和推理？此外，能否在不触碰冻结骨干网络的前提下训练此桥梁，使训练成本仅限于桥梁本身的参数？

答案是：Q-Former。它包含 32 个可学习的“query”向量，这些向量通过交叉注意力机制关注 ViT 的 patch token，生成一个 32 个 token 的视觉摘要供 LLM 消费。总计 1.88 亿参数。在接触 LLM 之前，先通过对比、匹配和生成目标对其进行训练。

## 核心概念

### 可学习查询向量

Q-Former 的核心技巧：不让 LLM 的文本 token 去关注图像 patch，而是引入一组全新的 32 个可学习查询向量 `Q`，让*它们*去关注图像 patch。这些查询向量是模型的参数——它们在训练过程中被学习，且同一组 32 个查询向量会用于处理每一张图像。

经过交叉注意力计算后，每个查询向量都持有一张图像的压缩摘要——例如“描述主要物体”、“描述背景”、“统计物体数量”等。这些查询向量并不会字面意义上地专门对应某个语义标签；它们会学习任何能使下游损失下降的编码方式。

### 架构设计

Q-Former 是一个小型 Transformer（12 层，约 1 亿参数），包含两条路径：

1. 查询路径：32 个查询向量首先流经自注意力机制（仅在自身内部交互），然后对冻结的 ViT patch token 执行交叉注意力，最后经过 FFN。
2. 文本路径：类 BERT 的文本编码器与查询路径共享自注意力和 FFN 权重。文本路径不启用交叉注意力。

训练时两条路径同时运行。查询向量和文本通过共享的自注意力机制交互，这意味着查询向量可以针对需要文本条件的任务（如 ITM、ITG）进行条件化。在 VLM 交接阶段的推理时，仅有查询向量流经网络，最终输出 32 个视觉 token。

### 两阶段训练

BLIP-2 的预训练分为两个阶段：

阶段 1：表示学习（不涉及 LLM）。包含三个损失函数：
- ITC（图文对比）：在池化后的查询 token 与文本 CLS token 之间执行类似 CLIP 的对比损失。
- ITM（图文匹配）：二分类器——判断该图文对是否匹配？采用硬负样本挖掘。
- ITG（图像 grounding 文本生成）：在文本上施加因果 LM head，以查询向量为条件。强制查询向量编码可生成文本的内容。

仅训练 Q-Former。ViT 保持冻结。不涉及 LLM。

阶段 2：生成式学习。接入一个冻结的 LLM（如 OPT-2.7B 或 Flan-T5-XL 等）。通过一个小型线性层将 32 个查询输出投影到 LLM 的 embedding 维度。将它们拼接到文本 prompt 之前。仅在拼接后的 prompt + 图像 + 描述序列上，针对 LM loss 训练线性投影层和 Q-Former。

阶段 2 结束后，Q-Former + 投影层即构成完整的视觉适配器。推理流程为：图像 → ViT → Q-Former → 线性投影 → 拼接到文本前 → 冻结的 LLM 生成输出。

### 参数经济性

BLIP-2 配置：ViT-g/14（11 亿参数，冻结）+ OPT-6.7B（67 亿参数，冻结）+ Q-Former（1.88 亿参数，训练）= 总计 80 亿参数，其中仅 1.88 亿参与训练。Q-Former 单独仅占整个堆栈参数的约 2.4%。训练成本也反映了这一点：仅需数天即可在少量 A100 上完成，而端到端训练则需要数周。

质量表现：BLIP-2 在零样本 VQA 任务上达到或超越 Flamingo-80B，且体积仅为后者的 1/50。该桥梁方案行之有效。

### InstructBLIP 与指令感知型 Q-Former

InstructBLIP（2023）为 Q-Former 增加了一个额外输入：指令文本本身。在执行交叉注意力时，查询向量现在可以同时访问图像 patch 和指令。这使得查询向量能够针对特定指令进行专业化（例如“统计汽车数量”、“描述氛围”），而不是学习单一固定的摘要。在未见任务上的基准测试取得了提升。

### MiniGPT-4 与仅投影器方案

MiniGPT-4 保留了 Q-Former，但仅训练输出端的线性投影层，冻结其余所有部分。成本低廉，但以质量为代价——查询向量使用的是 BLIP-2 的，而非你自己训练的。适合快速迭代，但并非最优架构。

### 为何 LLaVA 选择了更简单的方案

LLaVA（2023，见第 12.05 课）用简单的 2 层 MLP 替换了 Q-Former，将每个 ViT patch token 投影到 LLM 空间——对于 24x24 网格，每张图像产生 576 个 token，全部输入 LLM。压缩效果较差，但允许 LLM 直接关注原始 patch。当时这颇具争议；但到了 2023 年底，该方案成为主流，因为视觉指令数据（LLaVA-Instruct-150k）证明了 MLP 可以被训练以保留足够的信号。权衡在于：LLaVA 的上下文窗口填充更快，但它能自然地扩展到多图像和视频场景。

截至 2026 年，领域已分化为两派：在 token 预算敏感的场景（长视频、多图）中，Q-Former 依然存活；而在追求单 token 原始质量的场景中，MLP 投影器占据主导。

### 门控交叉注意力：祖先 Flamingo

Flamingo（见第 12.04 课）早于 BLIP-2，采用了相同的交叉注意力思想，但将其应用于每一个冻结的 LLM 层，而非作为一个单一桥梁。BLIP-2 证明了只需在输入层进行压缩同样有效。Gemini 和 Idefics 结合了两者：交错输入 token，并辅以可选的门控交叉注意力以实现上下文中少样本学习。

### 2026 年的衍生架构

- Q-Former：BLIP-2、InstructBLIP、MiniGPT-4，以及出于 token 预算考虑的大多数视频-语言模型。
- Perceiver resampler：Flamingo 的变体（见第 12.04 课）；Idefics 系列、Eagle、OmniMAE。
- MLP 投影器：LLaVA、LLaVA-NeXT、LLaVA-OneVision、Cambrian-1。
- Attention pool：VILA、PaliGemma。

以上四种方案均有效。决策的关键在于你是受限于 token 预算，还是优先考虑单 token 的质量。

## 实践应用

`code/main.py` 构建了一个基于标准库的类 Q-Former 交叉注意力模块：

1. 模拟 256 个图像 patch token（维度 128）。
2. 实例化 32 个可学习查询向量（维度 128）。
3. 执行缩放点积交叉注意力（Q 来自查询向量，K/V 来自 patch）。
4. 通过线性层投影到 LLM 维度（512）。
5. 输出 32 个可供 LLM 消费的视觉 token。

所有数学运算均使用纯 Python 实现（基于向量的嵌套循环）。虽为玩具示例，但形状正确。程序会打印注意力权重矩阵，以便观察每个查询向量分别关注了哪些 patch。

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|----------|----------|
| Q-Former | “查询 Transformer” | 包含 32 个可学习查询向量的小型 Transformer，通过交叉注意力机制关注冻结的 ViT 特征 |
| Learnable queries | “视觉软提示” | 一组固定参数，作为交叉注意力的查询侧；按模型学习，在所有输入间共享 |
| Cross-attention | “Q 从此处来，K/V 从彼处来” | 查询、键、值来自不同来源的注意力机制；查询向量如何从 ViT patch 中提取信息 |
| ITC | “图文对比” | 应用于 Q-Former 池化查询向量与文本 CLS 之间的类 CLIP 损失 |
| ITM | “图文匹配” | 基于硬负样本挖掘对的二分类器；强制查询向量区分细粒度的不匹配项 |
| ITG | “图像 grounding 文本生成” | 以查询向量为条件生成文本的因果 LM 损失；强制查询向量编码可解码为文本的内容 |
| Two-stage pretraining | “先表示后生成” | 阶段 1 仅训练 Q-Former（ITC/ITM/ITG）；阶段 2 接入冻结的 LLM，仅训练投影层 + Q-Former |
| Frozen backbone | “不进行微调” | 视觉编码器和 LLM 权重保持固定；仅训练桥梁部分 |
| Projection head | “映射至 LLM 维度” | 将 Q-Former 输出映射到 LLM 嵌入维度的最终线性层 |
| Perceiver resampler | “Flamingo 的版本” | 类似的可学习查询交叉注意力机制，Flamingo 在每一层使用它，而非作为单一桥梁 |
