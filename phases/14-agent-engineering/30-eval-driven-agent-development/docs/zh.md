# 评估驱动的智能体开发

> Anthropic 的建议：“从简单的提示词开始，通过全面的评估进行优化，仅在需要时添加多步智能体系统。”评估不是最后一步。它是驱动第 14 阶段所有其他选择的“外层循环”。

**类型：** 学习 + 构建
**语言：** Python（标准库）
**前置要求：** 完成第 14 阶段全部内容。
**耗时：** 约 60 分钟

## 学习目标

- 说出三个评估层级——静态基准、自定义离线评估、在线生产环境评估——以及各自的用途。
- 解释评估器-优化器紧密循环机制。
- 描述 2026 年的最佳实践：评估脚本与代码同级存放，在 CI 中运行，并作为 PR 合并的门槛。
- 将第 14 阶段的每一课与其生成的评估用例关联起来。

## 问题所在

智能体在演示中表现良好，但在生产环境中却会以演示无法预测的方式失败。基准测试回答的是“该模型是否具备广泛的能力？”，而不是“该智能体是否为我的产品提交了正确的补丁？”。答案是：在三个层级上进行持续评估，并将每一条安全护栏和学到的规则都映射到具体的评估用例上。

## 核心概念

### 三个评估层级

1. **静态基准** —— 用于代码的 SWE-bench Verified（第 19 课），用于浏览/桌面操作的 WebArena/OSWorld（第 20 课），用于通用能力的 GAIA（第 19 课），用于工具使用的 BFCL V4（第 06 课）。用于跨模型对比和回归门禁。数据污染是真实存在的：SWE-bench+ 发现 32.67% 的解决方案存在泄露。务必报告 Verified / ±审计分数。

2. **自定义离线评估** —— 贴合你的产品形态：
   - LLM-as-judge（Langfuse、Phoenix、Opik —— 第 24 课）。
   - 基于执行的评估（运行补丁，检查测试用例）。
   - 基于轨迹的评估（将动作序列与黄金标准对比；OSWorld-Human 显示顶级智能体的表现比黄金标准高出 1.4-2.7 倍）。

3. **在线评估** —— 生产环境：
   - 会话回放（Langfuse）。
   - 触发安全护栏告警（第 16、21 课）。
   - 单步成本/延迟追踪（第 23 课 OTel spans）。

### 评估器-优化器（Anthropic）

紧密循环流程：

1. 提议者生成输出。
2. 评估器进行评判。
3. 迭代优化直至评估器通过。

这是对 Self-Refine（第 05 课）的泛化。任何你关注的智能体工作流都可以包装成评估器-优化器模式以提升可靠性。

### 2026 年最佳实践

- 评估脚本与代码同级存放。
- 在每个 PR 提交时在 CI 中运行。
- 以评估分数作为合并门禁（例如：“相比 main 分支回归幅度不得超过 5%”）。
- 每条安全护栏都对应一个评估用例。
- 每条学到的规则（Reflexion、pro-workflow learn-rule）都对应一个失败用例。

### 评估驱动开发失败的原因

- **缺乏基线。** 没有“上次已知良好版本”作为参照的评估结果毫无意义。务必保存基线数据。
- **无依据的 LLM 裁判。** 裁判模型同样会产生幻觉。采用 CRITIC 模式（第 05 课）——让裁判基于外部工具进行判断。
- **过度拟合评估集。** 针对评估集优化会导致偏离生产环境的实际效用。定期轮换评估用例。
- **不稳定的评估。** 非确定性用例会导致误报。固定随机种子，快照化状态。

## 动手构建

`code/main.py` 是一个基于标准库的评估框架：

- 支持分类注册（基准、自定义、在线）。
- 待测的脚本化智能体。
- 评估器-优化器循环：提议、评判、优化，直至通过或达到最大轮次。
- CI 门禁：聚合通过率 + 与基线的回归对比。

运行方式：

```
python3 code/main.py
```

输出：逐用例的通过/失败状态、回归标志、CI 门禁判定结果。

## 如何使用

- 将评估用例编写在与智能体代码相同的仓库中。
- 通过 CI 在每个 PR 上运行它们。
- 出现回归时使构建失败。
- 随时间推移追踪通过率。
- 将每一次生产环境故障关联到一个新的评估用例。

## 交付上线

`outputs/skill-eval-suite.md` 为智能体产品构建了一个包含 CI 门禁和回归追踪的三层评估套件。

## 练习

1. 选取一次你遇到的生产环境故障。编写一个能复现该故障的评估用例。你的智能体现在能通过它吗？
2. 为你的领域构建一个包含三个维度（事实性、语气、范围）的 LLM 裁判评分标准。对 50 个会话进行打分。
3. 将评估套件接入 CI。当回归幅度 >=5% 时使构建失败。
4. 添加轨迹效率指标：智能体实际步数与黄金标准步数的对比是多少？
5. 将第 14 阶段的每一课映射到你套件中的一个评估用例。是否有遗漏？那就是需要填补的空白。

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|----------|----------|
| Static benchmark | “现成评估” | SWE-bench、GAIA、AgentBench、WebArena、OSWorld |
| Custom offline eval | “领域评估” | 针对你产品形态的 LLM-as-judge / 执行 / 轨迹评估 |
| Online eval | “生产评估” | 会话回放、安全护栏告警、成本/延迟追踪 |
| Evaluator-optimizer | “提议-评判-优化” | 迭代直至裁判通过 |
| CI gate | “合并阻断” | 评估发生回归时使构建失败 |
| Baseline | “上次已知良好版本” | 用于检测回归的参考分数 |
| Trajectory efficiency | “步数对比黄金标准” | 智能体步数除以人类专家最少步数 |
