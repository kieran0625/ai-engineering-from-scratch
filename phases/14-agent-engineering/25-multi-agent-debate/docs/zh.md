# 多智能体辩论与协作

> Du 等人（ICML 2024，《Society of Minds》）运行 N 个模型实例，各自独立提出答案，随后在 R 轮迭代中相互批评以达成共识。该方法能提升事实准确性、规则遵循能力和推理能力。在 Token 成本方面，稀疏拓扑结构优于全连接拓扑。

**类型：** 学习 + 构建
**语言：** Python (标准库)
**前置知识：** Phase 14 · 12（工作流模式）、Phase 14 · 05（自我优化与 CRITIC）
**预计时间：** 约 60 分钟

## 学习目标

- 解释辩论协议：N 个提议者，R 轮迭代，最终收敛于统一答案。
- 说明辩论为何能提升事实准确性、规则遵循能力和推理能力。
- 解释稀疏拓扑结构：并非每个辩论者都需要看到其他所有辩论者。
- 基于脚本化 LLM 实现标准库级别的辩论系统（包含全连接和稀疏变体），并测量 Token 成本与准确率的对比。

## 问题背景

自我优化（Lesson 05）是一个模型自我批评——存在群体思维的风险。CRITIC（Lesson 05）将批评建立在外部工具上——但并非总是可用。辩论引入了第三种模式：多个实例、交叉批评、通过分歧达成收敛。

## 核心概念

### Society of Minds（Du 等，ICML 2024）

- N 个模型实例针对同一问题独立提出答案。
- 经过 R 轮迭代，每个模型阅读其他模型的提案并进行批评。
- 模型根据收到的批评更新自己的答案。
- R 轮结束后，返回收敛后的答案。

由于成本限制，原始实验使用 N=3、R=2。在难题（如 MMLU、GSM8K、国际象棋走法有效性验证、传记生成）上，增加智能体数量和迭代轮数可进一步提升准确率。

跨模型组合优于单模型辩论：ChatGPT + Bard 联合表现 > 任一单独使用。

### 稀疏拓扑结构

《Improving Multi-Agent Debate with Sparse Communication Topology》（arXiv:2406.11776，2024-2025）表明，全连接辩论并不总是最优的。稀疏拓扑结构（星型、环型、中心辐射型）可以在更低的 Token 成本下达到相当的准确率。每个辩论者仅能看到部分同行。

具体影响：

- 全连接拓扑 N=5, R=3 = 5 × 3 = 15 次提案，每次阅读 4 个同行 = 60 次批评操作。
- 星型拓扑 N=5, R=3（1 个中心节点 + 4 个叶节点）= 15 次提案，叶节点仅阅读中心节点 = 12 次批评操作。

### 适用场景

- **事实准确性。** N 个独立提案，交叉核对可减少幻觉。
- **规则遵循。** 国际象棋走法有效性验证——一个模型遗漏规则时，其他模型可发现。
- **开放式推理。** 多种视角逐步收敛至正确答案。

### 不适用场景

- **对延迟敏感的交互体验。** N × R 串行轮次带来的延迟可能无法满足需求。
- **对成本敏感的大规模应用。** 每道题消耗 N × R 倍的 Token。
- **简单事实查询。** 一次检索的成本低于五次辩论。

### 2026 年实际落地方案

- **Anthropic orchestrator-workers**（Lesson 12）——带综合步骤的辩论变体。
- **LangGraph supervisor**（Lesson 13）——中央路由器 + 专家智能体可将辩论实现为图中的一个节点。
- **OpenAI Agents SDK**（Lesson 16）——智能体之间来回交接以实现迭代批评。
- **多智能体评估**——将辩论与评估器-优化器配对以获取评估信号。

### 常见陷阱

- **收敛崩溃。** 所有智能体过早收敛到第一个错误答案。可通过强制要求分歧轮次来缓解。
- **中心节点故障。** 在星型拓扑中，糟糕的中心节点会污染所有参与者。可采用轮换机制或使用多个中心节点。
- **提示词同质化。** 所有智能体使用相同的提示词，导致输出雷同。应使用多样化的提示词和/或模型。

## 动手实现

`code/main.py` 实现了标准库级别的辩论系统：

- `Debater` 类（带有每位辩论者观点漂移特性的脚本化 LLM）。
- `FullMeshDebate` 和 `SparseDebate` 运行器。
- 三道题目：一道事实题、一道规则题、一道推理题。
- 指标：收敛答案、收敛所需轮数、总批评操作数。

运行方式：

```
python3 code/main.py
```

输出结果：各协议的准确率与成本；稀疏拓扑在 2/3 的题目上以更低成本追平全连接拓扑的表现。

## 实际应用

- **Anthropic orchestrator-workers**：适用于简单的 2-3 个工作者辩论。
- **LangGraph**：适用于带检查点机制的状态持久化多轮辩论。
- **自定义实现**：适用于研究或特定正确性保障场景。

## 练习

1. 实现“强制分歧”规则：在第 1 轮中，每位辩论者必须生成不同的提案。测量其对收敛速度的影响。
2. 添加置信度加权聚合：辩论者返回 `(answer, confidence)`；聚合器按置信度进行加权。这是否有效？
3. 将一个“智能体”替换为具有不同观点的脚本化 LLM。异构性是否能提升准确率？
4. 在你的 3 道题目上测量全连接与稀疏拓扑的 Token 成本。绘制成本与准确率的对比图。
5. 阅读《Society of Minds》论文。将你的玩具项目扩展至 N=5, R=3。哪些地方会出错？哪些地方会得到改善？

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|----------|----------|
| Debate（辩论） | “多智能体批评” | N 个提议者，R 轮交叉批评，最终收敛 |
| Full mesh（全连接） | “所有人互相阅读” | 每轮中每个辩论者都阅读所有同行 |
| Sparse topology（稀疏拓扑） | “有限的同行视野” | 辩论者仅阅读部分同行 |
| Hub-and-spoke（中心辐射型） | “星型拓扑” | 一个中心辩论者，其余 N-1 个叶节点仅阅读中心节点 |
| Convergence（收敛） | “达成一致” | 辩论者收敛于统一答案 |
| Society of Minds（心智社会） | “Du 等人的辩论论文” | ICML 2024 提出的多智能体辩论方法 |
