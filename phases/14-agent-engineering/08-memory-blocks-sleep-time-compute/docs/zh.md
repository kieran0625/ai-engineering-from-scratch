# 记忆块与睡眠期计算（Letta）

> 2024年，MemGPT 演进为 Letta。2026年的版本引入了两个新概念：模型可直接编辑的离散功能型记忆块，以及在主代理空闲时异步整合记忆的睡眠期代理。这是将记忆能力扩展至单次对话之外的方法。

**类型：** 构建
**语言：** Python（标准库）
**前置条件：** 第14阶段 · 07（MemGPT）
**耗时：** 约75分钟

## 学习目标

- 说出 Letta 使用的三个记忆层级（Core、Recall、Archival）及其各自的作用。
- 解释记忆块模式：人类块（Human block）、人格块（Persona block）以及作为一等公民的类型化对象的用户自定义块。
- 描述什么是睡眠期计算，为何它位于关键路径之外，以及为何它能运行比主代理更强的模型。
- 实现一个脚本化的双代理循环，其中主代理负责响应请求，睡眠期代理在轮次之间整合记忆块。

## 问题背景

MemGPT（第07课）解决了虚拟内存的控制流问题。但在生产环境中出现了三个问题：

1. **延迟。** 每次记忆操作都位于关键路径上。如果代理必须在用户等待时进行修剪、总结或协调，尾部延迟会急剧上升。
2. **记忆衰退。** 写入不断累积。已被推翻的事实依然留存。检索系统被陈旧内容淹没。
3. **结构丢失。** 扁平的归档存储无法表达“人类块始终在提示词中；人格块始终在提示词中；任务块按会话切换。”

Letta（letta.com）是2026年的重写版本。记忆块使结构显式化；睡眠期计算将整合操作移出关键路径。

## 核心概念

### 三个层级

| 层级 | 作用范围 | 存储位置 | 写入方式 |
|------|----------|----------|----------|
| Core | 始终可见 | 主提示词内部 | 代理工具调用 + 睡眠期重写 |
| Recall | 对话历史 | 可检索 | 自动轮次日志记录 |
| Archival | 任意事实 | 向量 + KV + 图 | 代理工具调用 + 睡眠期摄入 |

Core 对应 MemGPT 的核心层。Recall 是对话缓冲区及其被驱逐的尾部。Archival 是外部存储。这种划分清理了 MemGPT 两层架构的过度负载问题。

### 记忆块

块是核心层级中类型化、持久化且可编辑的片段。原始的 MemGPT 论文定义了两个块：

- **人类块（Human block）**——关于用户的事实（姓名、角色、偏好、目标）。
- **人格块（Persona block）**——代理的自我认知（身份、语气、约束）。

Letta 将其泛化为任意用户自定义块：用于当前目标的 `Task` 块、用于代码库事实的 `Project` 块、用于硬性约束的 `Safety` 块。每个块都包含 `id`、`label`、`value`、`limit`（字符上限）、`description`（以便模型知道何时对其进行编辑）。

块可通过工具接口进行编辑：

- `block_append(label, text)`
- `block_replace(label, old, new)`
- `block_read(label)`
- `block_summarize(label)` —— 压缩接近上限的块。

### 睡眠期计算

2025年 Letta 的新增特性：在后台运行第二个代理，使其脱离关键路径。睡眠期代理会处理对话记录和代码库上下文，将 `learned_context` 写入共享块，并对归档记录进行整合或标记失效。

衍生出的特性：

- **无延迟成本。** 主代理的响应无需等待记忆操作完成。
- **允许使用更强模型。** 睡眠期代理可以使用更昂贵、更慢的模型，因为它不受延迟限制。
- **自然的整合窗口。** 在用户不等待时进行去重、总结和标记矛盾事实为无效。

这种形态契合人类的工作方式：你完成任务，然后休息消化，长期记忆会在夜间沉淀。

### Letta V1 与原生推理

Letta V1（`letta_v1_agent`，2026年）弃用了 `send_message`/心跳机制和内联 `Thought:` 令牌，转而采用原生推理。Responses API（OpenAI）和带有扩展思考功能的 Messages API（Anthropic）会在独立通道输出推理过程，并通过轮次传递（在生产环境中跨提供商加密）。控制循环仍然是 ReAct。思维轨迹是结构化的，而非提示词形状的。

### 该模式的潜在缺陷

- **块膨胀。** 无限的 `block_append` 会迅速触及上限。在写入超过上限前接入块摘要器。
- **静默漂移。** 睡眠期代理重写了某个块，但主代理从未察觉。对块进行版本控制并在轨迹中暴露差异。
- **污染性合并。** 睡眠期代理将攻击者可访问的内容处理并写入核心层。第27课的防御原则同样适用于睡眠期接口。

## 动手实现

`code/main.py` 实现了以下功能：

- `Block` —— id、label、value、limit、description。
- `BlockStore` —— CRUD 操作 + `near_limit(label)` 辅助函数。
- 两个脚本化代理 —— `PrimaryAgent` 负责响应轮次，`SleepTimeAgent` 在轮次间进行整合。
- 一条轨迹，展示包含三次轮次对话及块写入的过程，外加一次睡眠期处理，用于总结某个块并使陈旧事实失效。

运行方式：

```
python3 code/main.py
```

终端输出展示了这种分工：主代理轮次响应迅速并产生原始写入；睡眠期处理则负责压缩和清理。

## 实际应用

- **Letta**（letta.com）提供参考实现。支持自托管或托管云服务。
- **Claude Agent SDK skills** 作为块状知识——技能是一个命名、带版本、可检索的指令块，代理按需加载。
- **自定义构建** 面向希望掌控存储后端的团队。使用 Letta API 契约以便日后迁移。

## 交付部署

`outputs/skill-memory-blocks.md` 为任何运行时生成类 Letta 的块系统，并内置睡眠期钩子，涵盖安全规则与引用绑定。

## 练习

1. 添加一个 `block_summarize` 工具，当 `near_limit` 返回 true 时，用模型生成的摘要替换块的值。哪个触发阈值能同时最小化摘要调用次数和块溢出风险？
2. 在归档数据上实现睡眠期去重：文本 token 重叠度 >90% 的两条记录合并为一条。仅在睡眠期处理中执行，绝不在关键路径上运行。
3. 对块进行版本控制。每次写入时记录旧值和差异。暴露 `block_history(label)` 供运维人员调试“代理为何忘记了 X”。
4. 将睡眠期代理视为不可信写入者。当它们修改人格块或安全块时，提交前需经过第二个代理的审查。
5. 将示例移植为使用 Letta API（`letta_v1_agent`）。块架构会发生什么变化，原生推理如何改变轨迹形态？

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|----------|----------|
| Memory block | “可编辑的提示词片段” | 核心记忆中类型化、持久化且可由 LLM 编辑的片段 |
| Human block | “用户记忆” | 关于用户的事实，固定于核心层 |
| Persona block | “代理身份” | 自我认知、语气、约束，固定于核心层 |
| Sleep-time compute | “异步记忆工作” | 第二个代理在关键路径之外执行整合 |
| Core / Recall / Archival | “层级” | 三层记忆划分：始终可见 / 对话 / 外部 |
| Block limit | “容量限制” | 每个块的字符限制；强制触发摘要 |
| Native reasoning | “思考通道” | 提供商级别的推理输出，而非提示词级别的 `Thought:` |
| Learned context | “睡眠期输出” | 睡眠期代理写入共享块的事实 |
