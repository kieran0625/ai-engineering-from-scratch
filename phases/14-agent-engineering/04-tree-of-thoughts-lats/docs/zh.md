# 思维树与 LATS：刻意搜索

> 单条思维链轨迹没有回溯的空间。ToT（Yao 等，2023）将推理转化为树结构，并在每个节点进行自我评估。LATS（Zhou 等，2024）在蒙特卡洛树搜索（MCTS）框架下统一了 ToT、ReAct 和 Reflexion。在“24点游戏”中，准确率从 CoT 的 4% 提升至 ToT 的 74%；LATS 在 HumanEval 上达到了 92.7% 的 pass@1。

**类型：** 构建
**语言：** Python（标准库）
**前置知识：** 第 14 阶段 · 01（智能体循环）、第 14 阶段 · 03（反思机制）
**耗时：** 约 75 分钟

## 学习目标

- 将推理建模为搜索过程：节点是“思维”，边是“扩展”，价值函数衡量“前景如何”。
- 使用标准库实现带有自我评估评分的 ToT 风格 BFS 树搜索。
- 扩展为一个包含选择/扩展/模拟/反向传播的玩具级 LATS MCTS 循环。
- 判断何时值得付出 Token 倍增的成本进行搜索（如 24 点游戏、代码生成），以及何时单条轨迹已足够（如简单问答）。

## 问题背景

思维链是一条线性路径。如果第一步出错，后续所有步骤都会基于错误的前提进行推导。在“24点游戏”（使用四个数字通过 + − × ÷ 运算得出 24）中，GPT-4 的 CoT 准确率仅为 4%。模型在早期就选错了子表达式，且无法挽回。

推理真正需要的是提出多个候选方案、评估它们、挑选有前景的方案，并在遇到死胡同时进行回溯的能力。这就是搜索。思维树（Tree of Thoughts）和 LATS 是两种经典的范式。

## 核心概念

### 思维树（Tree of Thoughts, Yao 等，NeurIPS 2023）

每个节点都是一个连贯的中间步骤（即“一个思维”）。每个节点可以扩展出 K 个子思维。大语言模型通过评分提示词对每个节点进行自我评估。搜索算法遍历这棵树——可以是 BFS、DFS 或束搜索（beam search）。

```
                     (root: "find 24 from 4 6 4 1")
                    /               |            \
           ("6 - 4 = 2")    ("4 + 1 = 5")    ("4 * 6 = 24")  <- Score: HIGH
              /   \              |                  |
          ...    ...          ...                finish
```

自我评估是整个架构的承重部分。论文展示了三种变体：`sure / likely / impossible` 分类、`1..10` 数值评分，以及在候选方案间投票。这三种方法在 24 点游戏上都大幅超越了 CoT（GPT-4 从 4% 提升至 74%）。

### LATS（Zhou 等，ICML 2024）

LATS 在 MCTS 框架下统一了 ToT、ReAct 和 Reflexion。LLM 在此扮演三个角色：

- **策略（Policy）**：提出候选的下一步动作（类 ReAct 风格）。
- **价值函数（Value function）**：对部分轨迹进行评分（类 ToT 自我评估）。
- **自我反思器（Self-reflector）**：在失败时撰写自然语言反思（类 Reflexion 风格），并用于重新初始化后续的 rollout。

环境反馈（观测结果）会融入价值函数中，使搜索不仅依赖模型的主观意见，还能参考真实的工具执行结果。论文发布时的结果：GPT-4 在 HumanEval 上达到 92.7% 的 pass@1（当时 SOTA），GPT-3.5 在 WebShop 上平均得分 75.9（接近基于梯度的微调水平）。

### MCTS 极简原理

每次迭代包含四个阶段：

1. **选择（Select）**：使用 UCT（树的上置信界）从根节点遍历至叶子节点。
2. **扩展（Expand）**：通过策略生成 K 个子节点。
3. **模拟（Simulate）**：从子节点开始，利用策略进行 rollout，并使用价值函数（或环境奖励）对叶子节点进行评分。
4. **反向传播（Backpropagate）**：沿路径向上更新访问次数和价值估计。

UCT 公式：`Q(s, a) + c * sqrt(ln N(s) / N(s, a))`。第一项为开发（exploitation），第二项为探索（exploration）。需根据具体任务调整 `c`。

### 成本现实

搜索会导致 Token 消耗激增。在 24 点游戏中，ToT 消耗的 Token 量是 CoT 的 100 到 1000 倍。LATS 的情况类似。这不是免费的午餐；请将搜索保留给以下场景：

- 单条轨迹明显不足的任务（如 24 点游戏、复杂代码生成）。
- 正确性比运行时间更重要的任务。
- 拥有廉价且可靠的价值函数的任务（如代码的单元测试、数学题的明确目标值）。

如果你的任务只有一个正确答案，且评估器噪声较大，搜索往往会适得其反——它可能会找到一个“评分高但实际错误”的答案。

### 2026 年定位

大多数生产环境的智能体并不运行 LATS。它们运行的是带有工具验证的 ReAct（参见 Lesson 05 中的 CRITIC）。搜索主要出现在以下细分领域：

- 将测试作为价值函数的编码智能体（类 HumanEval 风格）。
- 探索多条查询路径的深度研究智能体。
- LangGraph 子图内高度依赖规划的工作流。

AlphaEvolve（Lesson 11）代表了 2025 年的极端案例：在代码上进行进化搜索，具备机器可验证的适应度函数，取得了前沿突破（56 年来首次改进 4x4 矩阵乘法）。

## 动手构建

`code/main.py` 实现了：

- 针对简化版“选择算术运算符”任务的微型 ToT BFS。
- 同一任务上的玩具级 LATS MCTS 循环（选择/扩展/模拟/反向传播），采用 UCT 选择策略。
- 由符号评分与自我评估评分组合而成的价值函数。

运行方式：

```
python3 code/main.py
```

运行日志显示，ToT 使用 BFS 在每个节点扩展三个候选方案，而 LATS 则通过 MCTS 收敛于最佳 rollout。两者均打印了 Token 消耗计数。

## 实际应用

LangGraph 将类 ToT 的探索能力封装为子图模式；LangChain 团队关于 LATS 的博客文章（2024 年 5 月）是参考教程。LlamaIndex 内置了一个 `TreeOfThoughts` 智能体。对于大多数 2026 年的生产环境智能体而言，该模式通常位于 `if task_complexity > threshold: use_search()` 门控之后——详见 Lesson 05 中的评估器-优化器模式。

## 交付部署

`outputs/skill-search-policy.md` 会根据任务形态、预算和评估器保真度，在线性 ReAct、ToT、LATS 和进化搜索之间进行选择。

## 练习

1. 分别使用 UCT 参数 c=0.1 和 c=2.0 运行玩具级 LATS。观察日志中发生了什么变化？
2. 将价值函数替换为噪声更大的评分器（添加随机抖动）。MCTS 是否仍能找到最优叶子节点？它能容忍的最小信噪比是多少？
3. 实现束搜索风格的 ToT（每层保留前 k 个），并与 BFS 进行比较。在严格的 Token 预算下，哪种表现更好？
4. 阅读 LATS 论文的第 5.1 节。复现 HumanEval 的轨迹数量统计：达到报告中的 pass@1 需要多少次 rollout？
5. 阅读 LATS 论文中关于“LATS 效果减弱的情境”的讨论。写一段决策规则，说明如何根据任务形态映射到搜索策略。

## 核心术语

| 术语 | 常见说法 | 实际含义 |
|------|----------|----------|
| Tree of Thoughts | “分支式 CoT” | Yao 等提出——带有自我评估的思维树节点 |
| LATS | “面向 LLM 的 MCTS” | Zhou 等提出——在 MCTS 下统一 ToT + ReAct + Reflexion |
| UCT | “上置信界” | 平衡开发（Q）与探索（ln N / n）的选择公式 |
| Value function | “当前状态有多好” | 提示词驱动的 LLM 评分或环境奖励；用于反向传播 |
| Policy | “动作提议者” | 类 ReAct 生成器；输出候选的下一步思维/动作 |
| Rollout | “模拟轨迹” | 使用策略从节点走到叶子，并用价值函数评分 |
| Backpropagate | “更新祖先节点” | 将叶子节点的奖励沿路径向上推送，更新访问次数和 Q 值 |
| Search cost | “Token 爆炸” | 24 点游戏中是 CoT 的 100-1000 倍；采用前需评估预算 |
