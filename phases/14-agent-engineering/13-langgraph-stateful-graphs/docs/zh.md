# LangGraph：有状态图与持久化执行

> LangGraph 是 2026 年低层有状态编排的参考实现。智能体是一个状态机；节点是函数；边是转换；状态是不可变的，并在每一步之后进行检查点保存。从任何故障中恢复时，都能精确回到中断的位置继续执行。

**类型：** 学习 + 构建
**语言：** Python（标准库）
**前置条件：** 第 14 阶段 · 01（智能体循环），第 14 阶段 · 12（工作流模式）
**时间：** 约 75 分钟

## 学习目标

- 描述 LangGraph 的核心模型：具有不可变状态、函数节点、条件边和步后检查点的状态机。
- 列举文档强调的四大能力：持久化执行、流式传输、人在回路、全面记忆。
- 解释 LangGraph 支持的三种编排拓扑：主管（Supervisor）、对等（Swarm/蜂群）、分层（嵌套子图）。
- 使用标准库实现一个有状态图，包含不可变状态、条件边以及检查点/恢复循环。

## 问题背景

智能体和工作流面临共同的问题：当一个 40 步的运行在第 38 步失败时，你希望从第 38 步恢复，而不是重新开始。二流的状态模型会让运维人员不得不在假设从头运行的库周围打补丁来实现重试。

LangGraph 的设计方案是：状态是一等公民的强类型对象，变更是显式的，并且每个节点执行后都会持久化检查点。恢复只需调用一次 `load_state(session_id)`。

## 核心概念

### 图结构

图由以下要素定义：

- **状态类型**。一种强类型字典（或 Pydantic 模型），每个节点读取并修改它。
- **节点**。纯函数 `(state) -> state_update`。返回值会合并到状态中。
- **边**。节点之间的条件或直接转换。
- **入口与出口**。`START` 和 `END` 哨兵节点标记边界。

示例：一个包含 `classify`、`refund`、`bug`、`sales`、`done` 节点的智能体——将路由工作流表示为图。

### 持久化执行

每个节点返回后，运行时会将状态序列化并写入检查点存储（如 SQLite、Postgres、Redis 或自定义后端）。如果在第 N 步发生故障，运行时可以 `resume(session_id)`，并以精确的状态从第 N+1 步继续执行。

LangGraph 文档明确指出了对此需求强烈的生产环境用户：Klarna、Uber、摩根大通。其核心主张并非图的结构本身，而是“图结构 + 检查点机制”使得故障恢复成本极低。

### 流式传输

每个节点都可以产出部分输出。图会以节点增量事件的形式向调用方流式传输数据，以便在图运行过程中实时更新 UI。

### 人在回路

在节点之间检查和修改状态。实现方式：在关键节点前暂停，将状态暴露给人工审核，接受修改后恢复。检查点机制使这变得轻而易举，因为状态已经是序列化的。

### 记忆

短期记忆（单次运行内——状态中的对话历史）和长期记忆（跨运行——通过检查点及独立的长期存储实现持久化）。LangGraph 通过工具集成外部记忆系统（如 Mem0 或自定义系统）。

### 三种拓扑

1. **主管（Supervisor）**。中央路由 LLM 将任务分发给专家子智能体。`create_supervisor()` 在 `langgraph-supervisor` 中（尽管 LangChain 团队在 2026 年建议直接通过工具调用来实现此功能，以获得更好的上下文控制）。
2. **蜂群（Swarm）/ 对等网络**。智能体通过共享的工具接口直接交接任务。无中央路由器。
3. **分层**。主管管理子主管，实现为嵌套子图。

### 该模式的常见陷阱

- **检查点过小**。仅检查点保存对话轮次会导致工具状态和记忆写入无法恢复。必须序列化完整状态。
- **非确定性节点**。恢复机制假设节点输入会产生相同的状态更新。随机种子、系统时钟、外部 API 调用结果必须被捕获并记录。
- **过度使用条件边**。如果所有边都是条件性的，该图将成为一个无法推理的状态机。更推荐线性链配合偶尔的分支。

## 动手实践

`code/main.py` 实现了一个基于标准库的有状态图：

- `State` —— 一个包含 `messages`、`step`、`route`、`output`、`human_approval` 的强类型字典。
- `Node` —— 接收状态并返回更新字典的可调用对象。
- `StateGraph` —— 节点 + 边 + 条件边 + 运行 + 恢复。
- `SQLiteCheckpointer`（内存模拟）—— 在每个节点后序列化状态；`load(session_id)` 负责恢复。
- 演示图：分类 -> 分支（退款/缺陷/销售）-> 人工网关 -> 发送。

运行它：

```
python3 code/main.py
```

追踪日志显示首次运行在人工网关处失败，随后进行持久化，最后通过恢复生成最终输出。

## 核心术语

| 术语 | 常见说法 | 实际含义 |
|------|----------|----------|
| State graph | “将智能体视为状态机” | 强类型状态 + 节点 + 边 + 归约器 |
| Checkpointer | “持久化后端” | 在每个节点后序列化状态；支持恢复 |
| Reducer | “状态合并器” | 将当前状态与节点更新合并的函数 |
| Conditional edge | “分支” | 由状态函数决定的边 |
| Subgraph | “嵌套图” | 作为另一个图中的节点使用的图 |
| Durable execution | “从故障恢复” | 以精确状态在最后一个成功节点处重启 |
| Supervisor | “路由 LLM” | 专家子智能体的中央分发器 |
| Swarm | “P2P 智能体” | 智能体通过共享工具交接；无中央路由器 |
