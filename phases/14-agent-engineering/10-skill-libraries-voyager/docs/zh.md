# 技能库与终身学习（Voyager）

> Voyager（Wang 等人，TMLR 2024）将可执行代码视为技能。技能具有命名、可检索、可组合的特性，并能通过环境反馈进行迭代优化。这是 Claude Agent SDK 技能、skillkit 以及 2026 年技能库模式的参考架构。

**类型：** 构建
**语言：** Python（标准库）
**前置条件：** 第 14 阶段 · 07（MemGPT）、第 14 阶段 · 08（Letta Blocks）
**耗时：** 约 75 分钟

## 学习目标

- 说出 Voyager 的三个组成部分——自动课程（automatic curriculum）、技能库（skill library）、迭代提示机制（iterative prompting mechanism），并说明各自的作用。
- 解释为什么 Voyager 将动作空间定义为代码而非原始命令。
- 使用标准库实现一个技能库，包含注册、检索、组合和基于失败的迭代优化功能。
- 将 Voyager 的模式映射到 2026 年的 Claude Agent SDK 技能和 skillkit 生态系统中。

## 问题所在

在每个会话中都从零开始重建所有能力的智能体会犯三个错误：

1. **浪费 Token。** 每个任务都会重新触发相同的推理过程。
2. **丢失进度。** 在会话 A 中学到的修正无法迁移到会话 B。
3. **长程组合失败。** 复杂任务需要能力层级结构；单次提示无法表达这些结构。

Voyager 的解决方案是：将每个可复用的能力视为存储在库中的命名代码块，支持按相似度检索、与其他技能组合，并通过执行反馈进行迭代优化。

## 核心概念

### 三大组件

Voyager（arXiv:2305.16291）围绕以下三点构建智能体架构：

1. **自动课程（Automatic Curriculum）。** 由好奇心驱动的提议器根据智能体当前的技能集和环境状态选择下一个任务。探索是自底向上的。
2. **技能库（Skill Library）。** 每个技能都是可执行代码。任务成功时添加新技能。技能通过查询与描述的相似度进行检索。
3. **迭代提示机制（Iterative Prompting Mechanism）。** 失败时，智能体接收执行错误、环境反馈和自我验证输出，随后对技能进行优化。

《我的世界》评估结果（Wang 等人，2024）：相比基线模型，独特物品数量增加 3.3 倍，石制工具制作速度提升 8.5 倍，铁制工具制作速度提升 6.4 倍，地图探索时长延长 2.3 倍。这些数据虽针对《我的世界》，但该模式具有通用性。

### 动作空间即代码

大多数智能体输出的是原始命令。Voyager 输出的是 JavaScript 函数。一个技能是：

```
async function craftIronPickaxe(bot) {
  await mineIron(bot, 3);
  await mineStick(bot, 2);
  await placeCraftingTable(bot);
  await craft(bot, 'iron_pickaxe');
}
```

由子技能组合而成。以描述和嵌入向量作为键值存储。检索时获取的是程序而非提示词。

这就是 2026 年 Claude Agent SDK 的技能定义：一段命名的、可检索的代码块，加上智能体按需加载的指令。

### 技能检索

新任务：“制作一把钻石镐”。智能体执行以下步骤：

1. 对任务描述进行向量化嵌入。
2. 查询技能库，获取最相似的 top-k 个技能。
3. 检索 `craftIronPickaxe`、`mineDiamond`、`placeCraftingTable` 等。
4. 结合检索到的基础技能与新逻辑，组合出新的技能。

这正是 MCP 资源（第 13 阶段）和 Agent SDK 技能所实现的模式：在当前任务范围内，对知识/代码表面进行检索。

### 迭代优化

Voyager 的反馈循环如下：

1. 智能体编写一个技能。
2. 技能在环境中运行。
3. 返回三种信号之一：`success`、`error`（附带堆栈跟踪）、`self-verification failure`。
4. 智能体将该信号作为上下文，重写该技能。
5. 循环执行，直到成功或达到最大轮次。

这是将 Self-Refine（第 05 课）应用于代码生成，并结合环境接地验证。CRITIC（第 05 课）则是采用相同模式，但使用外部工具作为验证器。

### 课程与探索

Voyager 的课程模块会根据智能体已掌握的能力和尚未完成的任务，提出类似“在湖边建造庇护所”的任务。提议器利用环境状态和技能清单，选择一个略高于当前能力的任务——即探索的最佳区间。

对于生产环境的智能体，这转化为一个“缺失检测”操作符：给定当前技能库和领域范围，我们还有哪些技能尚未覆盖？团队通常将其作为人工课程审查来实现。

### 该模式的常见陷阱

- **技能库腐化。** 同一技能因描述略有不同而被重复添加多次。写入时应增加去重机制；检索时仅返回唯一版本。
- **组合技能漂移。** 父技能依赖于已被优化的子技能。应对技能进行版本控制；父技能锁定 v1 后，不会自动升级到 v3。
- **检索质量下降。** 当技能库规模超过数百个时，基于技能描述的向量检索效果会退化。需辅以标签过滤和硬性约束（例如“仅包含具备 `category=tooling` 的技能”）。

## 动手构建

`code/main.py` 实现了一个标准库技能库：

- `Skill` —— 名称、描述、代码（字符串形式）、版本、标签、依赖项。
- `SkillLibrary` —— 注册、搜索（基于 Token 重叠）、组合（依赖项拓扑排序）和优化（更新时版本号递增）。
- 一个脚本化智能体，负责注册三个基础技能，组合第四个技能，遭遇失败后进行优化。

运行方式：

```
python3 code/main.py
```

运行日志展示了库写入、检索、组合、一次失败的执行以及 v2 版本的优化——完整呈现了 Voyager 的闭环流程。

## 实际应用

- **Claude Agent SDK 技能**（Anthropic）—— 2026 年的参考实现：每个技能包含描述、代码和指令；在智能体会话期间按需加载。
- **skillkit**（npm: skillkit）—— 为 30 多种 AI 编程智能体提供跨平台技能管理。
- **自定义技能库** —— 面向特定领域（如数据智能体的 SQL 技能、基础设施智能体的 Terraform 技能）。Voyager 模式同样适用于小型化场景。
- **OpenAI Agents SDK `tools`** —— 处于轻量级一端；每个工具本身就是一个轻量级技能。

## 交付部署

`outputs/skill-skill-library.md` 可生成符合 Voyager 架构的技能库，并为任何目标运行时环境内置注册、检索、版本控制和优化功能。

## 练习

1. 为 `compose()` 添加依赖循环检测器。当技能 A 依赖 B，而 B 又依赖 A 时会发生什么？报错还是警告？
2. 实现每技能的版本锁定。当父技能组合子技能 `crafting@1` 时，对 `crafting@2` 的优化不应静默升级父技能。
3. 将基于 Token 重叠的检索替换为 sentence-transformers 嵌入（或 BM25 标准库实现）。在包含 50 个技能的测试库上测量 retrieval@5 指标。
4. 添加一个“课程”智能体：给定当前技能库和领域描述，提出 5 个缺失的技能。每周调用一次。
5. 阅读 Anthropic 的 Claude Agent SDK 技能文档。将该测试库移植到 SDK 的技能模式中。可发现性方面会发生什么变化？

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|----------|----------|
| Skill（技能） | “可复用能力” | 带有名称和描述的代码块，支持按相似度检索 |
| Skill library（技能库） | “智能体的操作记忆” | 持久化的技能存储，支持搜索与组合 |
| Curriculum（课程） | “任务提议器” | 由当前能力缺口驱动的自底向上目标生成器 |
| Composition（组合） | “技能有向无环图（DAG）” | 技能调用技能；执行时按拓扑顺序排序 |
| Iterative refinement（迭代优化） | “自我修正循环” | 环境反馈、错误信息与自我验证结果共同反馈至下一版本 |
| Action-space-as-code（动作空间即代码） | “程序化动作” | 输出函数而非原始命令，以支持时间跨度较长的行为 |
| Dedup on write（写入去重） | “技能合并” | 高度相似的描述会被合并为一个标准技能 |
