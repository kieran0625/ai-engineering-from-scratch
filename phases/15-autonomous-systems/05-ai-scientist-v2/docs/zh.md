# AI Scientist v2 — 研讨会级别的自主研究

> Sakana 的 AI Scientist v2（Yamada 等人，arXiv:2504.08066）运行完整的研究循环：假设、代码、实验、图表、撰写、投稿。它是首个让生成论文通过 ICLR 2025 研讨会同行评审的系统。独立评估（Beel 等人）发现，42% 的实验因编码错误而失败，且文献综述经常将已有概念误标为新颖。Sakana 自身的文档警告称该代码库会执行 LLM 编写的代码，并建议使用 Docker 进行隔离。这幅图景的两面性正是其核心所在。

**类型：** 学习
**语言：** Python（标准库，研究循环状态机演示程序）
**前置要求：** Phase 15 · 03 (AlphaEvolve), Phase 15 · 04 (DGM)
**时间：** 约 60 分钟

## 问题所在

研究是一项开放式任务。与 AlphaEvolve 的算法搜索或 DGM 的基准约束型自我修改不同，研究成果没有机器可验证的正确性标准。论文由审稿人评判，而非单元测试。这使得闭环更加困难——但如果能实现闭环，其价值也更高，因为复利式进步正孕育于研究中。

AI Scientist v1（Sakana, 2024）通过从人工撰写的模板出发实现了闭环。LLM 在固定的脚手架中填充实验内容。AI Scientist v2（Yamada 等人, 2025）通过使用带有视觉-语言模型批判循环的智能体树搜索，消除了对模板的需求。该系统生成想法、实现实验、制作图表、撰写论文，并根据审稿反馈进行迭代。

同行评审结论：一篇由 v2 生成的论文在 ICLR 2025 研讨会上被接收（已披露来源）。独立评估结论：该系统远未达到可靠程度。两者皆为事实。

## 核心概念

### 架构

1. **想法生成。** LLM 根据主题和现有文献提出研究想法。v1 使用模板；v2 在假设空间中进行智能体搜索。
2. **新颖性检查。** 文献检索步骤用于核查该想法是否已发表。Beel 等人的评估在此步骤发现了误标问题——已有方法经常被归类为新颖。
3. **实验计划。** 智能体起草实验协议并编写代码。
4. **执行。** 代码在沙箱中运行。失败情况会被反馈至重试循环。根据 Beel 等人的测量数据，此阶段有 42% 的实验因编码错误而失败。
5. **图表生成。** 视觉-语言模型读取生成的图表并为其重写以提升清晰度。这是 v2 的关键技术新增项。
6. **撰写。** LLM 起草论文，并与内部审稿人进行迭代。
7. **可选：投稿。** 将论文提交至会议/期刊。

### 研讨会接收结果的含义

一篇由 v2 生成的论文通过了 ICLR 2025 研讨会的同行评审。作者向程序委员会披露了论文的生成来源。这一接收结果只是一个数据点；它并非授权宣称该系统“能够进行研究”。

重要背景：研讨会论文的门槛低于主会论文。同行评审存在噪声；每天接收的投稿中只有一小部分会被录用。一次成功只是概念验证，而非可靠性声明。那篇发表于 2026 年的《Nature》论文记录了端到端循环，且本身由人类研究人员共同署名；并非“系统写了一篇《Nature》论文”。

### 独立评估的发现

Beel 等人（arXiv:2502.14297）进行了外部评估。主要发现如下：

- **实验失败。** 42% 的实验因编码错误而失败（错误的导入、形状不匹配、未定义的变量）。重试循环捕获了部分失败，但并非全部。
- **新颖性误标。** 文献检索步骤经常将已有概念标记为新颖。这相当于研究领域的幻觉。
- **呈现质量差距。** 视觉-语言图表批判生成了出版级质量的视觉效果，掩盖了底层实验的缺陷。

最后一项发现对本阶段至关重要。一个能在不进行扎实研究的情况下产出令人信服输出的系统，比那些明显失败的系统更危险，而非更安全。评估必须触及底层主张，而不能止步于图表。

### 沙箱逃逸隐患

Sakana 自身的仓库 README 发出警告：

> 由于本软件的特性（会执行 LLM 生成的代码），我们无法保证安全性。存在引入危险依赖包、不受控的网络访问以及产生非预期进程的风险。请自行承担风险，并建议采用 Docker 隔离。

这就是在未经验证领域中自主性的运作形态。LLM 编写代码；代码运行；代码可以执行该进程被允许执行的任何操作。如果没有一个严格限制文件系统、网络和进程操作的沙箱，任何自驱型研究智能体都可能窃取数据、耗尽算力或自我改写。

AlphaEvolve 的沙箱机制相对容易实现，因为其评估器是封闭严格的。AI Scientist v2 的循环运行的是开放式代码，对应开放式目标。正因如此，它需要更强的隔离措施（最低限度使用 Docker；推荐使用 seccomp / gVisor），并且在每次提交离开系统前都需要人工审查。

### v2 在前沿技术栈中的位置

| 系统 | 目标 | 输出类型 | 评估器 | 已知故障 |
|---|---|---|---|---|
| AlphaEvolve | 算法 | 代码 | 单元测试 + 基准测试 | 受限于评估器的严谨性 |
| DGM | 智能体脚手架 | 代码 | SWE-bench | 奖励操纵（Reward Hacking） |
| AI Scientist v2 | 研究论文 | 文本 + 代码 + 图表 | 同行评审（较弱） | 实验失败、误标、润色掩盖缺陷 |

在这三者中，v2 拥有最弱的自动评估器、最广的输出表面，以及通向公开成果的最短路径。运营控制措施（沙箱、审查、披露）承担了大部分安全工作。

## 使用方式

`code/main.py` 将 v2 循环模拟为状态机：想法 → 新颖性检查 → 实验 → 图表 → 撰写 → 审查 → 接收或迭代。每个状态都配置了基于 Beel 等人发现的可调失败概率。运行模拟器 N 次循环并统计：

- 有多少想法最终达到投稿阶段。
- 有多少投稿包含已被精美论文所掩盖的关键实验缺陷。
- 重试预算如何在质量与产出率之间权衡。

## 交付规范

`outputs/skill-ai-scientist-sandbox-review.md` 是一份双闸口审查清单，适用于研究循环智能体产出的所有内容在离开沙箱之前。

## 练习

1. 使用默认参数运行 `code/main.py`。多少比例的循环运行产出了“干净”的论文？多少比例产出了带有实验失败缺陷、但被图表批判修饰过的论文？
2. 默认值已采用 Beel 等人的 42% / 25%。分别使用 `--experiment-failure 0.20 --novelty-mislabel 0.10` 和 `--experiment-failure 0.60 --novelty-mislabel 0.40` 重新运行。两次运行之间，“修饰但存在缺陷”的比例发生了怎样的变化？
3. 阅读 Sakana 的 AI Scientist v2 仓库 README 中关于沙箱要求的部分。列出两项你会在多天自主运行中额外施加的限制（除 Docker 之外）。
4. 阅读 Beel 等人第 4 节关于呈现质量差距的内容。设计一项额外的评估器，用于识别看似精美但实验存在缺陷的论文。
5. 提出一种针对研究智能体输出的人工审查协议，使其扩展性优于“让博士逐篇阅读论文”。指出瓶颈并围绕其设计解决方案。

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|---|---|---|
| AI Scientist v1 | “Sakana 的模板化研究智能体” | 将实验填充至固定脚手架中 |
| AI Scientist v2 | “无模板研究智能体” | 结合 VLM 图表批判的智能体树搜索 |
| Agentic tree search | “分支型研究智能体” | 并行扩展多个实验计划；由内部批评者剪枝 |
| Vision-language critique | “VLM 对图表的美化” | 多模态模型读取图表并重写以提升清晰度 |
| Literature retrieval | “新颖性检查” | 搜索既往工作以确认想法的新颖性——已知存在误标问题 |
| Polish masking | “精美的论文，破碎的研究” | 呈现质量超过实验质量；掩盖缺陷 |
| Sandbox escape | “LLM 代码突破限制” | 智能体执行的代码做出了循环设计者未曾预料的操作 |
