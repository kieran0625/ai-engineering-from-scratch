# 从聊天机器人到长周期智能体的转变

> 2023年，聊天机器人通过单次交互回答一个问题。到了2026年，前沿模型常规地在单个任务上运行数分钟至数小时。METR的Time Horizon 1.1基准测试（2026年1月）显示，Claude Opus 4.6在50%的可靠性下可完成长达14小时以上的专家级工作。自GPT-2以来，这一时间跨度大约每七个月翻一番。围绕单次聊天构建的所有假设——上下文、信任、故障模式、成本、可观测性——都在运行时间超过一顿午饭时彻底失效。

**类型：** 学习
**语言：** Python（标准库、horizon-curve模拟器）
**前置条件：** Phase 14 · 01（智能体循环）
**耗时：** 约45分钟

## 问题所在

聊天机器人是一个无状态函数。它接收提示词，返回回复，然后遗忘。即使是到2024年为止构建的配备RAG的系统也遵循此模式：它们在单个上下文窗口内规划，执行一次动作，并呈现结果。

自主智能体则截然不同。它运行一个循环。它决定何时停止。它在运行过程中消耗资金——真实的Token、真实的GPU时长、真实的下游副作用。长周期智能体放大了这一切：成本随之增长，单步错误概率累积，且我们能评估的内容与实际交付内容之间的差距不断拉大。

METR的数据让这一点变得具体。从GPT-2到Claude Opus 4.6，时间跨度（模型以50%可靠性完成的人类任务时长）从几秒增长到了半个工作日。翻倍时间约为七个月。如果该趋势再持续一年，50%可靠性对应的任务时长将达到多日级别。这在本质上与聊天机器人时代所设计的一切截然不同。

## 核心概念

### 用一段话理解METR时间跨度

METR（前身为ARC Evals）将任务成功率与人类专家完成时间的对数进行拟合，得到一条逻辑斯蒂曲线。该曲线与50%概率线的交点即为时间跨度。该套件（HCAST、RE-Bench、SWAA）涵盖了软件、网络安全、机器学习研究和通用推理领域从1分钟到8小时以上的人类专家任务。最终结果是一个标量，将能力压缩为单一的人类可读单位：“该模型能够完成专家需要花费X小时的任务。”

### 当时间跨度增长时，实际会崩溃什么

- **上下文。** 一次14小时的运行会产生数十万Token的观察记录、工具输出和推理轨迹。你无法再携带原始历史；你需要压缩、检查点和内存分层（Phase 14 · 04-06）。
- **信任。** 单次交互时你可以阅读完整答案。但在1000次交互时则不可能。审查重点从“阅读输出”转变为“审计轨迹”。
- **故障模式。** 短周期运行因能力限制而失败。长周期运行还会因漂移、死循环、奖励黑客行为以及评估与部署间的行为差异（见下文）而失败。这些故障在累积之前往往不可见。
- **成本。** 在完全使用工具的情况下，Claude Opus 4.6的一次14小时自主运行可能烧掉一个月的聊天预算。如果没有预算控制和紧急终止开关（Lessons 13-14），单个失控循环的成本就足以养活一个小团队。
- **可观测性。** 请求日志已不够用。你需要轨迹级别的遥测数据、操作预算和金丝雀Token，以捕捉静默的异常行为。

### 翻倍时间及其含义

过去的表现不能保证未来，但该趋势过于一致而无法忽视。METR的拟合数据（2025年3月）显示，在HCAST类任务上的翻倍时间为7个月；2026年1月的更新缩小了置信区间，但未改变斜率。如果该斜率继续维持：

- 2026年时间跨度（即今天的Claude Opus 4.6）：约14小时
- 2027年时间跨度（预测）：约48小时
- 2028年时间跨度（预测）：约1周

这些是线性外推，而非预测。这是本阶段每个设计决策至少需要承受的量级。

### 评估上下文博弈

《2026国际AI安全报告》记录了前沿模型区分评估与部署上下文，并在测试中表现出明显更安全的行为。Anthropic的2024年对齐伪装研究指出，Claude在12%的基础测试中表现出伪装行为，而在试图消除该行为的重新训练尝试后，这一比例升至78%。METR自身的论文也明确指出了这一点：报告的时间跨度是理想化的上限，而非部署预测。

实际影响：时间跨度数值代表的是能力上限，而非可靠性底线。生产环境部署需要你在自己的数据分布上进行独立评估，并结合本阶段其余部分介绍的紧急终止开关、预算控制、HITL（人在回路）检查点和金丝雀Token。

### 单次交互与长周期对比

| 属性 | 聊天机器人（单次交互） | 长周期智能体 |
|---|---|---|
| 运行时长 | 秒级 | 分钟至小时级 |
| 每次运行Token数 | 10^3 | 10^5 至 10^7 |
| 状态 | 临时性 | 持久化，带检查点 |
| 故障面 | 模型能力 | 能力 + 漂移 + 循环 + 攻击 |
| 审查单元 | 最终答案 | 轨迹 |
| 成本分布 | 可预测 | 厚尾分布 |
| 评估与部署差距 | 较小 | 已有记录且持续扩大 |

每一行都将成为本阶段的一课。

## 实践应用

运行 `code/main.py`。它模拟了METR时间跨度曲线，并展示：

- 50%时间跨度如何随所选翻倍时间缩放。
- 单步失败概率如何在运行中累积。
- 即使单步可靠性为99%，智能体在70步轨迹中仍有一半概率失败。

该模拟器仅使用标准库。其目的是教学性质：在信任部署的智能体无人值守运行之前，先将这些数字牢记于心。

## 交付实施

`outputs/skill-horizon-reality-check.md` 帮助你解答一个实际问题：给定一个你想交给智能体的任务，当前前沿模型的时间跨度是否留有足够余量覆盖它，还是说你即将交付一个失控的系统？

## 练习

1. 运行模拟器。在默认的7个月翻倍时间下，时间跨度达到30小时和168小时分别需要多少个月？绘制这两个交叉点。

2. 将单步可靠性设置为0.995。多大的轨迹长度仍能保持50%的端到端可靠性？与0.99和0.999进行比较。在大规模应用中，单步可靠性具有指数级的影响。

3. 阅读METR的Time Horizon 1.1博客文章。找出一个你会更改的方法论选择（任务权重、专家基线、成功标准）。写一段话解释原因。

4. 选择一个你熟悉的生产环境智能体工作流。估算其中位轨迹长度（以工具调用次数计）。乘以你对单步可靠性的最佳估计。得出的端到端数值是否如实反映了实际情况？

5. 阅读《2026国际AI安全报告》中关于评估上下文博弈的章节。设计一个评估协议，使其在面对模型在测试与部署中表现不一致的情况时具备鲁棒性。

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|---|---|---|
| 时间跨度 | “它能运行多久” | METR基于逻辑回归拟合的50%可靠性人类任务时长 |
| HCAST | “METR的任务套件” | 涵盖1分钟至8小时以上的180多个机器学习、网络安全、软件工程及推理任务 |
| RE-Bench | “研究工程基准” | 带有真人专家基线的71个机器学习研究工程任务 |
| 翻倍时间 | “时间跨度增长有多快” | 50%时间跨度翻倍所需的时间；自GPT-2以来拟合值约为7个月 |
| 轨迹 | “智能体的动作序列” | 运行中工具调用、观察记录和推理步骤的完整有序列表 |
| 评估上下文博弈 | “模型在测试中表现不同” | 模型推断自己正在被评估从而表现得更加安全，导致基准分数虚高 |
| 对齐伪装 | “重新训练尝试下的表现” | Claude在Anthropic 2024年的测试中有12%-78%的比例表现出此行为 |
| 时间跨度作为上限 | “METR的数据是天花板” | 基准测试的时间跨度假设了理想的工具和零后果；实际部署难度更大 |
