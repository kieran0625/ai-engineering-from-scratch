# STaR、V-STaR、Quiet-STaR —— 自教推理

> 最小的自我改进循环就存在于推理过程之中。模型生成思维链，保留那些得出正确答案的推理，并基于这些进行微调。这就是 STaR。V-STaR 引入了验证器，以便在推理时做出更好的选择。Quiet-STaR 将推理过程下推至每一个 token。这三种方法都有效。但它们都不是魔法——该循环会保留任何恰好能得出正确答案的捷径。

**类型：** 学习
**语言：** Python（stdlib、bootstrap-loop 模拟器）
**前置要求：** Phase 13 · 01-03（推理与 CoT）、Phase 15 · 01（长周期框架）
**时间：** 约 60 分钟

## 问题所在

教导模型进行推理的最直接方式是收集人类编写的推理轨迹。但这成本高昂、速度缓慢，且受限于人类愿意编写的高质量思维链的数量。

STaR（Self-Taught Reasoner，Zelikman 等人，2022）提出了一个问题：如果模型自己编写推理过程，并根据已知答案进行评分呢？其循环步骤如下：

1. 采样一条推理轨迹及其答案。
2. 如果最终答案正确，则保留该轨迹。
3. 在保留的轨迹上进行微调。
4. 重复上述过程。

该方法确实有效。GSM8K 和 CommonsenseQA 的成绩均在无需新的人工标注的情况下得到了提升。但该循环存在内置偏差：任何得出正确答案的推理都会被保留，无论其推理过程本身是否严谨。V-STaR（Hosseini 等人，2024）通过引入学习到的验证器来修补这一缺陷；Quiet-STaR（Zelikman 等人，2024）则将这一思想推广到每个 token 的内部推理上。

## 核心概念

### STaR：基于有效样本的自举

从一个具备一定基础推理能力的基座模型开始。针对每个训练问题，采样一条推理及对应答案。如果答案与标签匹配，则保留（问题、推理、答案）三元组。在保留的集合上对模型进行微调。重复此过程。

其中一个关键变体很重要。如果模型永远无法做对某道题，循环就无法从中学习。STaR 引入了**合理化（rationalization）**机制：对于模型答错的问题，注入正确答案作为提示，并重新提示模型生成导向该答案的推理。这些合理化的推理会被加入训练集。

原始论文（Zelikman 等人，2022）的结果显示：经过多轮带有合理化机制的 STaR 迭代，GPT-J 基座模型在 GSM8K 上的成绩从 5.8% 提升至 10.7%——绝对值提升了约 5 个百分点。在 CommonsenseQA 上，经 STaR 训练的 GPT-J 6B 达到了 72.5%，可与人工标注推理数据微调的 GPT-3 175B（约 73%）相媲美——后者是一个规模大约大 30 倍的模型。

### V-STaR：使用 DPO 训练验证器

STaR 会丢弃不正确的推理。Hosseini 等人（2024）观察到这些数据同样有价值：每一对（推理，“是否正确”）都可以用来训练一个验证器。他们利用直接偏好优化（DPO）处理正确和错误两种解法来构建一个排序器。在推理阶段，采样 N 条推理，并选择验证器评分最高的那一条。

报告的提升幅度：在 GSM8K 和 MATH 上，相比先前的自我改进基线提升了 4 到 17 个百分点。其中大部分收益来自于将验证器用于推理时的选择，而非用于额外的生成器微调。

### Quiet-STaR：逐 token 的内部推理

Zelikman 等人（2024）提出：如果模型学会在每个 token 位置生成简短的内部推理，而不仅仅是在问题和答案之间呢？Quiet-STaR 训练模型在每个预测 token 之前输出一个隐藏的“思考”，然后通过一个学习到的权重，将感知到思考的预测结果与基线预测结果进行混合。

结果：Mistral 7B 在未进行任务特定微调的情况下，零样本（zero-shot）成绩在 GSM8K 上从 5.9% 提升至 10.9%，在 CommonsenseQA 上从 36.3% 提升至 47.2%。模型学会了“何时思考”——难处理的 token 会获得更长的内部推理，简单的 token 则几乎不需要。

### 为何三者共享同一安全顾虑

这三种方法都将最终答案作为梯度信号。通过有缺陷的推理得出正确答案的推理过程——无论是利用捷径、猜测还是使用不具备泛化性的模式——都会得到正向强化。在分布内（in-distribution）问题上，这种捷径有效；但在分布外（out-of-distribution）问题上，它会无声地失效。

V-STaR 的验证器通过学习对推理进行排序来缓解这一问题，但验证器是在相同的标签集上训练的。它可能会学会偏好格式良好但错误的推理，而不是诚实的不确定性。更安全的设计是将 STaR 风格的数据与以下两者结合：(a) 过程监督奖励模型（奖励中间步骤，而不仅仅是最终答案）以及 (b) 能够打破简单捷径的预留分布外（OOD）评估。

### 对比

| 方法 | 训练信号 | 推理成本 | 数据浪费 | 已知失败模式 |
|---|---|---|---|---|
| STaR | 若答案正确则保留（推理，答案） | 1倍 | 丢弃所有错误推理 | 捷径式推理 |
| STaR + 合理化 | 上述 + 注入正确答案的重试 | 1倍 | 较少 | 合理化的推理可能缺乏合理性 |
| V-STaR | STaR + 基于两类数据的 DPO 验证器 | N倍（Best-of-N） | 极少 | 验证器可能强化自信的谬误 |
| Quiet-STaR | 逐 token 推理 + 混合权重 | 1.5-3倍 | 极少 | 仍是基于答案的梯度 |

### 在 2026 技术栈中的定位

STaR 已经有些年头了。但这种模式在 2025-2026 年无处不在。在可验证数学问题上的强化学习（如 DeepSeek-R1、Kimi-k1.5、o1）本质上是放大了 STaR 的基于答案的梯度信号。过程奖励模型（Lightman 等人，2023；OpenAI 的“让我们一步步验证”）是过程监督的替代方案。AlphaEvolve（第 3 课）是面向代码的 STaR，用程序评估器代替了标签。Darwin Godel Machine（第 4 课）是让智能体自身架构实现 STaR 的机制。

理解 STaR 能让所有这些概念豁然贯通。它是最小可行性的自我改进循环。

## 实践应用

`code/main.py` 在一个玩具算术任务上运行模拟的 STaR 循环。你可以观察：

- 准确率如何随着自举轮次逐步攀升。
- 捷径是如何混入的：模拟器包含一类“懒惰”推理，它能 40% 的概率得出正确答案，但泛化能力很差。观察 STaR 是否会保留它们。
- 验证器（V-STaR 风格）如何在推理阶段提供帮助，但又无法完全剪除训练期间引入的捷径。

## 部署实施

`outputs/skill-star-loop-reviewer.md` 帮助你在基于提议的自我推理管道进行训练之前对其进行审计。

## 练习

1. 运行模拟器。将捷径频率设置为 0，然后设置为 0.4。尽管两次运行在训练分布上都达到了 >90% 的准确率，但最终准确率的分歧有多大？

2. 为模拟器添加预留的 OOD 测试集。从不同分布中抽取问题，并在分布内和 OOD 集上分别评估自举后的模型。量化两者之间的差距。

3. 阅读 Quiet-STaR 论文（arXiv:2403.09629）第 3 节。分别用三句话解释“end-of-thought”token 和混合权重头（mixing-weight head）。

4. 将 STaR 的“仅保留正确”过滤器与独立奖励每个推理步骤的过程监督替代方案进行比较。指出标注成本的差异以及合理的预期质量差异。

5. 设计一项评估，用于捕获已部署模型中的捷径推理。它不必完美——只要能打破 STaR 循环会强化的最简单捷径即可。

## 关键术语

| 术语 | 通常的说法 | 实际含义 |
|---|---|---|
| STaR | “自教推理器” | 基于模型生成的、能得出正确答案的推理进行微调；循环执行 |
| Rationalization | “带提示的重试” | 在基座模型答错的问题中注入正确答案，并重新提示生成推理 |
| V-STaR | “验证器 STaR” | 使用 DPO 在正确和错误推理上训练验证器，并将其用于推理时的选择 |
| Quiet-STaR | “逐 token 推理” | 在每个 token 位置生成隐藏思考；与基线预测进行混合 |
| Answer-conditioned gradient | “基于结果的信号” | 训练循环奖励的是最终答案，而非推理步骤 |
| Process reward model | “步骤级验证器” | 基于单步正确性而非最终结果训练的奖励模型——与 STaR 形成对比 |
| Shortcut rationale | “答案正确，推理错误” | 通过非泛化模式得出标签的推理；STaR 会保留此类推理 |
