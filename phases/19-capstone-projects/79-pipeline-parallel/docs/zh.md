# 流水线并行与气泡分析

> 张量并行将矩阵乘法拆分到各个 rank 上。流水线并行将模型拆分到各个 rank 上，每个 rank 负责一个阶段（stage）。微批次（microbatch）在流水线中流动。起始和结束时的空闲时间称为气泡（bubble）；最小化气泡是这门技术的核心所在。

**类型：** 构建实现
**语言：** Python
**前置要求：** 第 19 阶段 C 路线第 42-49 课
**耗时：** 约 90 分钟

## 学习目标

- 将顺序模型拆分为 N 个阶段，并在 N 个 rank 上模拟前向流水线。
- 使用 GPipe 调度策略（仅前向填充，然后反向）安排 M 个微批次通过流水线，并计算气泡占比。
- 将气泡情况与 Megatron-LM 和 PipeDream 中使用的交错式 1F1B 调度策略进行对比。
- 论证阶段划分原则：每个阶段的计算量均衡比参数量均衡更重要。

## 问题背景

一个 70B 参数的 fp16 模型仅参数就需要 140 GB 显存。没有消费级 GPU 能装下它。ZeRO-3 将参数分片到各个 rank，但在每次前向步骤中仍需要每个 rank 对完整层执行 allgather，每层需付出 log(N) 跳的通信代价。流水线并行采取了不同的路线：将模型切分为 N 个阶段，每个 rank 放置一个阶段。第 1 层的前向计算在 rank 0 完成后，将激活张量传递给 rank 1；rank 1 运行第 2 层并传递给 rank 2；依此类推。反向传播则逆向流动。由于每个 rank 仅持有一个阶段，内存呈线性下降；但计算是顺序执行的，这就带来了气泡问题。

气泡是指流水线起始阶段（等待第一个微批次到达最后一个阶段）和结束阶段（等待最后一个微批次反向排空）的空闲时间。对于 M 个微批次和 N 个阶段，每个阶段的气泡占比为 (N-1)/(M+N-1)。当 M=8、N=4 时，占比为 27%。当 M=64、N=4 时，占比为 4.5%。当每个步骤包含大量微批次时，气泡会缩小，这意味着每个微批次的 batch size 较小，这一约束条件正是驱动微批次设计的核心因素。

## 核心概念

```mermaid
flowchart LR
  R0[rank 0: stage 0 / layer 0] --> R1[rank 1: stage 1 / layer 1]
  R1 --> R2[rank 2: stage 2 / layer 2]
  R2 --> R3[rank 3: stage 3 / loss]
  R3 -.backward.-> R2
  R2 -.backward.-> R1
  R1 -.backward.-> R0
```

### GPipe 调度策略

在开始任何反向传播之前，先用所有 M 个微批次正向填满流水线；然后按逆序反向排空。每个微批次的激活值必须保留到其反向传播完成，因此内存随 M 线性增长。前向传播耗时 M+N-1 个周期，反向传播再耗时 M+N-1 个周期。每个阶段的有效工作量为 2M 个周期；每个阶段的气泡为 2(N-1) 个周期。当每次前向和反向各耗时一个单位时间时，气泡占比为 (N-1)/(M+N-1)。选择远大于 N 的 M 值可以隐藏气泡。

### 1F1B 调度策略

交错执行：一旦某个微批次的前向传播到达最后一个阶段，立即启动其反向传播并让其流回。该调度策略在每个阶段交替执行一次前向和一次反向。气泡仍为 N-1，但激活内存受限于流水线深度，而非微批次数量。生产环境的流水线采用 1F1B（如 Megatron、PipeDream）。本课首先实现 GPipe 因为它更简单，并将 1F1B 作为练习。

### 为何每个阶段的计算量均衡至关重要

如果阶段 0 耗时 50 ms 而阶段 1 耗时 100 ms，则每个周期都会受限于阶段 1。其他阶段每个周期将空闲 50 ms，等待阶段 1 释放。参数量均衡是错误的维度：Transformer 的计算主要由每层的注意力机制和 MLP 主导，而嵌入层参数量大但计算量小。阶段划分应均衡每个阶段的 FLOPs（浮点运算次数），而非每个阶段的权重数量。

### 微批次与批次

流水线运行 M 个微批次，每个大小为 B。有效 batch size 为 M*B。流水线步骤结束时的梯度是基于合并后的 M*B 个样本计算得出的梯度。气泡占比取决于 M；优化器看到的是 M*B。调优 M 意味着在气泡（M 越大气泡越小）与单微批次内存（对于 GPipe，M 越大激活内存越高）之间进行权衡。

## 业界生产模式

有三种模式能使流水线并行达到足以交付生产的健壮程度。

**激活检查点与流水线搭配使用。** 在 GPipe 中同时有 M 个微批次在流水线中运行时，激活内存是单个微批次的 M 倍。激活检查点在反向传播时重新计算前向过程，以计算换内存；这种组合使得流水线在处理长序列时变得可行。

**阶段均衡是实测出来的，而非假设出来的。** 生产团队会运行一次性能分析（profiling），在目标硬件上测量每层的实际计算量（FLOPs 和挂钟时间），然后依据该测量结果进行划分。Megatron-LM 的 `--num-layers-per-stage` 标志接受一个列表，以便在各阶段每层成本不同时允许不均匀的层数分配。

**发送-接收调度必须避免死锁。** 如果流水线中每个阶段都先发送后接收，会在通信链路上发生死锁。标准修复方法是交错执行：偶数 rank 阶段先发送后接收，奇数 rank 阶段先接收后发送。本课显式地调度各个 rank，以便该模式清晰可见。

## 实际应用

生产环境模式：

- **Megatron-LM。** 大规模流水线并行的参考实现。采用 1F1B，并支持张量 + 流水线 + 数据并行组合。
- **DeepSpeed Pipeline。** 与 ZeRO 集成；ZeRO-1 + 流水线是最大型开源模型的常见组合。
- **PyTorch Pipe。** PyTorch 原生流水线封装，基于 `torch.distributed.pipeline.sync.Pipe` 构建。

## 关键术语

| 术语 | 通俗说法 | 实际含义 |
|------|----------------|------------------------|
| Pipeline（流水线） | “沿深度方向的模型并行” | 每个 rank 一个阶段，激活值在阶段间流动 |
| Bubble（气泡） | “流水线空闲时间” | 起始和结束阶段的 (N-1) 步，期间部分阶段无工作可做 |
| Microbatch（微批次） | “批次的切片” | 一个前向/反向单元；气泡随 M 增大而缩小 |
| GPipe | “先填满再排空” | 所有 M 次前向完成后才开始反向；激活内存占用高 |
| 1F1B | “交错调度” | 每个阶段一次前向一次反向；激活内存受限 |
